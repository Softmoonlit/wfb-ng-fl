# ADR-0002: 过渡阶段保留拆分进程架构

## 状态

已被 [ADR-0003: 最终联邦学习传输架构](0003-最终联邦学习传输架构.md) 取代。

## 背景

在早期真实硬件验证中，`wfb_core` 单进程合并架构在 server/client 环境中无法稳定 ping 通，而既有 `wfb_tx`、`wfb_rx`、`wfb_tun` 拆分进程架构已经验证可 ping 通。

为了尽快验证 Token Passing 的基础语义，项目第一阶段选择保留拆分进程路径：

- `wfb_tun` 继续负责 TUN 读写和本地 UDP 转发。
- `wfb_tx` 在空口注入前增加 Token gate。
- `wfb_rx` 识别 Token，并通过本机 IPC 通知 `wfb_tx` 更新授权状态。
- server 使用独立 C/C++ 常驻调度器按静态节点列表固定轮询发 Token。

## 决策

第一阶段保留 `wfb_tx`、`wfb_rx`、`wfb_tun` 拆分进程架构作为验证路径，不把 `wfb_tun` 与 `wfb_tx` 合并为主线交付目标。

该阶段的目标是验证：

- 无 Token 时 client 不向空口发射。
- 拿到本机 Token 后 client 可以上行。
- 多 client 同时运行时，只有被授权 client 能发射。
- 既有可 ping 通 TUN/IP 基线不被破坏。

## 为什么这样做

该选择降低了早期调试面，保住了已经跑通的 TUN/IP 路径，使 Token gate、scheduler 和真实硬件测试可以先闭环。

代价是拆分进程通过本地 UDP socket 转发，无法为 40MB 级大文件和多节点长期憋包提供可靠反压；当 `wfb_tx` 无 Token 停发时，`wfb_tun` 仍可能继续抽干 TUN 队列并把数据塞入本地 UDP 缓冲，最终导致不可控排队或静默丢包。

## 后续取代

随着最终架构明确，拆分进程架构不再作为大文件稳定传输的主线。最终方案由 ADR-0003 定义：

- 保留 TUN/IP 作为上层协议边界。
- 下行采用 UFTP 组播/广播。
- 上行第一版采用 TCP per-client。
- KCP per-client 作为后续候选。
- wfb 链路层演进为集成式守护进程。
- 在同一进程内统一 TUN 读写、Token gate、空口 TX/RX、固定容量队列、动态逻辑水位和反压。
- 使用反向控制窗口保证 UFTP NACK/完成状态反馈 与 TCP/KCP ACK/control 能回传。

## 结果

ADR-0002 仍保留为历史记录和过渡测试依据。旧拆分进程路径可以继续用于：

- Token gate 小步验证
- 真实硬件回归测试
- 与最终集成式守护进程对照排查

但它不再代表最终联邦学习大文件传输架构。任何涉及 40MB 级模型文件、多节点长期轮询、动态水位或反压的设计，应以 ADR-0003 为准。

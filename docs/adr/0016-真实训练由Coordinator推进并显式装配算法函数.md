# ADR-0016: 真实训练由 Coordinator 推进并显式装配算法函数

Status: accepted（部分取代 ADR-0010 与 ADR-0014）

真实 FedAvg 接入时，算法层旧描述把服务端循环交给 server 算法入口，常驻服务设计及代码则由 Coordinator 推进。用户明确选择由 Coordinator 唯一拥有服务端发布、收齐及多轮推进，通过显式配置的聚合、评估和可选无线策略函数进入算法；客户端完整作业入口继续拥有本地训练循环。这样保留现有文件交换机制，同时将评估、准备门禁和轮次间配置放在唯一协调序列中，清理重复 server 循环与文件复制算法，不增加另一套联邦学习框架或通用插件平台。

客户端入口演进为显式接收 Runtime、算法配置和作业上下文，承担数据／GPU 准备报告及协作停止；Runtime 四个文件接口与 manifest 保持原职责。入口及依赖在各端预部署，作业受理时固定配置，不动态分发或安装代码。此前的进程内调用、跨轮复用和任务级生命周期原则继续成立；ADR-0010 中双端入口各自拥有循环和二参数 callable 的假设不再用于真实训练目标；既有实现中算法执行前的裸 ready 通知也不能替代训练准备结果。

本次同时将受控无线配置纳入初始和轮次间算法边界：算法不能改信道，支持统一 HT 20／40 MHz，速率按带宽与下行 MCS 组合由守护进程校验。它部分替代 ADR-0014 的固定 HT40+、MCS 单维速率及纯交互层校验假设，不否定该记录的扁平配置、增量请求和既有调度基线。20 MHz 实测速率仍是部署交付项，不能以本决策代替实测。

实际规则分别由[算法层专题](../design/FL-算法层设计.md)和[跨层专题](../design/系统分层与跨层契约.md)唯一拥有。[训练作业契约决议](../../.scratch/fedavg-training-extension/issues/06-fedavg-job-contract.md#answer)记录用户确认过程；本记录和目标设计不表示产品代码或硬件验收已经完成。

# ADR-0009: 受信任环境模式下显式支持无加密链路

Status: proposed

## 背景

现有 `wfb-ng` 数据面依赖 `keypair`、`session key`、`crypto_box` 与 `crypto_aead` 形成链路层加密与解密路径。`v6` 正在推进集成式链路层底座替换，但团队后续计划在受信任实验/内网环境下移除这套现有加密机制，以降低迁移复杂度并避免把旧安全实现直接带入新底座。

当前已冻结约束包括：

- `v6` 采用 clean cutover，不允许旧 split-process 作为运行时 fallback
- 控制帧与普通数据面分离，控制面优先通路保持独立
- 参数迁移必须显式收口，不能靠注释代码制造半残协议

## 决策

在受信任环境前提下，后续正式运行目标收敛为 **`trusted_plaintext` 显式无加密模式**，用于旁路现有 `wfb-ng` 的 `keypair/session/crypto` 链路；`legacy_encrypted` 仅保留为历史基线、迁移对照与回归参考，不再作为后续正式运行目标。

该模式必须满足：

1. 作为**显式模式**存在，而不是通过临时注释 `tx` 加密或 `rx` 解密代码达成
2. 明确旁路以下路径：
   - `keypair` / 密钥文件读取
   - `WFB_PACKET_SESSION` 的生成、发送、接收与消费
   - 数据面 AEAD tag 长度假设、加密与解密校验
3. 文档、启动摘要与日志必须明确标注这是**受信任环境模式**，不提供现有链路层机密性保证
4. 控制面与数据面的既有边界、方向链路域、Token gate、队列 / 反压、接收重组等语义不得因无加密模式而被重新定义
5. 第一版无加密模式应保持**协议形态变化最小**：尽量保留现有 `packet_type` 分层、方向链路域、控制帧边界、普通数据面 `FEC` / 重组 / 队列 / Token gate 语义，仅抽走 `keypair/session/AEAD` 相关路径，不顺手重写整套空口帧格式

实现与迁移期可识别两种模式：`legacy_encrypted` 与 `trusted_plaintext`。其中 `trusted_plaintext` 是后续唯一正式运行模式；`legacy_encrypted` 仅用于历史基线、迁移对照与回归参考。禁止出现“部分关闭 session 但保留部分 AEAD 校验”之类混合半态；控制面与数据面在同一实例内必须共享同一链路安全模式判定。

链路安全模式相关参数校验必须 fail-fast：运行 `legacy_encrypted` 对照路径时必须提供旧加密材料，运行 `trusted_plaintext` 正式路径时禁止提供旧加密材料；任一模式与参数集合不匹配时，一律启动失败，不得静默忽略。

启动生效配置摘要与首条启动日志必须显式输出 `link_security_mode`；当模式为 `trusted_plaintext` 时，必须追加醒目的“受信任环境 / 无链路机密性”风险标记，避免现场误判当前实例仍运行在旧加密模式下。

## 不采纳的方案

### 1. 直接注释掉 TX 加密与 RX 解密代码

拒绝原因：

- 会留下仍然存在的 `session` 协议残骸与参数契约
- 容易造成“看似支持加密、实际半失效”的半残协议
- 维护者难以判断当前真实空口协议形态

### 2. 用差分隐私替代链路层加密

拒绝原因：

- 差分隐私解决的是联邦学习更新/聚合层面的隐私泄露风险
- 它不提供链路层机密性、完整性或控制帧防伪能力
- 因此不能替代现有 `wfb-ng` 的传输安全机制

### 3. 在同一阶段同步设计全新链路层替代安全机制

暂不采纳原因：

- 会显著扩大 `v6/v7` 范围
- 当前优先级是完成集成式底座替换与双基线等价

## 后果

- `legacy_encrypted` 退化为历史基线、迁移对照与回归参考路径，不再作为后续正式运行目标
- 启动生效配置摘要中，正式运行目标固定输出 `trusted_plaintext` 及其受信任环境风险标记；仅在历史对照运行时才应出现旧加密材料配置
- 验收与部署文档必须直说：无加密模式不适用于要求链路层机密性的场景，而旧加密模式只用于历史对照，不代表后续正式部署目标
- `keypair`、`session`、`AEAD` 等旧加密相关参数对正式运行目标 `trusted_plaintext` 一律按废弃处理；仅在 `legacy_encrypted` 历史对照路径中保留为基线专用参数，不再属于正式公开参数面
- 若未来需要重新引入安全能力，应单独通过新的 ADR 定义其边界，不得复活“注释代码式”的半残协议

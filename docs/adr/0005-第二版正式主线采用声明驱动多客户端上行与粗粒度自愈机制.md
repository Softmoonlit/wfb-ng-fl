# ADR-0005: 第二版正式主线采用声明驱动多客户端上行与粗粒度自愈机制

Status: accepted

为在不偏离 ADR-0003 总体边界的前提下把第一版单客户端主线推进到可用的多客户端上行闭环，第二版正式主线采用“**上行就绪声明** 驱动的多客户端上行”而不是静态预配置客户端列表：服务端维护单层 **活跃队列**，以固定队列加调度游标做盲 round-robin 发 Token；`grant` 继续沿用现有定义，`duration_ms` 与 `guard_interval_ms` 在第二版保持固定配置而不做动态伸缩；客户端在本地具备可上传数据时立即发送 **上行就绪声明** 入队，正常 grant 间隙只阻塞等待，不做周期性续约。`issue01` 落地时，ready 声明通道进一步收敛为单一固定接收端：调度器固定监听 `wfb-scheduler.ready`，不再暴露 ready 接收地址配置；发送侧在启用 token gate 时通过 `-q <NODE_ID>` 显式声明本节点身份，并将首次 ready 声明发送到该固定地址。之所以采用这一路线，是因为第二版需要优先验证“多客户端轮换上行、运行中动态加入、误删后可自愈重入”这三个主线行为，同时避免过早引入发送侧进展反馈闭环、动态 grant 时长策略、显式完成/失败控制消息或上层轮次结束信号；因此服务端只补接收侧 `per-node` 统计，并基于“静默时间 + 连续静默 grant 次数”双阈值做保守的粗粒度移除，客户端若长时间未获 Token 则重发 **上行就绪声明** 自愈。随着第二版主线收口，重复声明语义进一步收敛为：对仍在 **活跃队列** 中的节点仅刷新活性，不重复入队、不改变队列顺序和调度游标；若节点已不在队列中，则后续重声明按动态加入语义重新入队。该决策作为 ADR-0004 之后的第二版落地边界补充，与 ADR-0003 并存，继续保持底层实现简单、行为可观测、验收可分层推进。

# 射频事务广播可靠交付

本次仅修改 `wfb_ng/fl/control.py` 的服务器发送与等待逻辑，客户端沿用已有 proposal 身份检查和幂等处理。

PREPARE 在一次事务开始时确定本机 monotonic 截止，在原 `prepare_timeout_seconds` 内按现有 `ping_interval_seconds` 重发同一个报文。session、job、冻结目标、patch 和准备超时字段保持一致。只有全部目标返回成功 ACK 才进入 COMMIT；重发不建立新事务、不延长准备期限。客户端同一 proposal 重复 ACK，不重新取得 owner。

COMMIT 在原 `commit_delay_seconds` 等待窗口内按相同广播间隔重发。服务器只建立一次本机 monotonic 切换截止，每包 `delay_ms` 为发送前该截止减本机当前时间的剩余毫秒（向下取整，最少为零）。客户端只接收相对延迟，不比较跨机 monotonic 时钟。第一次收到 COMMIT 即启动已有延迟应用与租约，后续重复报文不会重新排期或重新启动租约。零延迟事务仍发送一次 COMMIT。

默认广播间隔、2 秒切换等待、准备与事务超时、230ms/10s 参数、协议字段和 FEC 均未修改。COMMIT 等待使用 `stop_event.wait` 直接响应取消；等待 ACK 时使用现有 Event，存在取消事件时单次等待最多 50ms，以免广播间隔较长时拖延取消。回退继续使用已有确认流程。

测试文件 `wfb_ng/tests/test_fl_control_delivery.py` 复用现有真实服务器、两个真实客户端、loopback socket guard 和动态 UDP 端口。仅在测试边界定向丢弃一个节点的首个 PREPARE、首个 PREPARE_ACK 或首个 COMMIT，验证最终全员确认、同一 proposal、固定切换时刻、只应用一次和只启动一次租约。另外验证全部 PREPARE 丢失时硬截止且不得 COMMIT/CONFIRMED，以及 PREPARE 与 COMMIT 等待期间的取消。测试使用短时间参数加速运行，不改生产默认值。

RED：原实现运行首个 PREPARE 丢失用例，得到 `节点缺失或准备失败: [1]`，事务回退。GREEN：修复后新增用例及现有射频事务、真实 loopback 测试共 65 项通过。验证命令：

```sh
python -m pytest -q wfb_ng/tests/test_fl_control_delivery.py wfb_ng/tests/test_fl_radio_transactions.py wfb_ng/tests/test_fl_radio_switch.py --disable-warnings
```

事务入口还会在取得 owner、作业 liveness lease 或广播之前校验所有时间参数：`ping_interval_seconds`、`prepare_timeout_seconds`、`commit_timeout_seconds` 和 `lease_timeout_seconds` 必须是有限正数；`commit_delay_seconds` 必须是有限非负数，零延迟仍合法。所有参数只接受 int/float，不接受 bool、NaN、无穷或字符串；非法参数抛出 `invalid_radio_timing`。不修改协议字段或默认时间值。

时间参数测试覆盖非法类型、非有限值、负数和零超时，并断言异常前没有广播、没有取得作业租约或事务 owner；真实 loopback 另验证零延迟只发一次 COMMIT 且全员成功。新增 RED 复现负数广播间隔未在入口拒绝；补齐后运行定向交付、射频事务、射频切换及控制面 review/plane/routing 测试，共 **158 项通过**。

广播重发提高原有窗口内的交付概率；持续缺端仍按原期限失败并执行已有回退/错误确认流程，不增加 fallback。

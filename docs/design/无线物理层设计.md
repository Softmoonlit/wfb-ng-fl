# 无线物理层设计

<a id="physical-contract"></a>

## 所有权

本文档唯一拥有无线物理层的能力边界和对链路层的物理输入假设。它不拥有 READY、GRANT、Token Passing、FEC、文件完成、TUN 或 FL 轮次语义。

## 冻结能力

无线物理层向链路层提供以下能力：

- 通过 802.11 monitor 接口接收空口帧，并把可观测的接收结果交给链路层。
- 通过 raw injection 发射链路层构造的 802.11 帧。
- 以广播物理承载支持 server 到 clients 的共享下行和 clients 到 server 的共享上行；物理广播不等同于链路层逻辑目标过滤。
- 提供链路层所需的 Radiotap 发射元数据，以及所选 802.11 HT/VHT 发射能力。
- 提供接收侧可用的射频观测结果，供链路层记录和判断收发环境；观测结果不是文件完整性确认。

## HT 带宽与网卡配置

正式链路固定使用 Long GI（800 ns），HT20／HT40、上下行数据帧及 READY／GRANT 调度控制帧保持一致；GI 不作为操作者或算法的可配置项。`RadioConfig.guard_interval` 及配置快照统一报告 `long`，配置校验拒绝覆盖为 `short`。Daemon 构造 native 启动命令和角色配置时省略 `--radio-short-gi`，沿用 `V6RadioConfig.short_gi = false` 的 Long GI 默认值；本机在线重配报文同样固定将 Short GI 位设为 `0`。该物理层保护间隔与 Token 调度的 `guard_interval_ms` 含义不同。

本节为已确认的双带宽目标设计，尚未完成实现与实测。首版支持 HT20／HT40，不扩展 80 MHz 或 VHT；网卡工作带宽必须与 Radiotap 帧发射描述相配。Daemon 通过网卡配置接口应用工作带宽与驱动功率索引；链路层使用的派生带宽配置见[v6 本机发射配置在线更新](链路层空口调度与反压.md#v6-本机发射配置在线更新)。功率不通过修改 Radiotap 代替网卡设置。驱动索引是控制档位，不能按字段名或`iw`读回的dBm标签当作经过校准的物理输出；板级功耗模式属于独立计算资源限制。

信道由操作者根据现场测量，在集群空闲时设置并保存；算法不修改信道，作业启动与轮次推进不自动选信道。请求带宽与固定信道、网卡或驱动支持不兼容时，在执行前明确拒绝，遵守现有信道候选与黑名单限制，不自动换信道或降低带宽。跨节点应用与确认见[算法无线配置与跨层重配边界](系统分层与跨层契约.md#算法无线配置与跨层重配边界)；发射调用、接收帧及射频元数据均为物理观测，不能替代重配完成确认。

## 完成边界

系统闭环不以硬件 ACK 作为文件、控制帧或 FL 轮次完成的前提。物理层能够报告发射调用和接收观测，但不能据此声称某个 client 已经收到模型或 server 已经收到 update。Transport 的文件结果和 Runtime 的校验仍是上层完成依据。

物理层能力必须与链路层的方向链路域和控制面/数据面边界兼容；链路层负责在广播承载上完成逻辑 `NODE_ID` 过滤。物理专题不冻结具体硬件型号、信道组合、监管策略、发射速率、功率阈值或测试手册中的演示参数。

## 与相邻层的关系

链路层需要的 monitor、raw injection、Radiotap/HT/VHT 和射频观测能力由本专题定义；链路层如何把这些能力用于控制帧、FEC、重组、发送权和反压，见[链路层空口调度与反压](链路层空口调度与反压.md#link-contract)。跨层文件交付顺序见[系统分层与跨层契约](系统分层与跨层契约.md#cross-layer-contracts)。

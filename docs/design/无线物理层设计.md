# 无线物理层设计

<a id="physical-contract"></a>

## 所有权

本文档唯一拥有无线物理层的能力边界和对链路层的物理输入假设。它不拥有 READY、GRANT、Token Passing、FEC、文件完成、TUN 或 FL 轮次语义。

## 冻结能力

无线物理层向链路层提供以下能力：

- 通过 802.11 monitor 接口接收空口帧，并把可观测的接收结果交给链路层。
- 通过 raw injection 发射链路层构造的 802.11 帧。
- 以广播物理承载支持 server 到 clients 的共享下行和 clients 到 server 的共享上行；物理广播不等同于链路层逻辑目标过滤。
- 提供链路层所需的 Radiotap 发射元数据，以及所选 802.11 HT/VHT 发射能力。
- 提供接收侧可用的射频观测结果，供链路层记录和判断收发环境；观测结果不是文件完整性确认。

## 完成边界

系统闭环不以硬件 ACK 作为文件、控制帧或 FL 轮次完成的前提。物理层能够报告发射调用和接收观测，但不能据此声称某个 client 已经收到模型或 server 已经收到 update。Transport 的文件结果和 Runtime 的校验仍是上层完成依据。

物理层能力必须与链路层的方向链路域和控制面/数据面边界兼容；链路层负责在广播承载上完成逻辑 `NODE_ID` 过滤。物理专题不冻结具体硬件型号、信道组合、监管策略、发射速率、功率阈值或测试手册中的演示参数。

## 与相邻层的关系

链路层需要的 monitor、raw injection、Radiotap/HT/VHT 和射频观测能力由本专题定义；链路层如何把这些能力用于控制帧、FEC、重组、发送权和反压，见[链路层空口调度与反压](链路层空口调度与反压.md#link-contract)。跨层文件交付顺序见[系统分层与跨层契约](系统分层与跨层契约.md#cross-layer-contracts)。

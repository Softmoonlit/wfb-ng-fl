# 链路层空口调度与反压

<a id="link-contract"></a>

## 所有权

本文档唯一拥有 TUN 边界、控制面与数据面分流、READY/GRANT、活跃队列、Token Passing、反馈机会、FEC/接收重组、发送队列、动态水位、反压、角色配置、节点身份、链路域和链路安全模式。它不拥有 FL Runtime 状态机、HTTP/UFTP 字段或物理层硬件能力。

## TUN 边界和分流

TUN 是上层 IP 流量与无线链路之间的虚拟网络边界。Transport 的普通 TCP/IP 和 UFTP 数据进入 TUN；链路层控制帧不经过 TUN。

空口接收后，链路层先区分控制面和数据面：

- 控制面帧进入控制面优先通路，更新授权、声明、反馈机会和活跃状态，不进入普通数据面 FEC、接收重组缓冲或 TUN。
- 数据面流量进入接收重组缓冲，经过 FEC/缺片处理后写入 TUN。
- 接收重组缓冲溢出不能阻塞控制面优先通路。

控制帧使用统一外层身份区分 `control_type`，各类型拥有专属精确载荷形态。`GRANT` 载荷承载 `duration_ms`，`READY` 载荷为空；给定 `version` 和 `control_type` 的总长度固定，接收端不得接受尾随字段。反馈窗口是调度行为，不要求独立的 `FEEDBACK_WINDOW` 控制帧。

## READY 和活跃队列

上行就绪声明（READY）由客户端上行发送队列从空变为非空时触发，表示本机已有等待空口发送机会的数据面出站积压。文件级待上传 ready 标记、训练完成或 `submit_update(...)` 调用本身不直接等同于 READY。

server 对 READY 的正式裁决顺序固定为：

1. 结构合法性检查。
2. `source_node` 必须等于发送声明的 client 自身 `NODE_ID`。
3. 接收入口和当前链路域必须正确。
4. `source_node` 必须属于静态已知 client 集。
5. 合法声明使节点进入活跃队列；已在队列中的重复声明只刷新活性，不改变轮换顺序。

非法 READY 至少按 `invalid_source`、`wrong_ingress_or_link_domain`、`unknown_client` 三类原因分别计数和日志记录。最小日志字段包括拒收原因、`source_node`、接收入口/链路域标识、当前 server `NODE_ID`，可判定时附带 `target_node` 和 `control_type`。READY 的 `target_node` 是可选上下文；缺失、零值或未填写不单独形成异常。指标默认按原因聚合，不按 `source_node` 拆维。

活跃队列是当前参与上行 Token Passing 轮换、尚未被移除的客户端集合及其顺序。静态已知 client 集只表达资格，不携带轮换顺序。活跃队列为空时不发普通上行 GRANT，只等待合法声明。

## GRANT 和 Token Passing

Token Passing 是中心化空口发送权分配机制。server 只向活跃队列中的 client 发放上行 GRANT；每个 GRANT 必须有明确的 `target_node`，不能使用 `0` 或 `ALL` 表示上行目标。单 server 下 `GRANT.source_node` 必须等于当前 server 的 `NODE_ID`。

GRANT 在结构合法后按以下顺序裁决：来源节点合法性、目标节点过滤、过期判定、序号新鲜度。只有来源合法且目标为本机、未过期的 GRANT 才能更新本机状态；`expires_at_ms <= now_ms` 即过期。只有 GRANT 对控制帧 `sequence` 施加按 `source_node` 的单次发送端生命周期内单调递增和接收端去重/过期语义；发送端重启必须通过独立重置边界清空接收侧新鲜度状态。READY 不依赖 `sequence`。

GRANT 是硬截止发送机会。每次上行发送机会使用固定的 `duration_ms` 和固定的 `guard_interval_ms`；本契约不引入根据队列或链路观测自动扩大的自适应时长。到期后 client 必须停止空口发送，未完成数据继续留在客户端上行发送队列中，等待下一次机会。Transport 的单个 TCP/HTTP 请求可以跨多个 grant，连接和请求不因 grant 到期重建。

## 反馈窗口

反向控制窗口是主发送方向之外的链路层发送机会，不是独立物理通道或额外配置 stream。

下行 UFTP 反馈窗口的目标契约是：server 按固定周期暂停主发送，从运行时活跃队列生成本轮反馈轮快照，按快照顺序发放使用固定 `duration_ms` 的短 GRANT，并在该轮短 GRANT 与固定 `guard_interval_ms` 完成后立即结束；client 在自身机会中回传缺块或完成状态。反馈轮快照只使用当时的活跃队列，不把静态已知 client 集输入顺序作为长期轮询配置。

当前存在的过渡实现可能仍按全部静态已知 client 的固定顺序轮询。该实现偏差必须局部记录为：目标是活跃队列快照；退出条件是反馈轮从运行时活跃队列生成快照并不再依赖已知集合输入顺序；在退出前不得把旧顺序升格为正式配置、接口或长期不变量。该过渡标注不改变目标契约。

Issue #41 P0 可以显式配置反馈窗口在 server 链路启动时立即打开，用于避免 shared UFTP 的首次 REGISTER 依赖 READY 到达。此时短 GRANT 仍按现有静态已知 client 轮询，且普通 READY/活跃队列语义不变；该临时配置可能与普通长 GRANT 时间片交错。它不表达 UFTP operation 生命周期，不定义 UFTP/HTTP 阶段隔离，也不改变本节目标契约。

当前 HTTP/TCP per-client 上行场景只要求在普通 GRANT 之间为 server 保留 ACK/control 反向回传机会；该机会不扩展为与下行 UFTP 反馈同构的固定周期反馈轮。

## 队列、FEC 和重组

链路层使用固定容量用户态队列承接已从 TUN 读入但尚未进入空口的数据。容量同时受字节数和数据包数量约束；客户端上行队列和 server 下行队列分属不同角色与方向。

动态逻辑水位以 `queued_bytes` 为主口径，通过 pause/resume 双阈值滞回控制是否继续从 TUN 读取；`queued_packets` 是容量硬上限。`queued_bytes` 只统计当前用户态发送队列内尚未发出的数据面 payload 字节，不含历史吞吐和对象开销。

- 达到 `pause_threshold_bytes` 时停止继续读取 TUN。
- 降至 `resume_threshold_bytes` 时恢复读取。
- `queued_packets` 先达到硬上限时也必须立即停读，并以独立原因记录，不与字节水位混同。
- server 下行和 client 上行允许使用不同阈值组。
- 停读、恢复和丢弃原因必须可通过日志/指标观察，不能静默丢弃已接受的数据。

接收重组缓冲属于入站数据面，和出站发送队列分离。它承接乱序、缺片和 FEC 恢复，按有限未完成 block 窗口工作；达到上限时淘汰最老未完成 block，为新 block 让位。重组溢出不改变 `queued_bytes`/`queued_packets` 口径，也不能阻塞控制面。

稳定运行时至少提供以下可观测字段：`reassembly_overflow_evict`、`evicted_block_idx`、`evicted_has_fragments`、`unfinished_blocks`、`unfinished_block_limit`、按原因累计的 TUN 停读次数和恢复次数、`queued_bytes_threshold` 与 `queued_packets_limit` 停读原因、`grant_sent_total`、READY 按原因的拒收计数、反馈窗口开始/结束计数（覆盖该场景时）。逐事件拒收上下文、GRANT 过滤/过期/去重细节、活跃队列变化和重组淘汰细节属于排障日志，不改变协议完成判定。

## 角色、身份和链路域

集成式链路层使用单一实现和显式 `role=server|client`。角色必须在最终配置中显式存在；未知角色、缺少角色专属参数或混用两侧参数时启动 fail-fast。

公共参数至少包括：`role`、方向链路域/`link_domain`、本机无线接口、`NODE_ID`、`link_id`、`uplink_stream`、`downlink_stream`、日志/指标位置、控制帧边界、链路安全模式和统一配置入口。`link_id` 是显式整数标识；WFB `channel_id` 可以由链路域与无线方向配置映射得到，但 `link_id`/`channel_id` 不承担节点级寻址语义。server 专属参数包括静态已知 client 集、GRANT 调度、反馈轮和 server 下行队列阈值；client 专属参数包括 READY、client 上行队列阈值和本地 token gate。

每个节点（server 与 client）都必须配置 `NODE_ID`；同一链路域内唯一，不按上下行 stream 分成两套编号空间。server 不使用协议级保留值、推荐值或默认值。单一链路域只定义一个 server，不支持多 server 并存或 client 切换。

`link_domain`/WFB `channel_id` 用于隔离空口通信范围；`link_id` 是该链路配置的显式整数标识，`channel_id` 只承担当前链路域过滤边界的映射语义。方向链路域分开 server 到 clients 的下行数据面和 clients 到 server 的上行数据面。方向链路域不替代控制帧中的 `NODE_ID` 目标过滤，也不代表额外的独立 control stream。`uplink_stream` 和 `downlink_stream` 作为成对公共配置同时存在。

配置合并顺序为：程序安全默认值、主配置/profile、角色专属配置段、服务环境注入、显式 CLI；合并后重新按 role 做 fail-fast 校验。启动摘要至少显示 role、链路域、NODE_ID、stream、接口、GRANT、队列/水位和反馈轮参数。

## 链路安全

链路安全模式必须显式配置并在控制面和数据面使用同一判定。模式为 `trusted_plaintext` 或历史对照用的 `legacy_encrypted`；受信任明文模式旁路 keypair、session 和 AEAD 路径，并明确标注“受信任环境、无链路机密性”风险。模式与参数不匹配时 fail-fast，不能形成部分关闭加密的混合状态。

链路安全模式不改变 packet type、方向链路域、控制帧边界、普通数据面 FEC、重组、队列和 Token gate 的层次语义。

## 与相邻层的关系

Transport 通过 TUN/IP 把文件交换映射为普通数据流，并依赖本专题的发送机会与反压；它不调用链路层控制 API。无线物理层提供 monitor、raw injection、广播、Radiotap/HT/VHT 和射频观测能力，本专题负责把这些能力组织为链路协议。完整上下行顺序和跨层完成边界见[系统分层与跨层契约](系统分层与跨层契约.md#cross-layer-contracts)。

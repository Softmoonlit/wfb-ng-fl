# v6旧参数迁移矩阵

## 目的

本文件用于承接 `wfb_tx`、`wfb_rx`、`wfb_tun` 到 `v6` 集成式链路层守护进程的参数迁移设计。

它是 `v6` 实现前置工件，不得在代码实现阶段临时口头决定旧参数去留。凡现有有效参数，都必须先进入本矩阵，再进入实现与测试。

## 适用范围

- `src/tx.cpp` 的公开启动参数
- `src/rx.cpp` 的公开启动参数
- `src/wfb_tun.c` 的公开启动参数
- 现有编排层对上述参数的实际依赖与转发

## 五种去向

每个旧参数必须且只能归入以下五类之一：

- **保留**：继续作为 `v6` / 后续正式运行目标的公开可配置项存在
- **改名归并**：不再保留原名，但迁入新参数 / 新配置段
- **内部化**：不再作为公开主参数暴露，但仍作为集成式内部实现连线或内部配置存在
- **废弃**：在后续正式运行目标中彻底移除，且不再进入有效配置面
- **基线专用**：仅供 `legacy_encrypted` 等历史基线 / 迁移对照 / 回归参考路径使用，不进入后续正式运行目标的公开参数面

若同一旧参数在“正式运行目标”和“历史对照路径”上的去向不同，矩阵必须显式同时写明，不得混写成单一结论。

## 全量收录要求

迁移矩阵必须先**全量收录**以下来源的现有有效参数，再逐项裁决去向：

- `src/tx.cpp` 的全部公开 CLI 参数
- `src/rx.cpp` 的全部公开 CLI 参数
- `src/wfb_tun.c` 的全部公开 CLI 参数
- `wfb_ng/services.py` 等现有编排层对上述参数的实际转发、拼装、依赖与隐式默认值

禁止只挑“重点参数”或“当前打算先实现的参数”进入矩阵。未收录项一律视为迁移设计未完成。

本矩阵不再使用单一 `v6去向` 列；每一行必须显式填写 `正式运行去向` 与 `历史对照去向` 两列。若两条路径结论一致，也必须分别填写相同值，不得省略其中一列。

迁移矩阵允许按“两阶段录入”推进：第一阶段先完成来源项全量收录；第二阶段再逐项补齐正式运行/历史对照去向、目标落点、启动摘要可见性与理由。第一阶段尚未完成裁决的相关单元格，统一填写“待裁决”，不得留空，也不得混用 `TODO`、`TBD` 等占位。进入实现前，矩阵中不得残留任何“待裁决”单元格。

## 裁决顺序

迁移矩阵逐项裁决时，按以下顺序推进：

1. **先判外部语义稳定参数**：角色 / 身份 / `NODE_ID` / 无线链路 / `TUN` 边界 / 队列水位 / 控制调度 / 链路安全模式等直接决定新主接口的参数
2. **再判 split-process 本地连线参数**：本地 UDP / UNIX socket、peer / bind、旧 aggregator / distributor / injector / forwarder 等主要服务历史多进程拼线的参数
3. **最后判历史模式分叉与边缘参数**：旧调试路径、边缘拓扑分叉和接近废弃候选的参数

禁止按实现者个人兴趣跳着裁决，以免先被历史拼线细节牵着走，反而延迟新主接口收口。

## 无线链路参数组口径

迁移矩阵中的**无线链路参数组**，定义为“**TX 发射配置参数 + RX 配套观测口径**”的联合组，而不是要求 `tx/rx` 两侧存在完全对称的公开配置项。

- TX 侧重点裁决：带宽、`GI`、`STBC`、`LDPC`、`MCS`、`NSS`、`frame_type` 等直接决定空口发射行为的参数
- RX 侧重点裁决：`mcs_index`、`bandwidth`、`freq`、天线 / `RSSI` 等配套观测口径，作为统计、证据与调优依据，而非对称发射配置项

禁止为了形式对称而给 RX 硬造并不存在的无线发射配置接口。

## TUN边界参数组口径

迁移矩阵中的 **TUN 边界参数组** 单独成组裁决，默认归入“保留”或“改名归并”，而不是被动内部化。

该组至少覆盖：

- `tun_name` / `ifname`
- `tun_addr` / `ifaddr`
- `default_route` / route 相关边界
- `mtu` / `radio_mtu` 相关边界
- `agg_timeout` / `tunnel_agg_timeout` 等直接影响 `TUN` 与链路层拼接行为的参数

`TUN/IP` 是当前正式上边界；因此凡直接决定链路层如何与上层 `IP` 世界接壤的参数，默认不得静默内部固化。

## 身份与链路域参数组口径

迁移矩阵中的 **身份与链路域参数组** 单独成组，并优先于其他参数组完成裁决。

该组至少覆盖：

- `role`
- `NODE_ID` / `local_node_id`
- `link_id`
- 旧 `radio_port` 到 `uplink_stream` / `downlink_stream` 的改名归并规则
- `channel_id` 映射规则
- `uplink_stream` / `downlink_stream` 方向链路域配置
- 与链路安全模式及其对应身份材料的绑定关系

这组参数定义“本节点是谁、属于哪个方向链路域、发送到哪个域、接收哪个域”；若该组未先收口，则控制帧 envelope、数据面方向链路域和 `server/client` 二分都无法稳定收口。
`role` 允许来源于 profile、配置段、systemd 环境或 CLI，但迁移裁决后的最终生效配置里必须显式落成唯一的 `role=server|client`；不得把 unit 名、profile 名或配置段名本身当作最终角色契约，也不得允许运行时仅靠隐式推出角色。最终生效配置固定分为“公共参数层 + 当前 `role` 对应的角色专属参数层”；若 `role=server` 却出现 client 专属参数，或 `role=client` 却出现 server 专属参数，一律 fail-fast。
其中 `link_id` 继续作为 `v6` 正式公共参数名保留，并在第一版中保持为显式整数标识，不引入字符串别名或标签层。旧实现事实允许 `channel_id = (link_id << 8) + radio_port` 这类映射继续存在，但该关系只属于当前链路域过滤边界的实现映射，不升格为节点级寻址语义。旧 `radio_port` 仅作为历史参数名进入迁移矩阵，不再作为 `v6` 正式公共参数名保留。`v6` 正式接口改用 `uplink_stream` / `downlink_stream` 表达方向 stream，不再把 stream 值与链路域混称；`link_id` / `channel_id` 不承担节点级控制目标语义，节点级目标仍由 `NODE_ID` / `target_node` 体系承担，READY 第一版例外也仅是不依赖 `target_node`，而不是把 `channel_id` 升格成节点地址。
`uplink_stream` / `downlink_stream` 作为系统方向链路域契约成对保留为公共参数，不因 `server` / `client` 角色不同而只暴露一半；角色只决定本节点通常主发/主收哪个方向，不改变这两个公共参数同时存在。
`NODE_ID` 作为链路层节点逻辑标识，server 与 client 都必须配置；迁移裁决不得把 server 继续当作无 `NODE_ID` 的协议特例，也不得引入 server 协议级保留常量、推荐值或默认值。双方共享同一显式配置取值空间，并要求在同一链路域内唯一，不按 `uplink_stream` / `downlink_stream` 再拆两套编号空间。旧实现或旧测试中的 `NODE_ID=0` 只可作为历史基线 / 过渡兼容事实保留，不得写回 `v6` 正式运行契约。
第一版同一链路域内只定义单个 server；client 不新增 `server_node_id` / `target_server_node` 一类正式公开参数，也不支持多 server 并存或切换。若过渡期仍存在 server grant / ready 入口、namespace、socket base 等信息，默认按桥接 / 部署编排参数裁决，不并入 client 正式主配置契约。
第一版 READY / 上行就绪声明只表达“发送者 `NODE_ID` 已具备上行发送条件”，不显式携带 server target 语义，也不要求 client 新增 `server_node_id` / `target_server_node` 一类正式公开参数；统一 envelope 虽保留公共 `target_node` 与 `sequence` 字段，但第一版 READY 的正式接收裁决既不依赖 `target_node`，也不依赖 `sequence`，READY 不因这两个字段形成专属 target / 去重契约。`READY.source_node` 必须显式等于发送该声明的 client 自身 `NODE_ID`，server 也据此完成静态已知 client 资格判定与活跃队列入队/刷新。被拒收的 READY 不得静默吞掉，至少要按“非法来源”“错误接收入口 / 链路域”“未知 client”三类原因分别计数并打日志；相关日志默认采用最小排障字段集：至少包含拒收原因、`source_node`、接收入口 / 链路域标识、当前 server `NODE_ID`，以及若能判定则带 `target_node` / `control_type`，其中 READY 的 `target_node` 仅作可选上下文，不因缺失、零值或实现未填而单独形成异常。第一版指标默认只按拒收原因聚合，不按 `source_node` 拆维；节点级排障细节留给日志。server 对重复 READY 的第一版行为固定为“未在活跃队列则入队，已在活跃队列则只刷新活性而不改变顺序”；若后续需要多 server、server 选路、READY 重放防护或更细新鲜度规则，再作为后续版本单独开题，不在第一版预埋 target 或专属去重字段。
统一 control envelope 在第一版仍可保留 `target_node` 公共外层字段，但 `GRANT` 必须显式指向某个具体 client `NODE_ID`，`target_node=0/ALL` 对 `GRANT` 一律非法；而 READY 的正式语义不依赖该字段。READY 在实现里若暂时填写某个具体 `target_node` 值，也只属于实现细节，不要求必须等于 server `NODE_ID`，更不自动升格为正式契约。
第一版普通数据面帧既不携带独立的 `target_node`，也不新增独立的 `source_node` 正式协议字段；但 shared uplink 多 sender 场景下，发送端必须在既有 `data_nonce` 中编码 sender namespace，server 也必须在进入 unfinished-block 重组前先解析该 namespace 并完成静态已知 client 裁决。节点级控制目标仍只属于控制帧 envelope，不把普通数据面改成 control envelope，也不新增普通数据面的 `target_node`
第一版统一 control envelope 保留显式 `version` 字段；`packet_type + magic + version` 共同构成最小解析边界。第一版仅接受单一固定 `version`，不匹配时直接丢弃并记录，不做隐式兼容；后续 envelope 结构演进优先通过显式版本升级完成。
第一版 `control_type` 采用严格有限枚举；第一版正式支持的控制类型至少包括 `GRANT` 与 `READY`。未知 `control_type` 一律直接丢弃并记录，不做隐式兼容或宽松透传；后续若引入阶段控制、静默或公告类控制，也必须先写文档并显式增补枚举值，而不是复用现有类型或依赖 flags 偷表达。
第一版 `GRANT` 必须占用独占专用 `control_type`；普通 `GRANT` 与反馈轮短 `GRANT` 不拆成不同类型，仍统一归为 `GRANT`。反馈轮、反向控制窗口等仅属于调度行为上下文，不单独占用新的 `control_type`；抓包、日志、验收与统计都直接以 `GRANT` 作为一等控制语义观察单位。
第一版 `READY` 也必须占用独占专用 `control_type`；其语义只表达“发送者 `NODE_ID` 已具备上行发送条件”。若未来需要新的 client->server 控制消息，必须单独新增显式 `control_type`，不允许通过复用 `READY`、追加 flags 或引入 `CLIENT_SIGNAL` / `CLIENT_EVENT` 父类型来偷偷扩义。
第一版文档先冻结 `control_type` 的语义集合，不先冻结具体数值编号；当前至少冻结 `GRANT` 与 `READY` 两个显式控制类型。具体枚举值留到实现阶段或协议定义文件中统一落定，但必须保证值唯一且与文档语义严格一致；若后续出现外部工具链或抓包格式对编号表的稳定依赖，再把数值表提升为显式文档契约。
第一版控制帧 payload 采用“统一 envelope + 按 `control_type` 分型负载”口径，而不是所有控制类型共用同一固定控制体。`GRANT` 的第一版专属 payload 固定承载 `duration_ms`；`READY` 的第一版专属 payload 固定为空载荷，不再为其保留 grant 专属字段。给定 `version` 后，每个 `control_type` 还必须对应唯一精确总长度；接收端不得继续沿用类似“`size < sizeof(wtoken_control_hdr_t)` 则拒绝、否则放行”的最小长度兼容模型。统一 envelope 虽保留公共 `sequence` 字段，但第一版接收端只对 `GRANT` 按 `source_node` 维护新鲜度状态并执行 duplicate / stale 拒绝，且在单 server 第一版下该 `source_node` 必须显式等于当前 server `NODE_ID`；该单调性仅要求覆盖单次发送端生命周期，跨重启接受较小序号时必须先通过独立重置边界清空对应源节点状态。`READY` 虽不依赖 `sequence` 完成正式接收裁决，但在第一版中其 `source_node` 仍必须显式等于发送该声明的 client 自身 `NODE_ID`。进入类型语义裁决后，`GRANT` 的正式判定顺序冻结为“来源节点合法性 → 目标节点过滤 → 过期判定 → `sequence` 新鲜度判定”；`source_node != server NODE_ID`、发给其他节点或已过期的 grant 都不得更新本节点新鲜度状态，且过期边界固定为本地 `expires_at_ms <= now_ms` 即失效。`READY` 的正式判定顺序则冻结为“来源节点合法性 → 当前链路域接收入口 → 静态已知 client 资格 → 活跃队列入队/刷新”；非法 READY 不得进入活跃队列，且至少要按“非法来源”“错误接收入口 / 链路域”“未知 client”三类原因分别计数并打日志，日志最小字段集至少包括拒收原因、`source_node`、接收入口 / 链路域标识、当前 server `NODE_ID`，以及若能判定则带 `target_node` / `control_type`；其中 READY 的 `target_node` 仅作可选上下文，不因缺失、零值或实现未填而单独形成异常。第一版指标默认只按拒收原因聚合，不按 `source_node` 拆维。旧实现里若存在类似 `wtoken_control_hdr_t` 的单一固定控制体，只能视为历史实现事实，不自动升格为 `v6` 正式协议契约；迁移时必须显式拆回 envelope、按类型校验的专属 payload 规则与精确长度校验。
后续凡涉及角色差异的迁移裁决，都必须明确写成“公共参数层 / server 专属参数层 / client 专属参数层”之一；不得继续写成“按 profile、unit 或命名约定自行理解”。

## 控制调度参数组口径

迁移矩阵中的 **控制调度参数组** 单独成组，并按以下三层裁决，禁止笼统地全做公开配置或全做内部参数：

1. **协议冻结常量**：第一切片已冻结且不面向现场调参的控制调度规则，例如仅携带相对 `duration_ms`、`GRANT/READY` 按 `control_type` 分型 payload、`READY` 第一版固定为空载荷、各 `control_type` 在给定 `version` 下采用精确总长度校验、单 server 第一版中 `GRANT.source_node == server NODE_ID`、`READY.source_node == 发送该声明的 client NODE_ID`、`GRANT` 采用“来源节点合法性 → 目标节点过滤 → 过期判定 → `sequence` 新鲜度判定”裁决顺序、`READY` 采用“来源节点合法性 → 当前链路域接收入口 → 静态已知 client 资格 → 活跃队列入队/刷新”裁决顺序，且 `GRANT` 本地 `expires_at_ms <= now_ms` 即过期、不携带绝对截止时间、不新增独立 control stream、不引入自适应扩窗等
2. **运行时内部动态状态**：例如 `expires_at_ms`、仅针对 `GRANT` 的新鲜度过滤状态、当前轮询位置、反馈轮进行态，以及随 session/`epoch` 重置边界一并清空的按源节点最新 `sequence` 观测状态等；这类状态不作为公开配置，但必须可观测；其中非法来源、发给其他节点或已过期 grant 都不得污染该新鲜度状态，非法 READY 也必须至少按“非法来源”“错误接收入口 / 链路域”“未知 client”三类原因分别进入日志 / 指标 / 事件观测面，而不得静默合并成一个模糊总数；单条 READY 拒收日志的最小排障字段集至少包括拒收原因、`source_node`、接收入口 / 链路域标识、当前 server `NODE_ID`，以及若能判定则带 `target_node` / `control_type`，其中 READY 的 `target_node` 仅作可选上下文，不因缺失、零值或实现未填而单独形成异常；对应指标默认只按拒收原因聚合，不按 `source_node` 拆维。
3. **部署级公开配置**：例如固定 `grant_duration_ms`、固定 `guard_interval_ms`、反馈轮周期、短 `GRANT` 时长、静态已知 client 集，以及其他经证明仍有独立现场调优价值的调度参数；其中静态已知 client 集在第一版只表达 `NODE_ID` 集合，且对 `server` 必须为非空集合。该集合属于启动期确定配置，第一版不支持运行中热更新，任何增删都通过配置变更 + 重启实例生效。该集合本身只有资格集合语义，不携带静态轮换顺序；上行 grant 顺序只由活跃队列进入顺序决定。只有属于该静态集合的节点，其 `READY` 才能被接受。活跃队列及其当前顺序仅属于运行时动态状态，不并入手工静态轮换表配置；namespace、socket base、`IP` / `TUN` 地址等桥接或部署编排信息不并入该正式参数组，后续裁决时默认按 split-process 本地连线 / 编排参数处理。若运行中当前活跃队列为空，则属于合法运行态，只表现为不发普通上行 `GRANT` 并保持空闲等待与观测，不反推为配置错误。若后续需要独立表达下行反馈轮固定顺序，必须新增单独 server 专属参数，不得复用静态已知 client 集输入顺序

只有第三层进入公开配置面；第一层进入协议 / 规划冻结，第二层进入日志 / 指标 / 事件观测面。

## 启动生效配置摘要口径

启动生效配置摘要汇总**所有参数组中的部署级公开配置**，而不是只覆盖控制调度组；其中包括从 `wfb_tx` / `wfb_rx` / `wfb_tun` 迁移后仍保留公开语义的身份与链路域、无线链路、`TUN` 边界、队列 / 水位、控制调度、链路安全模式、日志 / 指标等参数；仅在启用旧加密模式时，密钥 / 接口绑定才进入启动摘要。

其中角色相关内容只展示公共参数层与当前 `role` 的专属参数层，不展示另一角色的专属参数。

各参数组中的运行时内部动态状态只进入事件 / 指标 / 日志观测面，不进入启动摘要。

## 第一版验收证据分层口径

正式执行细则以 `docs/v6第一版正式验收标准细则.md` 为准；本节只保留参数迁移视角下的验收分层摘要，不再单独形成另一套判定标准。

第一版正式验收采用“双层验收”口径：

1. **外部语义通过层**：双基线等价、传输完成、无长期失活、共享下行 / 独立上行语义未退化等外部行为成立。
2. **观测证据完整层**：必须能从日志 / 指标或等价观测证明队列受限、控制窗口推进、`READY/GRANT` 关键裁决、反馈轮推进与恢复行为真实发生。
   - **2A 结构化必需证据**：必须形成稳定字段、固定计数或可归档摘要，便于自动判定、正式证据回填与跨批次对照。第一版 `2A` 不允许只散落在多段日志 / 多组指标里依赖人工拼装，必须为单次 run 产出一份统一结构化摘要以便归档、对照与自动判定。控制面最小 `2A` 集合先冻结为 `grant_sent_total`、`ready_accepted_total`、`ready_rejected_total_by_reason`、`feedback_window_open_count/feedback_window_close_count`（仅在场景覆盖反馈轮时必需）以及“目标 client 在短 `GRANT` 时隙内收到反向上行数据”的结构化计数。其中 `ready_rejected_total_by_reason` 只统计已经通过结构合法性检查并进入 READY 语义裁决后的三类拒收原因：`invalid_source`、`wrong_ingress_or_link_domain`、`unknown_client`；长度 / magic / version / control_type / payload 形态等结构解析失败不并入该指标。反馈窗口相关 `2A` 只要求证明开始/结束以及目标 client 在其短 `GRANT` 时隙内收到反向上行数据，不要求把反馈轮内逐个短 `GRANT` 的发放数升格为结构化必需证据；同样也不要求把 `GRANT` 目标过滤拒绝、过期拒绝或 stale / duplicate 拒绝中的任何一项升格为 `2A`。除控制面外，第一版队列 / 反压最小 `2A` 还至少包括：`TUN` 停读次数、恢复读次数，以及按原因累计的停读汇总；停读原因第一版至少区分 `queued_bytes_threshold` 与 `queued_packets_limit`，且该汇总按本次运行期间实际发生过的原因累计计数冻结，不强制要求把结束时当前停读原因快照也升格为 `2A`。RX 重组溢出相关 `2A` 只要求保留 `reassembly_overflow_evict` 计数与 `unfinished_block_limit` 可归档摘要，用于证明溢出曾真实发生且容量边界可追溯。
   - **2B 补充日志证据**：必须留下可核对留痕，用于解释状态迁移、拒收原因、恢复路径与异常上下文；但不要求第一版全部统一成同一套硬指标标签或数值门槛。单条拒收上下文、`target_node` 可选上下文、`GRANT` 目标过滤 / 过期 / 序号拒绝明细（包括 stale / duplicate 拒绝）、活跃队列逐条入队 / 刷新过程、反馈轮内逐个短 `GRANT` 的发放过程、单次停读 / 恢复事件的详细上下文、结束时当前停读原因快照，以及 `evicted_block_idx`、`evicted_has_fragments`、`unfinished_blocks` 等 RX 重组溢出细节与结构解析失败明细等，默认停留在 `2B` 而不误升格为 `2A`。

统一结构化摘要除行为 `2A` 计数外，还必须携带最小场景元数据，至少包括 `run_kind`、`link_security_mode`、`scenario_id`、`feedback_window_covered`；这些元数据同样属于 `2A`，用于界定该次正式证据对应的验收场景与运行路径。`scenario_id` 必须使用受控枚举；当前 namespace 正式验收实现已把枚举集中到 `wfb_ng/tests/v6_formal_summary.py`，并冻结 `v6_namespace_uplink_backpressure_reassembly` 与 `v6_namespace_downlink_shared_uftp_feedback` 两个取值。

日志 / 指标因此属于正式验收所需的证据层，而不是可有可无的调试副产物；但它们也不直接等同于每条能力项都必须先冻结成单一数值阈值。两层任一缺失，正式验收都不得判定为通过；而属于 `2A` 的项目也不得降格为“只有散乱日志即可”。

## 队列与反压参数组口径

迁移矩阵中的 **队列与反压参数组** 单独成组，并明确区分以下两类参数，禁止混为一谈：

1. **逻辑队列 / 反压参数**：如 `queued_bytes`、`queued_packets`、`pause_threshold_bytes`、`resume_threshold_bytes` 及 server/client 各自阈值组。这类参数描述链路层何时继续或停止从 `TUN` 读取，属于逻辑发送队列与反压契约。
2. **OS / I/O buffer 参数**：如 `rcv_buf`、`snd_buf` 及等价 socket / pcap buffer 调优项。这类参数描述底层内核 / I/O 缓冲设置，不得冒充逻辑停读阈值或固定容量用户态队列上限。

其中 **接收重组缓冲** 明确不属于本组的逻辑发送队列水位参数。

其中 `rcv_buf` / `snd_buf` 这类 **OS / I/O buffer 参数**，第一版默认保留为部署级公开配置；但在启动生效配置摘要与正式文档中，必须明确标注其属于内核 / I/O buffer 调优，不得与逻辑队列停读阈值或固定容量用户态队列上限共用同一语义栏位。

## 已冻结规则

### 1. 五种去向

每个旧参数在 `正式运行去向` 与 `历史对照去向` 两列中，都必须且只能填写以下五类之一：

- **保留**：继续作为 `v6` / 后续正式运行目标的公开可配置项存在
- **改名归并**：不再保留原名，但迁入 `v6` 新参数 / 新配置段
- **内部化**：不再作为公开主参数暴露，但仍作为集成式内部实现连线或内部配置存在
- **废弃**：在后续正式运行目标中彻底移除，且不再进入有效配置面
- **基线专用**：仅供 `legacy_encrypted` 等历史基线 / 迁移对照 / 回归参考路径使用，不进入后续正式运行目标的公开参数面

### 2. 默认内部化

凡仅因 split-process 本地 IPC 拼接而存在的旧参数，默认归入**内部化**。

### 3. 默认公开保留

凡直接表达以下外部运维语义的旧参数，默认归入**保留**或**改名归并**，不得静默内部固化：

- 无线链路
- 节点身份
- `TUN` 边界
- 旧加密材料：对正式运行目标 `trusted_plaintext` 一律按“废弃”裁决；仅在历史对照 `legacy_encrypted` 路径中标记为“基线专用”参数。
- 链路安全模式切到无加密时，默认优先选择“协议形态变化最小”的迁移方案：保留现有 `packet_type` 分层、方向链路域、控制帧边界与普通数据面 `FEC` / 重组 / 队列语义，仅裁决 `keypair/session/AEAD` 相关旧参数与路径。
- 链路安全模式裁决时，实现与迁移期仅识别 `legacy_encrypted` 与 `trusted_plaintext` 两种模式；其中 `trusted_plaintext` 为唯一正式运行目标，`legacy_encrypted` 仅作历史基线、迁移对照与回归参考，旧加密参数不得被裁成控制面 / 数据面各自独立的半态组合。
- 链路安全模式裁决落到实现时，参数校验必须 fail-fast：历史对照运行 `legacy_encrypted` 时保留并要求旧加密材料，正式运行 `trusted_plaintext` 时则禁止旧加密材料继续进入有效配置面。
- 链路安全模式落到实现后，`link_security_mode` 必须进入启动生效配置摘要与首条启动日志；正式运行目标固定输出 `trusted_plaintext` 风险标记，历史对照运行时才允许出现 `legacy_encrypted`。
- 队列 / 水位
- 控制调度

### 4. 废弃门槛

只有同时满足以下条件，旧参数才允许归入**废弃**：

- 不表达外部运维语义
- 不再作为集成式内部实现钩子存在

否则只能归入**保留**、**改名归并**、**内部化**或**基线专用**。

## 矩阵字段

每一行至少包含以下字段：

| 旧程序 | 旧参数 | 旧语义 | 当前调用 / 依赖位置 | 正式运行去向 | 历史对照去向 | 正式运行新参数名或配置段 | 历史对照新参数名或配置段 | 正式运行进入启动摘要 | 历史对照进入启动摘要 | 理由 |
|---|---|---|---|---|---|---|---|---|---|---|

两列去向都必须填写“五种去向”之一；若两条路径结论一致，仍分别填写同一值，不得合并回单列。两列目标落点也必须分别填写；若两条路径映射到同一新参数或同一配置段，仍分别填写相同值；若某一路径没有对应新参数名或配置段，则统一填写“无”，不得留空，也不得写 `-` 或 `N/A`。若去向为“内部化”且该路径下仍有稳定内部承载位置，则必须把该内部落点写出，不能一律写“无”。两列启动摘要可见性必须分别填写“是”或“否”；若两条路径都进入启动摘要，也仍分别填写“是”；不得填写“无”、空白或其他枚举。

`当前调用 / 依赖位置` 一列，最小粒度为“文件 + 符号/函数/参数解析位置”；若不存在稳定符号，则退到“文件 + 语义锚点”。不要求写行号，但不得只写孤立文件名。

`理由` 一列，使用短句、规则化说明；至少交代该去向的依据。若正式运行与历史对照结论不同，还必须补充差异原因。不得把实现步骤、测试步骤或大段背景散文塞入该列。

同一旧参数默认只占一行。只有当该旧参数实际承载多个不可合并的旧语义时，才允许拆成多行；一旦拆行，必须在 `旧语义` 一列把每行的语义边界写清楚。不得仅因正式运行与历史对照结论不同、理由较长或书写方便而拆行。

## v6 配置骨架

### 配置来源优先级骨架

- 程序内安全默认值 < 主配置文件 / profile 继承 < 角色专属配置段 < systemd 环境注入 < 显式 CLI 参数
- `wifibroadcast@<profile>`、profile 名、`--cluster` / `--wlans`、`WIFIBROADCAST_CFG` 与 `WFB_NICS` 都只能提供候选来源；最终生效配置里必须显式落出 `role=server|client`
- 合并后的最终结果必须再经过基于 `role` 的 fail-fast 校验：`role=server` 禁止混入 client 专属参数，`role=client` 禁止混入 server 专属参数
- `link_security_mode=trusted_plaintext` 时禁止旧 `keypair/session/AEAD` 参数继续进入有效配置面；`legacy_encrypted` 仅允许出现在历史对照路径

### 骨架执行规则

- 公共参数层只承载真正跨 `role` 稳定的外部运维语义；任何 split-process 本地拼线细节都不得回流到公共层
- `server` / `client` 专属参数层只承载角色真实差异；禁止把 `known_clients`、`uplink_token_gate`、`TUN` 拓扑参数长期混放在同一扁平命名空间靠运行时挑选
- 内部桥接参数必须默认不进入启动摘要，不参与正式验收的公共参数对齐；它们只服务过渡桥接、历史对照和测试调试
- 历史对照路径只允许承载正式运行目标已经废弃或内部化、但为了基线回放仍需保留的旧参数；不得反向倒灌成正式公开契约
- 进入实现前，本文件应作为唯一引用基线：新增参数或改名必须先落到上述四层骨架或历史对照路径之一，再进入代码与脚本

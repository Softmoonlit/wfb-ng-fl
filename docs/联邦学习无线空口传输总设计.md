# 联邦学习无线空口传输总设计

本文档描述联邦学习在高延迟、半双工无线空口上的总体传输设计。它承接 `CONTEXT.md` 中迁出的架构性内容，保留系统结构、流程、缓冲、调度和接口语义；具体难逆转的技术取舍记录在 ADR 中。

## 目标

- 保持联邦学习算法层只面对同步轮次语义
- 保持上层通过标准 IP 边界与底层无线链路解耦
- 在半双工空口上提供可预测的发送权、反馈窗口和反压语义
- 让大文件分发与多客户端上行都能形成稳定闭环

## 总体分层

系统从上到下分为五层：

1. **FL 算法层**
   - 负责训练、评估和聚合
   - 只表达联邦学习业务语义，不直接接触底层传输细节

2. **FL Runtime / SDK 层**
   - 负责同步轮次编排
   - 负责模型发布、模型等待、参数提交和参数收集
   - 负责把业务文件交换动作交给下方传输层

3. **Transport Backend 层**
   - 负责把文件交换语义映射到具体传输方式
   - 下行对接 UFTP，上行对接 per-client TCP，后续可切换或增加 KCP

4. **链路层**
   - 负责 TUN 读写、空口收发、Token gate、队列、水位和反压
   - 负责在主发送方向之外保留反馈回传机会

5. **物理层**
   - 负责 802.11 广播/注入
   - 不依赖硬件 ACK 作为系统闭环前提

## 端到端流程

### 下行：Server → Clients

1. Server 在 FL Runtime 中发布本轮全局模型
2. Transport Backend 将模型交给 UFTP 下行
3. 链路层在下行阶段控制空口发送节奏
4. Client 接收模型后在本地完成校验
5. 若发现缺块，Client 在反馈窗口中发送 UFTP 反馈

### 上行：Clients → Server

1. Client 完成本地训练后发出“已就绪”声明
2. Server 将该节点纳入活跃队列
3. Token Passing 为活跃节点分配上行发送机会
4. Client 在获得发送机会后上传 update
5. Server 接收 update、校验完成后交给 FL Runtime 聚合
6. Server 在发送窗口之间保留 ACK/control 回传机会

## 关键语义

### 下行阶段

下行阶段的核心不是“持续猛灌”，而是“呼气 + 反馈回收”的节奏控制。Server 主导发送模型文件，Client 在反向控制窗口中回传缺块和完成状态反馈。

### 上行阶段

上行阶段的核心不是“谁先写谁就赢”，而是“声明、排队、授予、发送、回传”这条闭环。训练完成只意味着节点可以进入活跃队列，不意味着可以立即占用空口。

### Token Passing

Token Passing 是中心化发送权分配机制。它控制节点在什么时候可以向空口发射，以及反馈窗口什么时候开放。

### 反向控制窗口

反向控制窗口用于承载与主发送方向相反的语义：

- 下行场景：UFTP 反馈
- 上行场景：TCP/KCP ACK/control

## 缓冲与反压

链路层采用两层缓冲语义：

- **固定容量用户态队列**：提供物理上界，避免无限积压
- **动态逻辑水位**：控制当前是否继续从 TUN 读取数据

当积压达到高水位时，链路层停止继续读入，让反压通过标准网络现象回传到上层。积压下降到低水位后，再恢复读入。

这套设计的重点是：不要把反压隐藏成静默丢包，而要让上层看到可感知、可恢复的拥塞信号。

## 上行会话模型

第一版上行采用 per-client 会话：每个客户端与服务端维持独立上行连接。

这样做的原因是：

- 便于验证单客户端闭环
- 便于把可靠性和反压行为与链路层调度一起观察
- 避免多个客户端共享单一会话带来的耦合

后续若 TCP 在真实半双工链路上吞吐不足，可切换或补充 KCP per-client 上行。

## FL Runtime 文件接口

FL Runtime 与传输适配层之间以文件作为解耦边界：

- 下行：模型文件与 manifest
- 上行：客户端 update 文件与 ready 标记
- 状态：轮次状态与收齐结果

这一接口的作用是把“联邦学习轮次”与“具体传输机制”拆开，让算法层不直接依赖 UFTP、TCP、KCP 或链路层细节。

# v6 新底座 real-hardware 现场演示手册

本文用于现场手动演示：系统在 `wfb_v6_uplink --role server/client` 新底座、`trusted_plaintext` 链路安全口径下，上行与下行都能通过三台真实机器上的 Wi-Fi monitor/raw-air 网卡完成大文件传输，并留下可归档证据。

演示口径：

- 不使用旧 `wfb_rx` / `wfb_tx` / `wfb_token_scheduler` / `-K`。
- server 在本机运行；client1、client2 分别在两台远端机器上通过 SSH 启动。
- 不创建或使用 Linux network namespace；三台机器均直接在各自默认网络环境中运行。
- 上行与下行都以“大文件传输实际耗时”为运行时长，不固定 180 秒。
- 默认文件大小为 `40MiB`，可通过 `DEMO_FILE_SIZE` 调整；排障时可先用 `1048576` 做 1MiB 探针。
- 上行证明双 client 独立 TCP 会话经 v6 新底座上行到 server。
- 下行证明 server 同一 payload 下发到两个 client，两个接收文件与 source SHA256 一致。
- 下行同时开启 feedback window，要求 `feedback_window_open_count` / `feedback_window_close_count` / `feedback_uplink_hit_total` 非零。
- 每轮必须保留 `result.md`、`formal_2a_summary.json`、原始日志、queue summary、SHA256 结果。

> 现场解释口径：这是“三机真实空口 + 文件驱动完整演示”，不是按固定秒数空跑。传输多久，链路层就必须在这段时间内持续推进；文件 SHA、GRANT/READY/feedback window/queue summary 一起证明系统正常。

## 1. 硬件与拓扑

默认三机拓扑：

| 角色 | 机器 | 默认 SSH / 本机标识 | 默认网卡 | TUN IP |
| --- | --- | --- | --- | --- |
| server | 本机 | local | `wlxbcec23372588` | `10.80.0.1/24` |
| client1 | 远端 1 | `virt@192.168.122.198` | `wlxfca386b38672` | `10.80.0.11/24` |
| client2 | 远端 2 | `virt@192.168.122.106` | `wlxfc221c300cbc` | `10.80.0.12/24` |

默认无线参数：

- channel：`157`
- width：`HT40+`
- link_id：`406`
- uplink stream：`32`
- downlink stream：`33`
- server node_id：`9`
- client1 node_id：`1`
- client2 node_id：`2`
- raw air 默认速率口径：`RADIO_BANDWIDTH=40`、`RADIO_MCS_INDEX=1`、`RADIO_SHORT_GI=1`
- client 上行队列默认水位：`UPLINK_PAUSE_THRESHOLD_BYTES=131072`、`UPLINK_RESUME_THRESHOLD_BYTES=65536`、`UPLINK_QUEUE_PACKETS_LIMIT=64`

如果现场 SSH 地址、仓库路径或网卡名不同，只改环境变量，不改命令结构。

默认启动口径优先使用 `HT40/MCS1/short GI` 与 `131072/65536/64` 队列水位。若现场弱信号、丢包或 TCP 会话不稳，可在启动前进一步保守化：

```bash
export RADIO_MCS_INDEX=1
export RADIO_BANDWIDTH=20
export RADIO_SHORT_GI=0
if [ "$RADIO_SHORT_GI" = "1" ]; then
  export RADIO_SHORT_GI_FLAG="--radio-short-gi"
else
  export RADIO_SHORT_GI_FLAG=""
fi
```

若现场链路稳定、需要恢复更高性能展示口径，再手工升档到 `RADIO_BANDWIDTH=40`、`RADIO_MCS_INDEX=3`、`RADIO_SHORT_GI=1`。

```bash
sudo pkill -x wfb_v6_uplink || true
```

## 3. 生成临时辅助脚本和演示文件

这些脚本只在本次演示日志目录内生成，用于通过 TUN TCP 传输大文件。它们不是旧 split-process 路径；真正的无线链路仍由 `wfb_v6_uplink` 负责。看到“TCP 接收器/发送器”时，含义都是应用层文件收发端，不是 WFB RX/TX 进程。

```bash
cat > "$DEMO_ROOT/tcp_recv.py" <<'PY'
#!/usr/bin/env python3
# -*- coding: utf-8 -*-
import argparse
import os
import socket

parser = argparse.ArgumentParser(description='接收一个 TCP 文件并落盘')
parser.add_argument('--bind-ip', required=True)
parser.add_argument('--port', type=int, required=True)
parser.add_argument('--output', required=True)
parser.add_argument('--timeout', type=float, default=300.0)
args = parser.parse_args()

os.makedirs(os.path.dirname(os.path.abspath(args.output)), exist_ok=True)
server = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
server.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)
server.settimeout(args.timeout)
server.bind((args.bind_ip, args.port))
server.listen(1)
conn, addr = server.accept()
conn.settimeout(args.timeout)
total = 0
with conn, open(args.output, 'wb') as fh:
    while True:
        data = conn.recv(65536)
        if not data:
            break
        fh.write(data)
        total += len(data)
print('received_bytes=%d peer=%s:%s' % (total, addr[0], addr[1]), flush=True)
PY

cat > "$DEMO_ROOT/tcp_send.py" <<'PY'
#!/usr/bin/env python3
# -*- coding: utf-8 -*-
import argparse
import socket
import time

parser = argparse.ArgumentParser(description='发送一个 TCP 文件')
parser.add_argument('--source-ip', default='')
parser.add_argument('--host', required=True)
parser.add_argument('--port', type=int, required=True)
parser.add_argument('--input', required=True)
parser.add_argument('--timeout', type=float, default=300.0)
parser.add_argument('--delay', type=float, default=0.0)
args = parser.parse_args()

if args.delay:
    time.sleep(args.delay)

deadline = time.time() + args.timeout
last_error = None
while True:
    sock = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
    sock.settimeout(max(1.0, min(5.0, deadline - time.time())))
    try:
        if args.source_ip:
            sock.bind((args.source_ip, 0))
        sock.connect((args.host, args.port))
        sock.settimeout(args.timeout)
        break
    except OSError as exc:
        last_error = exc
        try:
            sock.close()
        except Exception:
            pass
        if time.time() >= deadline:
            raise SystemExit('connect_failed=%s' % last_error)
        time.sleep(0.2)

total = 0
with sock, open(args.input, 'rb') as fh:
    while True:
        data = fh.read(65536)
        if not data:
            break
        sock.sendall(data)
        total += len(data)
    sock.shutdown(socket.SHUT_WR)
print('sent_bytes=%d target=%s:%d' % (total, args.host, args.port), flush=True)
PY

chmod +x "$DEMO_ROOT/tcp_recv.py" "$DEMO_ROOT/tcp_send.py"
```

在 server 本机生成 source 文件：

```bash
python3 - <<'PY'
import os
from pathlib import Path
root = Path(os.environ['DEMO_ROOT'])
size = int(os.environ['DEMO_FILE_SIZE'])
for name, pattern in [
    ('client1_uplink.bin', b'client1-uplink-demo\n'),
    ('client2_uplink.bin', b'client2-uplink-demo\n'),
    ('server_downlink.bin', b'server-downlink-shared-demo\n'),
]:
    path = root / name
    with path.open('wb') as fh:
        remaining = size
        while remaining > 0:
            chunk = pattern[:remaining] if remaining < len(pattern) else pattern
            fh.write(chunk)
            remaining -= len(chunk)
PY

sha256sum "$DEMO_ROOT"/*.bin | tee "$DEMO_ROOT/source_sha256.txt"
```

### 4.2 执行双客户端上行大文件

启动 server 侧两个应用层 TCP 文件接收器。它们都绑定同一个 server TUN IP `10.80.0.1`，只是端口和落盘文件不同；上行共享无线/WFB 接收进程仍然只有 4.1 中的 `U_SERVER_PID` 一个，不是两个 WFB RX：

```bash
sudo "$DEMO_ROOT/tcp_recv.py" \
  --bind-ip 10.80.0.1 \
  --port 19111 \
  --output "$ULOG/server/client1_uplink_received.bin" \
  > "$ULOG/server/client1_tcp_recv.log" 2>&1 &
export U_RECV1_PID=$!

sudo "$DEMO_ROOT/tcp_recv.py" \
  --bind-ip 10.80.0.1 \
  --port 19112 \
  --output "$ULOG/server/client2_uplink_received.bin" \
  > "$ULOG/server/client2_tcp_recv.log" 2>&1 &
export U_RECV2_PID=$!
```

两个 client 通过 SSH 同时上传。这里等待的是本机 SSH 包装进程；远端 `tcp_send.py` 的详细输出写入远端日志，随后再拉回本机归档。

```bash
ssh "$CLIENT1_HOST" "python3 '$CLIENT1_DEMO_ROOT/tcp_send.py' \
  --source-ip 10.80.0.11 \
  --host 10.80.0.1 \
  --port 19111 \
  --input '$CLIENT1_DEMO_ROOT/client1_uplink.bin' \
  --timeout 300 \
  > '$CLIENT1_ULOG/tcp_send.log' 2>&1" \
  > "$ULOG/client1/tcp_send.ssh.log" 2>&1 &
export U_SEND1_SSH_PID=$!

ssh "$CLIENT2_HOST" "python3 '$CLIENT2_DEMO_ROOT/tcp_send.py' \
  --source-ip 10.80.0.12 \
  --host 10.80.0.1 \
  --port 19112 \
  --input '$CLIENT2_DEMO_ROOT/client2_uplink.bin' \
  --timeout 300 \
  > '$CLIENT2_ULOG/tcp_send.log' 2>&1" \
  > "$ULOG/client2/tcp_send.ssh.log" 2>&1 &
export U_SEND2_SSH_PID=$!

U_SEND1_STATUS=0
U_SEND2_STATUS=0
U_RECV1_STATUS=0
U_RECV2_STATUS=0
wait "$U_SEND1_SSH_PID" || U_SEND1_STATUS=$?
wait "$U_SEND2_SSH_PID" || U_SEND2_STATUS=$?
wait "$U_RECV1_PID" || U_RECV1_STATUS=$?
wait "$U_RECV2_PID" || U_RECV2_STATUS=$?
if [ "$U_SEND1_STATUS" -ne 0 ] || [ "$U_SEND2_STATUS" -ne 0 ] || [ "$U_RECV1_STATUS" -ne 0 ] || [ "$U_RECV2_STATUS" -ne 0 ]; then
  echo "uplink tcp failed: send1=$U_SEND1_STATUS send2=$U_SEND2_STATUS recv1=$U_RECV1_STATUS recv2=$U_RECV2_STATUS" >&2
  false
fi
```

拉回 client 侧日志和 queue summary：

## 8. 常见失败与现场处理

### 8.1 SSH 或远端路径错误

现象：client 命令未启动、`scp` 拉不回日志、远端日志目录为空。

处理：

```bash
ssh "$CLIENT1_HOST" "pwd; test -x '$CLIENT1_PROJECT_ROOT/wfb_v6_uplink'; ls -ld '$CLIENT1_DEMO_ROOT'"
ssh "$CLIENT2_HOST" "pwd; test -x '$CLIENT2_PROJECT_ROOT/wfb_v6_uplink'; ls -ld '$CLIENT2_DEMO_ROOT'"
```

判断：

- `CLIENT*_HOST` 必须能免交互 SSH。
- `CLIENT*_PROJECT_ROOT/wfb_v6_uplink` 必须存在且可执行。
- `CLIENT*_DEMO_ROOT` 必须可写。

### 8.2 TUN 不出现

现象：`ip addr show v6us0`、远端 `ip addr show v6uc1` / `v6uc2` / `v6dc1` / `v6dc2` 找不到设备。

处理：

```bash
cat "$ULOG/server/wfb_v6_uplink.log" 2>/dev/null || true
ssh "$CLIENT1_HOST" "cat '$CLIENT1_ULOG/wfb_v6_uplink.log' 2>/dev/null || cat '$CLIENT1_DLOG/wfb_v6_uplink.log' 2>/dev/null || true"
ssh "$CLIENT2_HOST" "cat '$CLIENT2_ULOG/wfb_v6_uplink.log' 2>/dev/null || cat '$CLIENT2_DLOG/wfb_v6_uplink.log' 2>/dev/null || true"
```

重点看：

- 网卡名是否匹配当前机器。
- 网卡是否已切到 monitor 且在同一信道。
- 是否缺少 root 权限。
- 是否出现 `绑定 raw air socket 失败`。

### 8.3 上行只有一个 client 推进

处理：

```bash
grep -E '^grant seq=|ready_accept|ready_reject|GRANT_FILTER|READY_FILTER' "$ULOG/server/wfb_v6_uplink.log" | tail -n 80
grep -E 'grant_accept|authorized_sends|READY_REJECT|GRANT_FILTER' "$ULOG/client1/wfb_v6_uplink.log" | tail -n 80
grep -E 'grant_accept|authorized_sends|READY_REJECT|GRANT_FILTER' "$ULOG/client2/wfb_v6_uplink.log" | tail -n 80
```

判断：

- 如果某个 node 没有 `ready_accept`，检查该 client 的 TUN/TCP sender 是否启动。
- 如果有 `ready_reject`，必须先解释拒收原因，不能判定演示成功。
- 如果两个 client 都有 `grant_accept` 和 `authorized_sends`，但 server 只收到一个 client 的 TCP，会话问题可能在 raw-air 聚合、block index、RF 接收或 server TUN 侧回包路径，不能用单 client 成功替代双 client 结论。

### 8.4 上行速度明显过低

现象：两个 client 都在推进，但 `tcp_send.log` / `tcp_recv.log` 平均只有 `0.0x MiB/s`。

处理：

```bash
printf 'raw air: HT%s MCS%s short_gi=%s\n' "$RADIO_BANDWIDTH" "$RADIO_MCS_INDEX" "$RADIO_SHORT_GI"
printf 'client1 uplink queue: pause=%s resume=%s packets=%s\n' "$CLIENT1_UPLINK_PAUSE_THRESHOLD_BYTES" "$CLIENT1_UPLINK_RESUME_THRESHOLD_BYTES" "$CLIENT1_UPLINK_QUEUE_PACKETS_LIMIT"
printf 'client2 uplink queue: pause=%s resume=%s packets=%s\n' "$CLIENT2_UPLINK_PAUSE_THRESHOLD_BYTES" "$CLIENT2_UPLINK_RESUME_THRESHOLD_BYTES" "$CLIENT2_UPLINK_QUEUE_PACKETS_LIMIT"
grep 'RX_ANT' "$ULOG/server/wfb_v6_uplink.log" | tail -n 20
```

判断：

- 正式演示默认应为 `HT40/MCS3/short GI` 与 `131072/65536/64`；若仍按旧口径使用 `MCS0 bw=20` 或很小的 client 上行队列，速度会被人为压低。
- `RX_ANT` 若长期停在 `mcs=0 bw=20`，先确认三台机器都已同步最新 `wfb_v6_uplink` 并按本手册参数重启。
- 只有弱信号或高丢包时才统一降档到 `RADIO_MCS_INDEX=1 RADIO_BANDWIDTH=20 RADIO_SHORT_GI=0`；降档后低速属于预期。

### 8.5 下行 SHA 不一致或某个 client 没收到

处理：

```bash
cat "$DLOG/server/tcp_send_client1.log" 2>/dev/null || true
cat "$DLOG/server/tcp_send_client2.log" 2>/dev/null || true
cat "$DLOG/client1/tcp_recv.log" 2>/dev/null || true
cat "$DLOG/client2/tcp_recv.log" 2>/dev/null || true
grep -E 'feedback_window|feedback_uplink_hit|ready_|PKT|REASSEMBLY' "$DLOG/server/wfb_v6_uplink.log" | tail -n 120
```

判断：

- 如果 TCP 无法连接，先确认三台机器的 TUN IP 和 `wfb_v6_uplink` 进程仍在。
- 如果只有一个 client 收到，优先检查现场 RF 拓扑：server TX 是否能被两个 client RX 同时接收。
- 如果 `feedback_window_*` 为 0，说明下行没有覆盖反馈窗口能力，不能按完整口径通过。

### 8.6 出现旧路径污染

任何日志或命令中出现以下路径，都不能作为 v6 新底座现场演示结论：

- `wfb_rx`
- `wfb_tx`
- `wfb_token_scheduler`
- `-K ./gs.key`
- `-K ./drone.key`

本手册只允许 `wfb_v6_uplink --role server/client`。

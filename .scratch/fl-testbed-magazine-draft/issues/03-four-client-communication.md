# 03：四客户端纯通信冒烟与等量载荷准备

Status: ready-for-agent
Type: task

## 用户决定与范围

用户停止继续心跳关联分析，按fl01、fl02、fl04、fl05固定集合进入下一阶段；服务端fl00，fl06～fl10不连接或参与。保留此前寻频、迟到和供电变化证据，不将READY快照写成无故障。

## 顺序与公开接缝

1. 只读确认五节点管理身份、运行c665948及统一native SHA、实际网卡driver rtl88xxau_wfb、15W和当前射频，无活动作业。
2. 通过现有本机`/api/v1/radio/reconfigure`对完整目标[1,2,4,5]切换157/40MHz，保留索引18、下行MCS3/上行MCS4、RS(8,14)、注入15000kbps、Long GI。`calibrate`仅支持HT20，不用于本轮。普通重配不持有作业准入租约；执行前后核对无活动作业，本轮不并发启动FL任务。使用独立UFTP1144/HTTP18080；事务失败即保存事实、不绕过目标。
3. 复用已安装的`ServerRole`/`ClientRole`及其Runtime/Transport，不启动训练、聚合或评估，不改生产代码。常驻native/TUN/控制面保持运行；测试进程仅拥有自己启动的UFTP/HTTP及明确添加的组播路由。
4. 首先一次1MiB确定性文件冒烟：全四端接收并验hash后共同进入上传，服务端收齐并独立核验每份update。它不是等量载荷候选验收。
5. 确认具体CIFAR-10 ResNet-18与FP32制品格式，实测实际序列化字节数；再用等量文件筛三组。现有MNIST严格制品限制不允许直接把BN int64 buffer静默转成FP32。

## 完成和执行边界

- 主编排210秒，独立回收60秒，总预算270秒；I/O预算60秒。每个目标先prepare全通过后才启动任何测试资源。默认只打印计划，执行匹配已审查的bundle SHA；自有临时unit以225秒RuntimeMaxSec和8秒TimeoutStopSec约束子进程。
- 使用当前安装来源，不导入工作树未提交生产模块。不改变现有node_id/TUN/电源/位置/网卡组合。
- 失败或断连时关闭自有角色/进程、删除自有同一ifindex路由；不pkill、不停daemon、不新建native、不清registry。
- 传输完成、文件核验、资源回收分别记事实，不能用后处理失败覆盖已完成上传。角色关闭前消费服务端全员update结果。
- 冒烟最多先一次，阶段后报告成功、失败或明确工具阻塞；不无限重跑。若切频事务失败先停止，不直接iw逐机强改绕过事务。
- 结束后用正常重配恢复原配置及非calibration状态，显式保存读回及恢复结果。若恢复失败，单独报告，不抹除传输结果。
- 选参仍按四端全部完成、SHA256通过、无超时/最终传输失败；每个最终组连续2次等量闭环。角色功率独立控制仍是第三组实施前提。

## Comments

本票不再要求先完成心跳关联诊断或等待九客户端。现阶段只完成纯通信冒烟和载荷准备，不宣称正式FL训练已实现或验收。

# 07 — 全局 IEEE Communications Magazine 行文风格编审

**What to build:** 以工单 06 组装并通过蓝图校准的 `.scratch/fl-testbed-magazine-draft/prototypes/IEEE-Communications-Magazine中文初稿.md` 为唯一审阅对象，在同一文件上执行一次全文级发展性编辑和一次逐段语言编辑，直接产出修订后的单一权威初稿。编审目标不是再次改写各节提纲，而是消除逐节独立写作造成的重复、跳跃、术语门槛和技术报告式表达，使全文在中文阶段形成 IEEE Communications Magazine 所要求的教程式、清楚、跨专业可理解的叙事。不得只提交审查意见而不修改正文。

**Blocked by:** 06-全文组装与蓝图校准验收

**Status:** ready-for-agent

## Pass 1：全文发展性编辑

- [ ] **受众与教程性**：默认读者熟悉通信系统的一般概念，但不同时熟悉 FL、802.11 的底层无线机制、无线驱动和分布式系统实现；任何跨专业概念在承担论证职责前先用通俗机制解释
- [ ] **单一叙事主线**：全文始终围绕中心句定稿原文“本文把隐藏在 FL 抽象层下的真实无线链路变成显式的实验对象，使研究者能够主动改变无线条件并观察实际传输行为，同时通过消费级硬件降低开展这类实验的成本与门槛”推进，不出现与之竞争的第二中心主张；第 1 节使用定稿原句提出命题，其后以更短回声连接（第二次）、第 3 节和第 5 节按各自职责自然回声，不作机械复读
- [ ] **全文因果链**：五节形成“黑盒问题 → testbed 需求与载体差距 → WFB-FL 如何实现 → 实验证据如何回答问题 → 洞察、局限与开放路径”的连续推进；第 2 节的平台综合定位自然进入第 3 节的一轮多客户端 FL 运作，第 3 节体系设计自然进入第 4 节资格确认和综合实验。节间承接应有信息量，但不为衔接刻意在每个小节结尾制造悬念
- [ ] **章节去重与职责边界**：删除逐节写作造成的背景、贡献、平台优势、架构和实验设计重复；除有意设计的中心句回声外，同一事实只在最能承担论证的位置完整解释，其他位置只作必要回指
- [ ] **中心句、需求与定位分层**：中心句只提出无线链路从隐藏背景变为显式实验对象的总体命题，不直接复用或穷举三项需求名称；第 2 节再将其操作化为三项能力需求和具体平台比较维度，Table 1 后使用 spec 定稿的平台优势句收束，第 3 节解释实现机制，第 4 节承接正式证据
- [ ] **需求与平台定位**：全文稳定使用三项核心实验能力需求——关键无线参数与发送行为可控、面向多客户端的高吞吐广播分发、关键无线传输特征可独立观测；硬件成本以及部署、配置、运行复杂度作为平台比较维度但不列为第四项需求；平台优势必须使用“相比候选平台，WFB-FL 的优势不在某一项孤立能力，而在于它在同一平台中同时满足上述三项需求，并通过消费级硬件降低实验平台的搭建成本与使用门槛”这一逻辑与措辞，不得缩减为只有低成本或易用性
- [ ] **段落论法**：一般论证段落只承担一个主要判断，并按“主张 → 解释或证据 → 对全文的含义”组织；第 3 节的流程段落则以“当前参与者与传输对象 → 发生的动作 → 必要机制 → 动作结果”组织。不得以组件、协议字段、配置项或机制名称清单代替论证
- [ ] **完整轮次叙事**：第 3 节开篇用一个紧凑段落和 Figure 1 交代五层架构，随后跟随同一份模型从服务端到所有客户端、再跟随各客户端更新返回服务端并进入聚合，按“共享下行将模型送达所有客户端 → 受控上行让客户端有序回传 → 跨层完成边界闭合一轮训练”的真实执行顺序推进。每个核心段落都应让读者明确知道谁在行动、模型或更新位于何处、下一动作是什么以及产生了什么可观察结果；五层职责、控制与独立观测、发送权轮转、反压和完成边界只在流程走到相应位置时说明，不得按名称逐项罗列或集中定义
- [ ] **生动但克制**：用具体参与者、传输对象、动作、状态变化和独立观测结果建立可跟随的运行图景，避免抽象名词连续堆叠；“生动”不意味着加入拟人化修辞、虚构场景、宣传语或未经证据支持的效果判断
- [ ] **配置与动态机制边界**：正文只把信道、带宽、MCS、GI、FEC 和发射功率写成实验者可设定的无线参数，并在下行和上行实际无线收发处说明发送端设定与接收端无线观测；出站队列水位和限时发送窗口只能在受控上行中作为链路层自行维护的动态调控机制出现，不得称为可配置项、参数旋钮或实验变量；Table 2 不包含这两项
- [ ] **主张与证据对账**：引言不以编号贡献清单呈现，中心句后以验证句收束；文中任何“做了什么”的判断均由对应层的正式证据支持；设计事实、能力核验、真实硬件实验结果和待回填数据严格分级，不把开发回归、netns 验收或演示计数包装为投稿证据
- [ ] **实验性证据结构**：第 4 节使用描述性小标题，只保留 Table 2 控制与观测能力资格确认和一个 MCS 端到端综合实验，不使用 `RQ1/RQ2` 编号。资格确认不包装成研究问题；不得恢复三个典型配置档位的独立链路实验，也不得把多个参数组合成无法区分来源的档位
- [ ] **综合实验对照边界**：唯一综合实验选择两个当前硬件稳定支持且能在客户端下行接收记录和服务端上行接收记录中可靠区分的 MCS 设置，固定信道、带宽、GI、FEC、发射功率、拓扑、模型、数据划分和计算条件，并执行多次独立完整运行；结果同时核对发送端设定、客户端的下行接收记录、服务端的上行接收记录、模型分发、结果提交和轮次耗时。因果解释只针对本实验中的 MCS 对照；准确率随实际时间的进展只作辅助结果，不声称改变按轮次计的算法收敛规律或最终准确率
- [ ] **平台比较边界**：第 2 节只比较常规 Wi-Fi、低功耗蓝牙、软件定义无线电和 WFB-FL，并按三项核心能力、硬件成本以及部署、配置、运行复杂度组织 Table 1；删除逐节草稿可能带入的生态定位、相关工作区分或跨类别性能比较
- [ ] **图表嵌入论证**：每张图表在正文中先被引入，随后解释读者应观察什么，最后回收为一个明确结论；为每张图表确认唯一主要职责和“不能证明什么”，避免正文与图表相互复述
- [ ] **末节收束**：先回收正式证据支持的系统洞察，再陈述本文具体适用边界，最后把每项局限连接到一个开放路径；不在末节新增贡献、实验结果或未经验证的愿景性结论

## Pass 2：逐段语言编辑

- [ ] **中文优先与术语最小化**：可用常用中文准确表达的概念不保留生疏英文名或缩写；正文使用“低功耗蓝牙”“软件定义无线电”“联邦学习运行层”“传输适配层”，Wi-Fi 保留常用写法；全文首次使用 FL 时写“联邦学习（FL）”；实验部分不用 `RQ1/RQ2` 标签；不得裸用 `PHY/MAC`、`Runtime`、`Transport Backend`、`Wall-Clock`、`RSSI` 等增加理解成本
- [ ] **上行调度术语**：面向读者只使用“发送权轮转”“发送许可”和“限时发送窗口”，优先写成“服务端按活跃队列轮流授予发送许可”等行为句；正文不得出现 `Token Passing`、`Token` 或“令牌”。限时发送窗口只用于说明链路层约束一次发送许可的持续时间，不得写成实验者可配置参数；MCS、GI、FEC、Radiotap、monitor 模式等确有技术识别职责的术语可以保留，但首次出现时必须用一句通俗中文说明作用；UFTP 仅在需要识别实际文件分发机制时保留，首次写作“一对多文件分发协议 UFTP”
- [ ] **具体收发行为**：第 3 节直接说明 monitor 模式与 Radiotap 解析使客户端记录下行实际收到的无线帧及其元数据、服务端记录上行实际收到的无线帧及其元数据，原始帧注入使发送端发出按指定参数构造的帧；全文一般叙事使用“无线链路”“无线传输”或“无线收发”，需要精确限定时直接描述实际收到或发出的帧、无线媒介占用或发送机会，不为这些行为额外引入专业概念
- [ ] 句子主语、动作和因果关系明确；拆分过长复句、连续括注和多层名词堆叠，删除“显而易见”“众所周知”“值得注意的是”等无信息量套语
- [ ] 段首句尽量明确该段承担的主要判断，段内主语、动作和因果关系连续；相邻段之间不存在无连接的主题跳转，但不机械要求每个段尾或小节结尾都设置下一问题
- [ ] 删除空泛 roadmap、章节内容预告、元叙事和“本文将首先/然后/最后”等目录式表达；只保留携带因果信息的过渡
- [ ] 语气保持克制、技术性和非广告化；`首个`、`完全`、`彻底`、`显著`、`保证`等强措辞必须有一手依据和正式证据，否则收窄或删除
- [ ] 正文原则上不用公式；确需表达的指标优先使用文字或表格解释，不为显示学术性增加数学符号

## 全局合规与交付验收

- [ ] **图表预算裁决**：全文只保留 Figure 1–3、Table 1 和 Table 2 五项候选内容单元。Figure 1 是五层架构与完整 FL 轮次的简洁综合图，只保留五层、主要参与者和模型下行、本地训练、结果上行、聚合四个阶段；不得恢复原独立时序图，也不得增加需求标签、内部字段或密集机制注释。第 4 节不恢复独立链路实验结果图；不为占满额度增加图表，不用密集子图或缩小字号规避图与表合计最多 6 个的限制。同步核对全文编号、引用和图表清单
- [ ] **篇幅预算**：记录编审前后各节和全文的中文词数；各节围绕初始目标动态调整，第 3 节先按约 1200 词撰写，确有必要时放宽至约 1300 词；在不破坏论证链的前提下将中文正文控制在不超过 4600 词，目标约 4450 词。中文词数不能直接证明投稿合规，编审记录必须保留后续检查：英文普通稿同时满足最多 7 个双栏 magazine pages，以及标题、作者信息、摘要、正文、图表文字、图注、参考文献、作者简介等全部内容合计不超过 5500 词
- [ ] **引用预算边界**：本轮不编制参考文献列表；若正文已有引用或引用占位，只保留支撑外部事实和直接定位所必需的条目，并在编审记录中注明英文成稿参考文献最多 15 篇
- [ ] **事实保护**：风格编审不得擅自增加项目能力、实验数据、外部事实或引用；发现证据缺口时保留规范占位或收窄主张，不得用更流畅的措辞掩盖不确定性
- [ ] **自包含终稿**：原位修订 `.scratch/fl-testbed-magazine-draft/prototypes/IEEE-Communications-Magazine中文初稿.md`，清除批注、编辑标记和重复版本；最终只保留该文件作为可连续通读的权威正文
- [ ] **编审记录**：在本工单 `## Comments` 中简要记录两轮编辑完成情况、主要跨节调整、图表压缩裁决、仍待实验或英文阶段处理的事项，不把编审记录写入论文正文
- [ ] **最终通读**：以“非本项目、但具通信背景的读者”视角连续通读一遍；任一段若必须查阅项目代码或其他工单才能理解其论证，即视为未通过

## 边界

本工单负责让中文初稿在叙事、组织、解释深度和语气上达到 ComMag 教程式文章基线，同时执行可在中文阶段确认的全局合规检查。英文翻译后的句法、ComSoc 英文 copyediting、双栏排版和投稿门户字段仍需在英文成稿阶段复核，但不得以这些后续工作为由跳过本工单的中文全文编审。

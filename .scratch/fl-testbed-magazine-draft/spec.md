# IEEE Communications Magazine 中文初稿规范（第二版：两项核心需求与观测降级校准）

Status: ready-for-agent

## Problem Statement

在现有的中文初稿规范中，第 2 节将“关键无线传输特征可独立观测”与“参数可控”、“高吞吐广播”并列为三项核心实验能力需求。然而在实证检验和方案论证中，接收端通过 monitor 模式读取物理帧元数据（Radiotap 头部中的 MCS、信号强度、频率等）在技术上属于原始帧注入架构的自然伴生能力，且在实际实验中仅承担核验发送端设定是否在物理层真实生效的方法论职责，未作为独立驱动实验结论的业务能力使用。将观测过度拔高为独立的核心需求，导致论证链条出现“声称了独立核心能力但未给出独立实验发现”的逻辑薄弱点。

此外，需要严格界定“核心实验需求”（推导实验平台不可或缺的起点）、“比较维度”（横向对比候选平台的评估轴）、“平台实现机制”（架构内部设计）与“实验验证手段”（方法论核验）四者的边界，使全文论证严密、首尾贯通，并与 IEEE Communications Magazine 的教程式文体保持高度一致。

## Solution

更新中文初稿规范与论证蓝图：

1. **核心实验需求归纳为两项**：(1) 关键无线参数与发送行为可控；(2) 面向多客户端的高吞吐广播分发。
2. **观测降级为实验方法论核验手段**：帧元数据观测（monitor 模式接收捕获）作为第 4 节参数控制资格确认的物理层核验依据，支撑 Table 2 的控制可信度，不再作为第 2 节的独立核心需求。
3. **平台比较维度明确为四项**：在 Table 1 中对候选平台（常规 Wi-Fi、低功耗蓝牙、软件定义无线电、WFB-FL）按 (1) 关键无线参数可控性、(2) 高吞吐广播分发能力、(3) 硬件成本、(4) 部署与维护门槛四个维度进行系统对比。
4. **低成本与低门槛定位**：作为比较维度和实际采用决策指标，在对比矩阵与定位收束段中体现，不参与第 2 节的问题侧需求推导。
5. **多客户端有序上行定位**：作为第 3 节跨层架构中的关键实现机制展开，不上升为第 2 节的通用需求。
6. **中心句保持稳定**：“本文把隐藏在 FL 抽象层下的真实无线链路变成显式的实验对象，使研究者能够主动改变无线条件并观察实际传输行为，同时通过消费级硬件降低开展这类实验的成本与门槛。”中心句概括平台整体能力边界与愿景，不因实验使用的范围而自我削弱。
7. **全文五节论证链全面校准**：引言（黑盒困境 → 中心句 → 机制句 → 验证句）、需求与对比（两项需求 → 四维对比 → 组合优势定位）、体系机制（五层架构 → 共享下行 → 受控上行 → 轮次闭合）、实验证据（实验设置 → Table 2 控制资格确认 → 综合实验）、讨论与挑战（洞察回声 → 平台客观边界 → 开放方向）。

## Implementation Decisions

### 概念分层与边界清晰化

为杜绝概念混淆，全文统一遵守以下概念划分标准：

- **核心实验需求（2 项）**：开展真实无线 FL 实验必须满足的先决能力，缺一不可。
  1. 关键无线参数与发送行为可控（信道、带宽、MCS、GI、FEC、发射功率）。
  2. 面向多客户端的高吞吐广播分发（高物理速率、一对多广播、避免单播开销倍增与标准广播速率锁死）。
- **比较维度（4 项）**：横向评估各候选实验平台可采用性的评估轴。
  1. 关键无线参数可控性
  2. 高吞吐广播分发能力
  3. 硬件成本
  4. 部署与维护门槛
- **平台核心定位**：WFB-FL 在同一平台中同时满足两项核心实验需求，并通过消费级硬件降低搭建成本与使用门槛。
- **架构实现机制**：为在 monitor 模式与消费级硬件上达成上述能力而设计的跨层机制（如发送权轮转、反向控制窗口、出站队列水位与反压、跨层完成边界），在第 3 节随流程展开，不列为第 2 节需求。
- **实验方法论核验**：通过接收端捕获的帧元数据（Radiotap 头部信息）核验发送端设定是否在物理层真实生效，作为第 4 节 Table 2 的证据支撑，不作为独立核心能力售卖。

### 中心句与各节回声规则

- **中心句定稿**：“本文把隐藏在 FL 抽象层下的真实无线链路变成显式的实验对象，使研究者能够主动改变无线条件并观察实际传输行为，同时通过消费级硬件降低开展这类实验的成本与门槛。”
- **第 1 节**：在黑盒困境分析收束处完整提出定稿中心句，紧跟操作性解释，随后以简短回声连接命题，以一句验证句（如“本文基于消费级 802.11 硬件构建并验证了这一主张”）收束引言，不设编号贡献清单。
- **第 3 节**：开篇以中心命题的自然回声承接第 2 节定位，引出端到端轮次中跨层机制如何使无线链路显式化。
- **第 5 节**：在实验洞察开头以“真实无线链路已成为可主动改变条件、可观察实际传输行为的显式实验对象”回收中心主张，不改写成需求列表。

### 逐节结构与论证责任

#### 第 1 节 Introduction（目标约 600 词）
- 揭示联邦学习向无线边缘拓展时，主流框架将无线链路简化为黑盒管道的结构性断层。
- 展开黑盒抽象在真实无线环境下的不可解释性（无线参数差异 → 队列积压 → 传输延迟与慢节点 → 训练收敛变慢或发散）。
- 提出中心句及操作性解释（主动改变无线条件 = 显式控制无线参数与发送行为；观察实际传输行为 = 接收端记录帧元数据；成本与门槛 = 消费级硬件）。
- 交代核心机制句（802.11 monitor 模式与原始帧注入），给出简短回声和验证句，因果过渡到第 2 节。

#### 第 2 节 Testbed 需求与无线平台能力对比（目标约 800 词）
- 自顶向下推导两项核心实验需求：
  1. 关键无线参数与发送行为可控（满足实证研究中主动构造可复现无线条件的需求）。
  2. 面向多客户端的高吞吐广播分发（满足 FL 下行一对多分发大模型且不被基本速率集锁死的需求）。
- 说明硬件成本和部署维护门槛是决定实验平台能否广泛采用的现实比较维度，而非独立功能需求。
- 分析候选平台局限：常规 Wi-Fi（黑盒协议栈无物理层控制、广播速率锁死、无法逐帧观测）、低功耗蓝牙（带宽严重受限无法承载大模型分发）、软件定义无线电（成本昂贵、软硬件复杂度极高）。
- 插入 Table 1（四维度对比矩阵）。
- Table 1 后给出平台综合定位收束句，并因果过渡到第 3 节跨层实现。

#### 第 3 节 WFB-FL 跨层体系架构与端到端运作机制（目标约 1200–1300 词）
- 开篇用紧凑段落和 Figure 1 交代五层架构（算法层、运行层、传输适配层、链路控制层、无线收发层）。
- 按照一轮多客户端 FL 的真实时序展开流程叙事（模型下行 → 本地训练 → 更新上行 → 聚合）：
  1. **共享下行将模型送达所有客户端**：本轮参与集合冻结、UFTP 一对多广播分发、原始帧注入与六项无线参数设定（信道、带宽、MCS、GI、FEC、发射功率）、客户端 monitor 模式接收与 Radiotap 元数据记录、反向控制窗口回传状态、下行完成屏障。
  2. **受控上行让客户端有序回传**：客户端训练完成生成更新、上行就绪声明、服务端活跃队列管理与发送权轮转（发送许可与限时发送窗口）、控制面优先分流、固定容量队列水位与反压、服务端 monitor 模式接收与元数据记录、FEC 恢复与重组。
  3. **跨层完成边界闭合一轮训练**：逐客户端原子提交确认、期望更新集合收齐判定、移交算法层聚合。
- 严格区分可配置参数（六项无线参数）与内部动态调控机制（队列水位、调度窗口）。

#### 第 4 节 Experimental Evidence（目标约 850–950 词）
- **实验设置**：交代真实硬件（计算节点与网卡型号）、节点规模、空间布置、无线环境、FL 模型与数据集负载、固定与变化条件。插入 Figure 2（硬件布置与数据路径/采集点）。
- **无线参数控制与观测能力资格确认**：说明利用接收端 monitor 模式捕获的帧元数据核验参数控制有效性的通用方法，插入 Table 2（六项参数的发送设定、接收端核验依据、资格结论与硬件边界）。
- **不同无线工作配置下的完整 FL 运行**：定义稳健性优先、折中、吞吐优先三种预设配置（带宽、MCS、GI、FEC 组合），固定信道与发射功率等其他条件，执行多次独立完整 FL 运行。插入 Figure 3（下行吞吐、上行提交、轮次耗时分布）。以组合整体为比较单位，不归因单项参数，不映射具体设备类型。

#### 第 5 节 Discussion and Open Challenges（目标约 600 词）
- **实验洞察回声**：回扣中心主张，总结打破黑盒对 FL 真实无线传输行为理解的价值。
- **平台客观约束边界**：硬件与规模边界、不同网卡与驱动对无线参数控制与观测的支持范围差异、统计外推边界。
- **开放研究挑战**：跨设备与新频段泛化、智能化自适应无线发送调度、自动化持续集成评测床。

### 验证缝隙（Testing Seams）

本特性的唯一最高层验证缝隙为：**中文初稿正文（`IEEE-Communications-Magazine中文初稿.md`） vs 本规范（`spec.md`）的全局合规性审查**。

审查涵盖以下核心核验项：

1. **需求与定位一致性**：第 2 节是否严格推导且仅推导两项核心实验需求；Table 1 是否仅包含 4 个比较维度；Table 1 后的定位段是否准确收束为两项需求与低成本低门槛的组合优势。
2. **中心句与回声规范**：第 1 节是否完整提出定稿中心句并紧跟简短回声；第 3 节和第 5 节是否按职责自然回声；是否存在将中心句改写为需求清单的情况。
3. **主张与证据对账**：引言无编号贡献清单；第 3 节不把设计或未经验证能力包装为既有创新；第 4 节 Table 2 是否如实记录帧元数据核验依据，综合实验是否严格以配置组合为单位分析且无过度主张。
4. **流程驱动的架构叙事**：第 3 节是否以模型和更新的流转过程为主线推进；五层职责是否作为骨架而非独立小节；机制是否随流程自然引出而非集中罗列。
5. **参数与动态机制边界**：第 3 节与 Table 2 是否严格限定六项可配置参数；出站队列水位和发送窗口是否仅作为内部动态机制在受控上行中说明。
6. **图表合规性**：Figure 1–3、Table 1、Table 2 共 5 项候选单元是否齐全、位置正确、职责唯一且图表占位规范；图表总数不超过 6 个。
7. **术语与中文优先**：术语替换是否彻底（无裸用英文内部名、无令牌术语）；首次出现的专业术语是否有通俗解释。
8. **节间衔接与路线图清理**：节间过渡是否有信息量；全文无“本文结构如下”等无信息量段落。
9. **篇幅控制**：中文正文总词数在 4450 词左右且不超过 4600 词。

### 先例

本规范的验证方法继承自仓库现有的端到端文档审计与验收流程（如 `06-全文组装与蓝图校准验收.md` 与 `07-全局IEEE-Communications-Magazine行文风格编审.md`）。

## Out of Scope

- 撰写英文正文、英文摘要或 Cover Letter。
- 执行物理硬件实验或回填真实测试数值（由实验批次单独执行）。
- 绘制正式矢量图与排版渲染图表。
- 修改底层系统代码架构与通信协议实现。
- 将未实现的动态自适应调度等设想包装为当前平台已完成的贡献。

# IEEE Communications Magazine 中文初稿（第一版）

Status: ready-for-agent

## Problem Statement

fl-testbed-magazine-wayfinder 已产出完整的写作蓝图（06-0 轮廓草稿 + 06-1 终审校准），锁定了五节结构、中心句、三项贡献、三项核心实验能力需求、平台综合定位、图表职责和逐节论点。但蓝图本身是骨架级轮廓，不是可通读的连续正文。需要一份中文初稿第一版，把蓝图的每一条骨架填充为段落级连续叙事，使后续英文翻译和导师审阅可以直接在正文上操作，而不是对着提纲猜测。逐节独立撰写和结构验收还不足以保证全文形成统一的 Magazine 文体，因此组装后必须再执行一次独立的全文发展性编辑与逐段语言编辑。

## Solution

以 06-0 轮廓草稿为结构基准：工单 01–05 撰写五节中文正文，工单 06 组装到 `.scratch/fl-testbed-magazine-draft/prototypes/IEEE-Communications-Magazine中文初稿.md` 并执行蓝图合规验收，工单 07 在同一文件上执行全局 IEEE Communications Magazine 文体编审并产出单一权威修订稿。实验数据、正式图表、摘要和英文均不在本轮产出范围，相关位置保留规范性占位。历史蓝图若与本 spec 的后续裁决冲突，以本 spec 和工单 01–07 为准。

## User Stories

1. 作为论文作者，我希望第 1 节 Introduction 以连续段落呈现黑盒困境、中心句、主动改变无线条件与检查实际传输行为的通俗解释、消费级硬件带来的成本与门槛优势、monitor 模式与原始帧注入机制句和三项贡献声明，使读者读完引言即可把握全文论点与结构。
2. 作为论文作者，我希望中心句“本文把隐藏在 FL 抽象层下的真实无线链路变成显式的实验对象，使研究者能够主动改变无线条件并检查实际传输行为，同时通过消费级硬件降低开展这类实验的成本与门槛”在引言中完整提出，并在贡献声明前、第 3 节开篇和第 5 节洞察中按各自职责自然回声，使全文论证链首尾贯通而不机械复读。
3. 作为论文作者，我希望第 2 节从无线 FL 的业务流量特征与实证科学方法自顶向下推导三项核心实验能力需求：关键无线参数与发送行为可控、面向多客户端的高吞吐广播分发、关键无线传输特征可独立观测；物理层、介质访问控制层等分层术语只在技术展开确有必要时解释，不作为需求标题。
4. 作为论文作者，我希望第 2 节的平台对比叙事在 Table 1 前后形成"提出缺陷 → 表格量化 → 得出定位"的三段论证，而不是孤立地展示表格。
5. 作为论文作者，我希望第 2 节的平台比较对象限定为常规 Wi-Fi、低功耗蓝牙、软件定义无线电和 WFB-FL，不另设跨层定位或相关工作区分段，也不转向比较联邦学习框架、应用层通信协议或广域网系统。
6. 作为论文作者，我希望第 2 节明确区分需求推导与平台定位：硬件成本以及部署、配置、运行复杂度是平台比较维度而非第四项实验需求；Table 1 后使用统一的综合定位句，说明 WFB-FL 的优势来自三项能力与消费级硬件实现的组合。
7. 作为论文作者，我希望第 3 节以五层跨层架构为骨架，逐层解释核心职责与层间接口，配合 F1 占位，使读者理解 WFB-FL 的静态结构。
8. 作为论文作者，我希望第 3 节的无线收发控制部分明确区分两类对象：实验者可设定的六项无线参数（信道/频段、带宽、MCS、GI、FEC、发射功率），以及由链路层在运行过程中自行维护的出站队列水位和 Token 调度窗口；后两项不得作为可配置参数或实验旋钮呈现。
9. 作为论文作者，我希望第 3 节的独立接收侧观测清晰描述 monitor 模式接收与 Radiotap 头部解析，使读者理解关键无线传输特征如何被独立观测。
10. 作为论文作者，我希望第 3 节的端到端 FL 轮次生命周期以三阶段（下行高速广播 → 上行令牌防撞与原子上传 → 全员收齐聚合）连续叙述，配合 F2 占位，使读者理解 WFB-FL 的动态运作。
11. 作为论文作者，我希望第 4 节按“控制与观测能力核验 → 典型无线配置档位的链路实验 → 完整 FL 轮次中的端到端示范”递进组织证据，使用描述性小标题而不是 `RQ1/RQ2` 编号，并在实验数据处标注“待正式硬件实验执行后回填”。
12. 作为论文作者，我希望第 4 节的 Table 2 能力核验矩阵完整列出六项可配置无线参数（信道、带宽、MCS、GI、FEC、发射功率），对每项说明设定值、核验依据和适用边界；出站队列水位和 Token 调度窗口不进入该矩阵。
13. 作为论文作者，我希望第 4 节以典型无线配置档位组织链路实验：在 Table 2 逐参数核验的基础上，将 MCS、带宽、GI、FEC 等多项可配置无线参数组合成 3 个典型档位（信道与实验环境保持一致，发射功率按平台默认），每个档位独立重复 10 次以验证链路结果可重复；随后从该实验中选取 2 个已形成清晰链路差异的档位进入多客户端 FL 实验，固定拓扑、模型、数据与计算条件，以示范无线链路差异如何体现为模型分发、更新提交和轮次耗时的变化。因果归因以整个档位为尺度，不把差异归因到单个参数；不预设任何单个参数比其他参数更重要。
14. 作为论文作者，我希望第 5 节采用"Discussion and Open Challenges"结构，依次包含实验洞察回声、平台客观约束和三个开放研究方向，不声称未经验证的推论。
15. 作为论文作者，我希望第 5 节的平台客观约束从整体上说明不同网卡、射频芯片和驱动对各项无线参数配置与观测的支持范围，不把任何单项参数设为独立约束。
16. 作为论文作者，我希望写作阶段的七项候选图表内容（F1-F5、Table 1、Table 2）均以统一格式保留编号、标题和论证职责说明，并在全局编审时合并为不超过 6 个正式图表。
17. 作为论文作者，我希望全文在保持领域含义准确的前提下优先使用普通中文，避免用项目内部英文名、英文缩写或专业分层标签增加阅读门槛；确需保留的术语首次出现时以通俗中文解释。
18. 作为论文作者，我希望节间衔接使用有信息量的因果过渡句，而不是无信息量的 roadmap 段（如"本文余下部分组织如下"）。
19. 作为论文作者，我希望三项贡献声明以目标主张形式写成，措辞不超越当前已有的设计层与回归层证据范围，实验层证据以"待正式实验回填"标注。

## Implementation Decisions

### 权威基准与输入来源

- 结构基准：wayfinder 工单 06-0 产出的第二版轮廓草稿（`fl-testbed-magazine-wayfinder/prototypes/06-0-magazine轮廓草稿.md`）。若其历史措辞与本 effort 的后续用户裁决冲突，以本 spec 和工单 01–07 为准。
- 逐节校准指引：wayfinder 工单 06-1 的终审验收。
- 技术事实来源：`docs/联邦学习系统设计入口.md` 指向的六篇设计专题。
- 术语来源：`CONTEXT.md` 的领域词汇表。

### 中文优先与专业术语边界

- 正文优先使用中文常用表述。`BLE` 写作“低功耗蓝牙”，`SDR` 写作“软件定义无线电”；Wi-Fi 属于常用表述，保留不改。全文首次使用 `FL` 时写作“联邦学习（FL）”，后文可使用缩写。
- 实验部分使用能够直接说明证据职责的描述性小标题，不引入 `RQ1/RQ2` 编号。
- 不在面向普通读者的句子中裸用 `PHY/MAC`。确需分层时写“物理层和介质访问控制层”，否则直接描述“无线参数”“发送行为”或“无线传输”。
- 项目内部架构名与正文展示名分离：`FL Runtime / SDK` 在正文写作“联邦学习运行层”，`Transport Backend` 写作“传输适配层”；只有必须与代码、接口或设计文档对照时才在首次出现处括注内部名称。
- 全文一般叙事使用“无线链路”“无线传输”或“无线收发”。第 3 节直接说明具体行为：monitor 模式使独立接收端能够记录实际收到的无线帧及其元数据，原始帧注入使发送端能够发出按指定参数构造的帧；不再额外引入术语为无线链路中的实际收发环节命名。
- 无法合理替换且承担技术识别职责的术语可以保留，包括 MCS、GI、FEC、Token 调度窗口、Radiotap 和 monitor 模式；首次出现时用一句通俗中文说明其作用，后文使用稳定的最短名称，不反复给出英文全称。Token 调度窗口仅用于说明链路层如何动态分配和约束发送机会，不得写成实验者可配置参数。UFTP 只在需要识别实际文件分发机制时出现，首次写作“一对多文件分发协议 UFTP”。
- 专有名词和缩写只在后文确实需要复用时引入；不得为了显得专业而增加括号、英文全称、协议字段或分层标签。

### 中心句与操作性解释

- 中心句定稿：“本文把隐藏在 FL 抽象层下的真实无线链路变成显式的实验对象，使研究者能够主动改变无线条件并检查实际传输行为，同时通过消费级硬件降低开展这类实验的成本与门槛。”
- “显式的实验对象”概括无线链路从隐藏背景变为研究对象；“主动改变无线条件”和“检查实际传输行为”以普通读者可理解的语言概括控制与观测，不直接复用三项需求名称。
- “开展这类实验的成本与门槛”明确限定低成本、低门槛的对象；正文再具体解释为平台硬件投入以及部署、配置和运行要求。
- 中心句在第 1 节黑盒困境收束处使用定稿原句完整提出；贡献声明前、第 3 节开篇和第 5 节洞察按各自论证职责自然回声，不逐字重复。

### 中心句、能力需求与平台综合定位

- 中心句负责改变无线链路在实验中的地位并概括总体价值，不是三项需求的缩写或清单，也不能替代平台比较和证据。
- 三项核心实验能力需求定稿为：关键无线参数与发送行为可控、面向多客户端的高吞吐广播分发、关键无线传输特征可独立观测。
- 三项需求从无线 FL 的业务流量特征与实证科学方法自顶向下推导：“主动改变无线条件”由第一项具体化，“检查实际传输行为”由第三项具体化；第二项则由无线 FL 的一对多模型分发特征独立推导，不要求逐字进入中心句。
- `PHY/MAC`、`物理广播`和`帧级观测`仅用于能力展开时确有必要的技术定位，不作为面向普通读者的能力名称；正文按“中文优先与专业术语边界”执行。
- 硬件成本以及部署、配置、运行复杂度是平台比较维度，不列为第四项实验需求；中心句可以概括其总体价值，Table 1 必须用具体维度支撑。
- 平台优势定稿为：“相比候选平台，WFB-FL 的优势不在某一项孤立能力，而在于它在同一平台中同时满足上述三项需求，并通过消费级硬件降低实验平台的搭建成本与使用门槛。”
- 第 2 节只比较 Table 1 中的四类真实无线平台：常规 Wi-Fi、低功耗蓝牙、软件定义无线电和 WFB-FL。平台优势句由 Table 1 后的综合定位段提出，随后直接过渡到第 3 节机制；第 3 节解释实现机制，第 4 节提供正式证据。正文不另设生态定位或相关工作区分段。

### 三项贡献

1. 可控的真实无线广播与消费级硬件上的低成本实现。
2. WFB-FL 跨层实验平台与端到端可靠性契约。
3. 真实硬件上的代表性实验洞察。
- 措辞不超越当前证据范围；贡献 3 的证据以"待正式实验回填"标注。

### 可配置参数与动态调控机制

- 第 3 节明确列出实验者可设定的六项无线参数：信道、带宽、MCS、GI、FEC 和发射功率。
- 出站队列水位和 Token 调度窗口属于链路层在运行过程中自行维护的动态调控机制：前者用于根据积压状态实施停读、恢复和反压，后者用于分配和约束发送机会。二者不得与六项无线参数并列为可配置项或实验旋钮。
- 第 4 节 Table 2 核验矩阵只包含上述六项可配置无线参数，所有参数行格式一致且无特殊标注。
- 第 5 节从整体上讨论不同网卡、射频芯片和驱动对无线参数配置与观测的支持范围，不把任何单项参数设为独立约束。

### 实验性证据的递进关系

- 能力核验是平台声明可信的前提，不称为研究问题：Table 2 对六项可配置无线参数逐项记录发送端设定、独立接收端或系统记录提供的核验依据，以及当前硬件和驱动边界。
- 链路实验不预设任何单个参数比其他更重要。Table 2 完成六项参数的逐项核验后，链路实验将多项可配置无线参数组合为 3 个典型配置档位（信道与实验环境保持一致，每档重复 10 次），以中位数和四分位距报告链路结果分布，证明研究者可整体设定一组无线条件并获得可重复的链路观测；本实验不回答“差异由哪个参数引起”。
- 端到端 FL 实验从链路实验中选择 2 个已形成清晰差异的档位，固定拓扑、模型、数据划分和计算条件，对每档执行多次独立完整运行。因果归因以档位整体为尺度；结果只展示无线配置差异如何体现为链路、分发、提交与整轮耗时的变化，不把差异归因到单个参数。
- 准确率随实际运行时间的曲线只用于展示系统时间差异如何改变单位时间内的训练进展，不得据此声称无线设置改变了按轮次计的算法收敛规律、最终准确率或算法本身。

## Testing Decisions

### 什么是好的验证

好的验证只检查初稿的外部可观察属性（结构完整性、术语一致性、蓝图合规性），不检查散文风格或英文可译性等主观属性。

### 验证缝隙：中文初稿正文 vs 蓝图校准指引

唯一验证缝隙：对照 06-1 终审校准指引和本 spec 的 Implementation Decisions，逐项审查初稿正文。

检查清单：

1. **结构完整性**：五节是否齐全，每节标题与蓝图一致，节内小节结构与蓝图对应。
2. **中心句职责与措辞**：第 1 节黑盒收束处使用定稿原句完整提出，贡献前、第 3 节和第 5 节按各自职责自然回声；任何位置都不得把中心句改写成三项需求清单。
3. **需求与平台定位正确性**：三项核心实验能力需求齐全且推导逻辑完整；硬件成本以及部署、配置、运行复杂度作为比较维度而非第四项需求；Table 1 及表后综合段把三项能力与这些实现条件共同收束为 WFB-FL 的组合优势。
4. **三贡献声明**：措辞与蓝图一致，不越界。
5. **候选图表内容**：七项候选内容单元全部出现在正确位置、格式统一，并留待工单 07 合并为不超过 6 个正式图表。
6. **配置与动态调控边界**：第 3 节只把信道、带宽、MCS、GI、FEC 和发射功率列为实验者可设定的无线参数，并把出站队列水位和 Token 调度窗口说明为链路层动态机制；第 4 节 Table 2 核验矩阵只包含六项可配置无线参数；第 5 节不把任何单项无线参数设为独立约束。
7. **术语与可读性**：检查领域含义是否遵守 CONTEXT.md，同时检查可中文化的英文词和缩写是否已替换、必要术语是否在首次出现时解释，以及正文是否直接描述具体无线收发行为而未增加无助于论证的专业概念。
8. **节间衔接**：每个节间过渡句有信息量，无 roadmap 段。
9. **篇幅**：各节信息配比与蓝图目标大致一致；工单 06 组装稿记录各节及全文词数，工单 07 编审后的中文正文不超过 4600 词。英文成稿另按 ComMag 5500 词总量口径核算。
10. **实验设计与过度主张**：第 4 节按能力核验、链路实验、端到端 FL 实验递进；链路实验使用由多项无线参数组合的典型配置档位并独立重复，端到端实验从其中选择 2 个已确认档位且固定拓扑、模型、数据与计算条件，归因以档位整体为尺度；不出现未经验证的因果越级、证据越界、算法收益或未完成能力包装。

### 验证缝隙：逐节合格与全文 Magazine 文体之间

工单 06 的十项检查只验证结构与蓝图合规，不能证明五节组装后具备统一的教程式行文。工单 07 必须以完整初稿为对象，先执行全文发展性编辑，再执行逐段语言编辑，并直接修改交付正文。验收至少覆盖：跨专业读者可理解性、单一中心主线、节间因果链、章节去重、`主张 → 机制 → 证据 → 含义`段落论法、术语与缩写首次解释、贡献和证据对账、图表嵌入论证、克制的非广告语气，以及`洞察 → 局限 → 开放路径`的末节收束。只提交审查报告而未形成单一权威修订稿，视为未完成。

### 先例

wayfinder 工单 06-1 本身就是对 06-0 草稿的逐节校准验收，方法完全相同。本 spec 的验证只是把同样的校准方法应用于正文级初稿。

## Out of Scope

- 撰写英文正文、英文摘要或 cover letter。
- 执行正式硬件实验或回填实验数据。
- 绘制正式图表（F1-F5）。
- 修改系统设计或实现以迎合文章叙事。
- 将尚未完成的能力包装成平台现有贡献。
- 标题候选与最终英文措辞的确定。
- 参考文献列表的编制。

## Further Notes

- 本 effort 的输入完全来自 `fl-testbed-magazine-wayfinder` 的已结单产出，不重新打开该 wayfinder 的任何工单。
- 中文简版初稿（`fl-testbed-magazine-wayfinder/prototypes/WFB-FL中文简版初稿.md`）可作为写作参考，但其需求分类和部分措辞已过时，以本 spec 的“三项核心实验能力需求 → 平台比较 → 综合定位”裁决为准。
- 初稿经工单 06 组装验收后，必须再由工单 07 完成全局 Magazine 文体编审；只有 07 产出的单一权威修订稿才可交付导师审阅。

# IEEE Communications Magazine 实验方案执行计划

## 1. 实验总体定位与目标

本实验服务于论文《面向真实物理无线链路的联邦学习实验平台设计与性能评估》第 4 节（真实硬件实验与结果评估）。

核心目标是：**在参与节点、空间物理拓扑、任务模型、数据划分和训练条件保持一致的前提下，通过无线参数模拟手机可能遇到的通信条件，评估其对模型分发、客户端更新回传和完整联邦学习轮次耗时的影响。**

实验分为两个阶段：

1. **纯通信预实验**：使用与正式模型等量的文件，筛选三组合理、能够完成全部节点通信的无线配置。选参只依据通信可靠性和通信耗时，不运行训练、聚合或模型评估。
2. **正式 FL 实验**：冻结三组配置后，执行真实 CIFAR-10 / ResNet-18 多轮同步 FedAvg，评估通信与系统性能。

本实验不以证明算法收敛精度提升为目的，也不预设哪组配置一定最快或三组之间必须出现明显差距。手机情境由无线参数限制表达，不移动客户端，也不将其解释为对真实手机硬件、功耗或蜂窝网络的完整复现。

### 2.2 节点筛查流水线

1. **基础盘点**：核验主机身份、系统环境、磁盘、GPU、供电与温度状态。
2. **无线硬件校验**：核验网卡识别、驱动加载、monitor 模式与 injection 能力。
3. **统一版本部署**：部署同一发布版本，记录版本和配置。
4. **基础通信冒烟**：排查天线、供电、驱动和基础通信故障。
5. **锁定参与集合**：当前批次按用户授权排除fl04，固定 $\mathcal{S}_{\text{formal}}=\{1,2,3,5,6,7,8,9,10\}$、$N=9$；通信候选必须在同一九客户端集合验收，不为某组完成而临时跳过其他弱节点。

不因节点在较高 MCS 下表现差而将其剔除；保留真实弱链路，并在固定参与集合上选择可行参数。论文按实际数量 $N$ 呈现。正式采样期间若硬件故障导致参与集合变化，应重新验收并开启新批次。

## 3. 正式实验的学习任务与控制条件

### 3.1 任务、模型与载荷

- **任务**：CIFAR-10 图像分类。
- **模型**：CIFAR版ResNet-18，复用torchvision BasicBlock `[2,2,2,2]`，3×3/stride1输入卷积、无初始maxpool、十分类；11,173,962个可训练参数。浮点权重及buffer为CPU FP32，保留20个BN int64计数，完整state_dict交换；格式`cifar10-resnet18-fp32-v1`。初始化和严格制品接口见`wfb_ng/fl/cifar10_model.py`及`docs/deployment/CIFAR10参考初始模型.md`。
- **载荷核验**：已用seed7生成初始制品，实测**44,770,302字节**（含序列化开销），SHA-256及软件版本见`evidence/model-sized-four-20261106T173222Z/model-manifest.json`；原始张量为44,734,408字节。约44.7MB只作早期预算，不等同于40MiB。本轮下行和原样上传该真实文件；正式训练update的附加算法元数据及实际字节数仍须在训练入口实现时另外核验，不能将本次原样上传称为已验证真实update。
- **真实训练**：正式实验交换实际模型与更新文件；纯通信预实验使用等量文件。

通信耗时占比、训练耗时和三组性能排序均为待测结果，不预设通信占比为 70%～85%。

### 3.2 数据划分与本地计算

- **数据集**：CIFAR-10 的 50,000 张训练图像与 10,000 张独立测试图像。
- **划分**：对固定的 $N$ 个客户端进行分层 IID 划分，各节点样本数量尽量相等，完整记录不能整除时的分配结果。
- **本地训练**：每轮在 GPU 上训练 1 epoch，batch size 为 64。
- **数据预置**：数据集通过管理平面预置，不通过实验无线链路传输原始图像。
- **组间一致性**：使用相同数据分区和初始模型；各组对应的重复任务使用相同随机种子序列，每项任务重新初始化模型。

正式开测前核实 GPU、依赖、真实训练入口以及训练、聚合和评估耗时；这些检查不参与无线选参。若节点无法承载既定负载，暂停并解决或重新讨论负载，不在组间改变训练条件。记录温度与计算耗时等因素，不将所有轮次差异直接归因于无线。

## 4. 三组手机通信情境与参数设计

### 4.1 设计原则与固定条件

节点位置和参与集合保持一致。采用共同基准，每次引入一种通信限制；必要的适配调整显式记录。

- **工作信道**：正式实验目标固定为 Ch 157；40 MHz 使用 HT40+，辅信道为 Ch 161。开测前核验当地监管及硬件支持，三组不以切换信道制造差异。当前故障诊断及本轮软件发布继续使用 Ch 149、HT40+，其观察结果不能当作 Ch 157 的验收；正式选参前须明确切换并重新读回、验收。
- **保护间隔**：统一固定 Long GI（800 ns），不作为可配置参数或实验变量。代码a63037a已随c665948发布至当前六在线目标，native只读GET_RADIO均返回short_gi=0，且启动参数不含Short GI标志。此前因fl04不可达中止的五目标批次保留历史记录；未发布的断电节点恢复后仍须补发和实读核验。
- **FEC**：当前筛选基线为RS(8,14)，同时比较RS(8,12)；每次切组须全部当前参与native统一冷启动并实读GET_FEC。最终正式实验的三种手机情境共用经全九端筛选和连续两次模型闭环验收的同一FEC，不能预先把尚未完成的8/12标为入选。RS(8,14)每8个数据分片附加6个校验分片，校验占总分片约43%，相对数据额外开销75%；RS(8,12)则附加4个，分别约33%和50%。
- **MCS 与注入速率**：遵守平台、驱动及带宽对应的合法范围；上下行 MCS 分别记录。
- **UFTP 注入速率**：仅约束下行发送，不将其等同于上行限速或真实网络拥塞。
- **传输与调度**：三组使用相同协议、调度机制与其他固定参数。

### 4.2 三组配置的含义与对照关系

| 组别 | 手机通信情境 | 相对共同基准的变化 | 解释边界 |
| :--- | :--- | :--- | :--- |
| 1. 无明显资源限制 | 当前条件下可用无线资源较充足 | 从通过通信可靠性筛选的 40 MHz 候选中，根据通信闭环耗时中位数选择基准 | 只代表当前拓扑下的实测基准，不代表理想信道或理论上限 |
| 2. 可用带宽受限 | 可用无线带宽减少 | 从 40 MHz 收窄至 20 MHz，并匹配合法的下行注入速率；优先保持功率及上下行 MCS 一致 | 模拟可用带宽减少，不声称复现真实竞争流量或网络拥塞 |
| 3. 终端上行发射能力受限 | 终端因功率或热约束等原因降低发射能力 | 保持基准带宽、服务端功率及下行参数，降低客户端发射功率；所有客户端使用同一功率 | 模拟终端上行链路预算受限，不据此推导手机整机能耗或节电效果 |

带宽受限组若无法可靠完成，允许调整 MCS 并记录为情境下的适配措施。终端上行受限组在基准之下逐档降低客户端驱动功率索引，具体档位由通信预实验确定，选择通过可靠性验收的受限配置；必要时调整上行 MCS 并记录。

功率依据 [svpcom/rtl8812au v5.2.20 驱动 README](https://github.com/svpcom/rtl8812au/blob/v5.2.20/README.md)：固定索引范围为 1..63，索引18使用 `iw dev <专用接口> set txpower fixed -1800`。该索引不能直接换算为标准 dBm；未经标定不得将索引变化解释为 3 dB 或 6 dB 的物理降幅。

板级功耗由 Jetson `nvpmodel` 单独管理，与网卡发射索引无关。用户已最终澄清：25W、40W指板级功耗，网卡目标为**驱动功率索引18**。10台已核验官方Orin Nano配置的15W（`nvpmodel_p3767_0003_super.conf`，mode 0）、CPU/GPU/EMC上限及功耗服务成功；fl00/fl04禁用jtop并重启后完整生效，EMC均未锁频，详见`evidence/board-power/15w-20261106T090049Z/README.md`。不能把错误SKU旧模式名称当成有效限制证据。

本轮已发布六节点的启动参数固定索引18，重启后仍读回18；断电节点恢复后须补发和读回，不能宣称全部九客户端已处于同一当前运行基线。物理dBm仍未经标定，本实验按驱动索引记录。索引14、25及误解纠正过程保留为历史证据，不作为当前目标。

三组不再使用“稳健优先、均衡折中、吞吐优先”的性能档位定义，不预设上行完全无丢包、均衡组最快或高吞吐组必须出现超时。

### 4.3 角色功率独立配置的实施前提

当前平台设计中发射功率为全网统一值，尚不能直接表达第三组要求。执行前需实现并验证：

- 服务端与客户端按角色分别配置发射功率，所有客户端仍使用同一功率。
- 将角色功率纳入现有配置下发、参数核验和节点审计流程。
- 核验实际生效值，保持第三组服务端功率与基准一致。

不能通过全网同时降功率替代第三组，否则会同时改变下行链路条件。

## 5. 纯通信预实验与选参

### 5.1 单次通信闭环

0. 先以明确标记的小文件完成基础通信冒烟；它只确认工具与端到端流程，不能算作等量载荷选参或最终验收。
1. 选参及最终验收使用与正式模型实际序列化字节数一致的文件。
2. 服务端使用正式下行协议向全部固定客户端分发，确认全部接收并通过完整性校验。
3. 所有客户端接收完成后，统一进入上传阶段，各自上传一份等量文件，使用正式上行协议与调度机制。
4. 服务端确认全部文件收齐并通过完整性校验，记录通信闭环完成。

预实验不运行本地训练、FedAvg 聚合或模型评估。统一进入上传阶段用于提供一致的上行竞争条件；正式 FL 中训练完成时间差异造成的提交时序另行观察。

### 5.2 筛选依据与最终验收

- **可靠性门槛**：全部固定客户端收发完成、完整性校验通过，无超时、传输最终失败或缺失文件。
- **允许的恢复机制**：正常 FEC 纠错和协议重传允许发生，并记录相应指标；不要求空口零丢包或协议零重传。
- **性能依据**：通信闭环耗时（分发开始到全部上传文件收齐）、分发耗时、全部上传完成耗时与客户端长尾。共同基准按合格候选的通信闭环耗时中位数选择。
- **筛选过程**：先以少量纯通信闭环淘汰不合格候选，再对拟入选的三组参数进行最终验收。不使用训练时间、模型精度或完整 FL 轮次耗时排名选参。
- **最终验收规模**：每组最终配置连续通过 **2 次纯通信闭环**。每次均满足全部节点完成、校验通过且无超时或最终传输失败。
- **证据限制**：2 次成功用于确认配置可执行，不解释为已证明长期可靠或失败概率为零。

预实验全部候选参数、成功与失败记录均保留。配置调整后重新验收。三组均须通过验收，不为制造性能差异而选择不可靠配置。

## 6. 正式 FL 实验执行

### 6.1 前置条件与配置冻结

正式采样前完成：

1. 固定节点集合、位置、数据分区、软件版本、初始模型和随机种子序列。
2. 完成角色功率独立配置能力，并核验三组参数实际生效。
3. 三组各通过连续 2 次纯通信闭环验收。
4. 完成真实训练准备检查，实测准备、训练、聚合和评估耗时，冻结超时预算与指标计时边界。

配置冻结后不在正式任务中自动调整无线参数。

### 6.2 批处理规模与顺序

- 每项任务执行 **5 轮真实同步 FedAvg**。
- 每组配置执行 **10 次独立任务**，每组 50 轮，合计 30 次任务、150 轮。
- 分为 10 个执行区组，每个区组各执行三组配置一次，组内顺序提前随机确定并保存。
- 每次任务重置初始模型，按既定序列设置随机种子，核验射频参数、服务健康、作业资源释放和待命状态。
- 预实验与正式实验数据分开保存，预实验数据不混入正式统计。

### 6.3 超时预算与异常处理

准备期限、单次 I/O 期限和完整轮次期限分别配置，根据通信测量及真实训练准备阶段的实测耗时确定，为最慢合格配置保留明确余量，三组使用相同预算。完整轮次预算覆盖模型发布、训练、上传、聚合、评估及必要确认。替换原先未经实测的“上行 180 秒”设定。

超时预算在正式采样前冻结，不能在采样过程中为某组临时延长，也不能用无限等待代替可靠性要求。

正式采样发生超时、传输最终失败、校验失败、缺少客户端更新或作业失败时：

1. 暂停该批次，保存失败任务、参数、日志和遥测记录。
2. 安全终止相关任务，核实资源恢复待命后排查。
3. 若调整无线参数或参与节点集合，重新执行通信验收并开启新批次。
4. 不静默删除失败任务，不以补跑成功样本覆盖失败事实。

三组完整完成任务是实验执行要求；未来运行仍可能出现意外故障，实际失败必须如实披露。

## 7. 统计、指标与产物

### 7.1 核心指标

Figure 4 保留三类核心证据：

1. **模型下行分发**：实际模型文件字节数、分发耗时和有效吞吐。
2. **客户端更新回传**：各客户端提交完成时序、首个／中位／最后完成时间及长尾分布。
3. **完整轮次与任务结果**：轮次端到端耗时、任务完成情况，以及实际发生的失败与恢复记录。

同时记录训练、聚合、评估等计算耗时及必要的链路遥测，用于解释通信与计算各自的影响。预实验通信闭环耗时与正式 FL 轮次耗时分别统计。

各指标的开始、结束事件及跨节点时钟处理方式须在正式采样前核验并冻结，避免混用训练完成、开始提交、服务端收齐和整轮完成等边界。

### 7.2 统计与归档原则

- 以任务作为独立重复，保留任务内轮次关联；不将同一任务中的 5 轮视为完全独立重复。
- 报告中位数、四分位距及轮次分布，保留每项任务和每个客户端的原始记录。
- 归档节点清单与位置、软件版本、数据分区、随机种子、模型及更新字节数、实际射频参数、超时设置、执行顺序、完整性结果和日志。
- 三组结论限于当前固定拓扑与负载下的通信情境对比。多参数发生适配调整时，不将结果归因为单个参数的独立因果效应。
- 不以预期排序作为结果正确性的判断标准，不隐去失败或性能接近的结果。

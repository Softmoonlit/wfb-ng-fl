## 测量与验证方法

复用既有AF_PACKET TUN被动采集逻辑，仅监听八客户端，使用客户端同机`monotonic_ns`计算旁路请求至回执时长；按node、boot、session、请求timestamp、信道以及反向IP/端口匹配confirmed=true ACK，重复包另计。schema3区分及时、晚到、未配对、挑战及窗口末端右删失，并同时给出已配对样本和完整请求窗口两种分母。服务端应答耗时不作为client RTT，不跨主机比较单调时钟。副本仅采集，无协议、门限或射频改动。

初始loopback因无权限失败及最初包装路径错误保留为工具错误；随后sudo动态loopback、SIGTERM正常收尾、方向/身份/重复/边界/分母合成回归通过。见loopback、regression相应原始结果。最新采集器支持准确停止并输出结果，最长采集1500秒。

**旁路ACK不是应用接受证明。** 230 ms从应用sendto前起算，10秒anchor是最近一次有效确认对应请求的发送时间；抓包时刻与应用接收时刻有差别。按时配对仅称候选，不能把wire ACK gap直接当应用活性anchor。当前窗口journal没有有效条目，不能把无日志解释为已证明无HUNTING。

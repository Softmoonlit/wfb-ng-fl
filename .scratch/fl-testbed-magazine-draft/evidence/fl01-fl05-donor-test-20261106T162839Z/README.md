## 只读代码核查

native FEC定时flush为2ms，普通grant/guard默认120/10ms；active grant队列由READY动态加入。源码没有可直接解释本次约190ms基础RTT的固定周期，不能由配置客户端总数推算活跃队列或给出确定归因。本轮未据此实施新的软件修改。

## 结论边界

本轮fl01/fl05的确认比例与寻频表现改善，仍有少量超过230ms的尾延迟；同时fl02/fl04出现新寻频，故现象不能解释为仅两块原卡故障。还发生了fl05电源及主机启动变化、fl06退出（五客户端变四客户端），不构成严格单变量硬件因果对照。天线组合没有独立测量，不能据此认定原网卡芯片损坏或排除供电/负载因素。

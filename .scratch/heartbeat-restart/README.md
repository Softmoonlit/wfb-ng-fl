# 心跳跨重启修复与验证

## 结论

修复了客户端主机重启后本机单调时间回退，服务端仍回复ACK却将新心跳全部判为旧报文的问题。该问题解释了原卡反向测试中“19/19请求收到ACK、服务端24/24 OFFLINE”的矛盾；不代表所有心跳尾延迟或无线丢包已经解决。

客户端每次控制面实例使用独立boot_id；服务端通过HMAC无状态挑战完成往返确认，挑战绑定当前接纳会话、候选boot_id、请求时间戳、来源端点与信道。确认后先CONNECTING，后续IDLE才READY。同会话仍严格拒绝乱序/重复值更新活性；旧启动报文不能覆盖新会话。ACK绑定boot、session、request、channel及确认状态。协议不保留旧报文兼容路径。

使用Python标准库hmac/hashlib/os，不新增依赖、不持久化计数器、不保存历史UUID集合。HMAC确认往返、隔离迟到报文，不提供客户端认证。230ms单次预算和10秒失活门限保持原约束。

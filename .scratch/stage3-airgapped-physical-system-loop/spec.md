# Stage 3: 真实断网物理全流程系统闭环测试

## Problem Statement

在完成了 Stage 1 底层射频极限攻坚（双 40 MiB 两轮并发验收）以及 Stage 2 脱离 SSH 的核心协同引擎与常驻守护服务后，系统所有通信和自愈协议已具备带内自治能力。然而，现有的所有自动化验收脚本均运行在操作者通过以太网管理网（SSH）连接集群的环境下。

在真正的断网物理环境或外场演示中，三台机器之间不存在任何有线以太网，Server 无法通过 SSH 连入 Client 1 与 Client 2。如果真实拔掉以太网线，可能会暴露以下未在隔离单元测试中出现的物理现实隐患：
1. 双端守护服务（`wfb-fl-server-daemon` 与 `wfb-fl-client-daemon`）在操作系统冷启动后是否真能无外网自主完成网卡 Monitor 模式配置与 TUN 绑定；
2. 纯无线电空口环境下，UDP 控制信令与 40 MiB 大文件（UFTP 下行与 HTTP PUT 上行）高密度并发交织时，是否会发生空口拥塞或信令被压制超时；
3. 真实物理射频切换时，若某节点受突发强干扰掉队，15 秒租约看门狗是否真能在无外部干预下触发物理网卡回滚至 Channel 157；
4. 仿真多轮运行完毕后，各节点本地日志和进程池是否能在无 SSH 审计脚本介入下自主维持洁净无泄漏。

因此，Stage 3 必须彻底拔掉三台物理机之间的以太网线并禁用 SSH，执行纯物理无线空口环境下的全流程联邦学习两轮 40 MiB 并发验收。

## Solution

1. **纯物理断网环境搭建与 SSH 禁用隔离**：
   在三台物理机（Server、Client 1、Client 2）上禁用以太网接口或拔除网线，完全切断带外 SSH 通道。操作者仅在 Server 机器本地终端（或物理显示屏）通过 `wfb-fl-core` CLI 触发仿真作业。

2. **端到端带内自治流程全量验证**：
   - 三台机器开机后，常驻守护进程自主完成硬件扫描、TUN 网卡建立与基准 Channel 157 汇合；
   - Server 协同守护引擎在后台通过 UDP 心跳自主建立包含 Node 1 与 Node 2 的全局拓扑视界；
   - 操作者在 Server 本地发起两轮 40 MiB 并发仿真作业；
   - 验证 Server 通过下行 UDP 广播任务宣告唤醒客户端沙箱；
   - 验证 40 MiB 全局模型通过 UFTP 组播高速交付两台客户端；
   - 验证两台客户端执行本地梯度更新，并通过 HTTP PUT 成功实现自然并发上传；
   - 验证 Server 协同调度器根据设定的协同范式（`sync` 与 `semi_async`）严格收集更新、执行聚合并推进下一轮；
   - 验证两轮作业完成后，双端子进程干净退出，临时目录回收，系统平稳回退至待命状态。

3. **真实断网抗干扰与看门狗自愈演练**：
   在无网络环境下，通过物理屏蔽或软件制造突发丢包，演练信道切换失败场景，验证 15 秒租约看门狗能否让受阻客户端与服务端整齐自愈回退至基准信道 157，杜绝信道脑裂。

4. **离线黑盒可审计性归档**：
   在断网测试完成后重新接驳网络或通过本地 U 盘提取各节点带内审计日志，验证所有节点的状态机跃迁、心跳记录、传输区间与丢包遥测 100% 严丝合缝。

## User Stories

1. 作为 现场演练指挥官，我希望在拔掉所有机器网线并关闭 SSH 的纯断网物理环境下，系统能够完全依赖 WFB 无线电空口完成全套联邦学习训练，以证明平台具备野外实战自治能力。
2. 作为 仿真操作者，我希望只需在 Server 本地终端敲下一行 `wfb-fl-core run`，整个三机集群就能自动被唤醒并协同推进，无需我跑去每台 Client 机器上敲命令。
3. 作为 现场测试员，我希望在断网前开机时，两台 Client 机器的守护进程能自动点亮 Monitor 模式并向 Server 发送心跳，以便 Server 瞬间感知全网在线。
4. 作为 现场操作者，我希望在断网两轮 40 MiB 训练中，UFTP 下行与 HTTP PUT 上行仍能维持与 Stage 1 一致的高吞吐与低丢包表现，证明控制信令与数据流互不干扰。
5. 作为 质量审计人员，我希望两轮 40 MiB 双客户端并发训练在无网络环境下依然能在 400 秒硬时限内全部完成，且单次 I/O 无任何停滞超时。
6. 作为 混沌工程测试员，我希望在断网状态下演练信道重配失败时，孤立的 Client 能在 15 秒看门狗超时后自主将物理网卡切回 Channel 157，以便恢复集群通讯。
7. 作为 审计人员，我希望测试完成后提取的本地日志中，每个节点的心跳时间戳、任务状态机与分源丢包遥测都能精确交叉印证。

## Implementation Decisions

- **物理断网前置配置与执行流**：
  - 物理隔离：通过 `ip link set dev <eth_dev> down` 或物理拔线禁用三台机器的管理以太网；
  - 触发方式：在 Server 物理机本地终端，执行 `wfb-fl-core run --config job_physical_airgap.json`；
  - 作业载荷：标准两轮、双 Client（Node 1 与 Node 2）并发、40 MiB（41,943,040 字节）大模型与更新，FEC 8/14，`standard` 预设（MCS 3，HT40+）。
- **验收门禁矩阵**：
  - 门禁 1：纯空口心跳拓扑建立成功（Server 本地 IPC 查询显示 Node 1 与 Node 2 在线 `IDLE`）；
  - 门禁 2：两轮 40 MiB 并发 FL 闭环在断网状态下跑通，耗时不超过 400 秒；
  - 门禁 3：分源遥测无偏离，残余丢包率控制在 1%~2% 内；
  - 门禁 4：故意阻断信道切换时，触发 15 秒租约看门狗回滚，全网在 20 秒内重新在 157 信道成功恢复心跳对齐；
  - 门禁 5：任务结束后三台物理机均无孤儿 Python/C++ 进程残留，TUN 设备安全恢复。

## Testing Decisions

- **测试设计原则 (Seams at the highest level)**：
  - 端到端物理真实硬件级集成测试；
  - 以前台 CLI 提交、后台守护进程协同、无线空口传输与离线日志提取比对为最高接缝。
- **核心测试接缝**：
  - 断网冷启动全自动组网接缝；
  - 无 SSH 两轮 40 MiB 算法作业闭环接缝；
  - 物理断网信道切换异常与看门狗自愈回退接缝。
- **既有实现借鉴 (Prior Art)**：
  - 继承 `tests/real_hardware/issue41_fl_runtime_loop.sh` 沉淀的 2-round 40 MiB 并发模型与不可篡改归档校验；
  - 继承 `tests/real_hardware/issue41_validate_archive.py` 的严格五分区校验标准。

## Out of Scope

- 浏览器 Web 控制面板交互（由 Stage 4 承接）；
- 多于 2 台客户端的大规模压力极限测试；
- 动态自适应跳频（已由 ADR-0011 彻底否决）。

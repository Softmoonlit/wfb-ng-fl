# 定义文件仿真作业运行契约

## Question

首版保留从用户电脑经 Web 和管理网上传初始模型到 Server 模型库的正常操作流程，以大文件代替模型和 update，直接跳过训练与聚合。平台应如何复用现有 Coordinator、Runtime、Transport 和 Client RoleService，定义同步闭环的固定次数推进、文件关联与校验、失败和急停边界？算法插件运行契约延期，不在本票设计。

## Comments

### 第一轮范围澄清

用户确认：

- 不承诺跨轮插件内存状态；后续若保留算法调用，其输入必须显式表达所需状态。
- 首版不考虑具体 FL 训练与聚合流程，也不验收训练或聚合效果；运行过程中直接跳过训练和聚合，以大文件代替模型和 update，验证下发与上传。
- 正常完成采用平台配置的固定次数，不提供算法收敛触发的提前结束。

第二项是首版运行范围的澄清，不应解释为仍须交付可执行训练与聚合插件。

### 第二轮已确认范围

用户确认采用文件闭环，并将算法插件机制延期：

- 用户通过 Web 经管理网上传初始模型文件到 Server 模型库，随后选择文件启动作业。
- Server 经无线数据面向目标 Clients 分发所选文件。
- Clients 跳过训练，以收到的文件作为本次 update 上传。
- Server 收集 update 后跳过聚合，继续使用同一模型文件执行下一次下发。
- 达到配置次数后正常完成；保留完整性校验、状态观察、恢复和急停要求。
- 首版不交付插件注册、插件选择、训练参数 Schema 或全节点插件一致性门禁；真实算法插件另立后续工作。

本票改名为「定义文件仿真作业运行契约」，文件路径保持不变以维持 tracker 引用。

### 第三轮已确认协同范围

用户确认首版只支持同步文件闭环：每轮向全部目标 Clients 下发，收齐全部有效 update 后才推进下一轮。固定次数表示完整同步轮次的数量；全部轮次完成才正常完成作业。

半异步、异步模式及其跨轮迟到 update 处理不进入首版 Web 文件仿真作业或验收范围。此结论不把已有 Coordinator 模式分支视为首版必须交付的能力，也不要求在本次规划中修改现有实现。

### 第四轮已确认失败与制品策略

用户确认：

- 任一目标节点失联、上传超时或完整性校验失败，当前轮及整个作业失败；停止其他节点任务并释放资源，不跳过节点、不自动重跑整轮、不续跑失败轮。排除问题后可使用模型库中的同一文件启动新作业。单次传输内部的正常协议重传由现有 Transport 负责。
- 急停取消传输、停止任务角色并恢复待命链路；资源释放完成前禁止启动下一作业。
- Server 模型库中的原始上传文件保留；任务资源停止后清理各节点的临时模型和 update 大文件副本。
- 成功、失败与急停均保留小型日志、配置、状态及大小/摘要记录。证据归档失败时保留对应沙箱供排查，沿用现有机制；首版不提供结果大文件下载或历史归档浏览。

### 最终确认与关闭

用户已整体确认完整契约。本票决策完成，状态设为 `resolved`；正式答案见下方 `Answer`，地图仅保留结论索引。本次只完成规划，不表示运行实现或硬件验收已经完成。

## Answer

首版采用以下已确认的同步文件仿真作业契约。

### 作业范围与输入

- 首版交付同步文件仿真作业，不执行真实训练或聚合，不加载算法插件。
- 用户从电脑通过 Web 经管理网上传初始文件到 Server 受控模型库，选择该文件、目标节点集合与固定轮次数启动作业。模型库的具体上传、引用保护和删除契约由[定义内容寻址模型库契约](02-content-addressed-model-library.md)拥有。
- 平台按不透明普通文件处理输入；正式三机验收使用由 `wfb_ng.fl.issue41_fixtures` 生成的确定性 40 MiB 文件。40 MiB 是验收输入，不把任意用户文件要求为固定尺寸。
- 作业固定目标节点集合，运行中不因掉线缩减集合。首版不暴露算法选择、训练/聚合参数、半异步或异步模式。

### 每轮流程与成功判据

1. 复用 Server Daemon、Client Daemon、Client RoleService、作业级 `TASK_READY` 屏障及现有 Coordinator/Runtime/Transport；正常作业路径不依赖管理网 SSH。
2. Server 通过现有 UFTP 无线数据面向全部目标 Clients 下发所选文件。
3. 每个 Client 完成模型文件校验后跳过训练，把收到的模型文件内容作为本轮 update，经现有 HTTP PUT 无线数据面上传。不要求为了模拟训练而额外复制文件或人为延迟。
4. Server 校验每个目标节点提交的 update：除既有作业/轮次/节点关联和传输完整性规则外，其大小与 SHA-256 必须等于本轮下发文件。重复提交不得充当其他节点或后续轮次的结果。
5. 下行完成屏障达成且全部目标节点的有效 update 收齐，才算本轮完成。Server 跳过聚合，下一轮继续使用模型库中的同一文件内容；每轮仍具有独立 Runtime 轮次身份。
6. 配置次数表示完整同步轮次数，全部轮次完成才正常完成作业。同一作业内跨轮复用 Runtime/Transport，不逐轮重启任务角色。

### 失败、急停与下一作业

- 任一目标节点的确定性失败、等待超时或文件校验失败，使当前轮和整个作业失败。正常 UFTP/TCP 协议重传不等于重跑整轮；平台不自动补轮、不跳过节点、不恢复失败轮。
- 急停取消进行中的传输，停止任务角色并恢复待命链路；失败和急停均不继续开启新轮次，也不执行占位训练/聚合函数。
- 停止流程必须以实际传输、任务角色和资源释放结果为依据；不能仅设置作业终态或等待固定时长就宣告已恢复。未完成必要资源释放时禁止启动下一作业，并展示阻塞原因。
- 操作者处理问题后使用模型库中的原始文件启动新作业，不续用旧作业身份或失败轮次身份。
- 具体状态字段、事件和页面呈现由[定义控制台运行状态与进度语义](03-console-state-and-progress-semantics.md)拥有；沿用现有分层超时机制，首版不新增算法超时或人为训练/聚合延迟参数。

### 制品与证据

- 保留 Server 模型库中的原始上传文件，不随作业结束自动删除。
- 任务资源停止后，完成各节点小型日志、配置、状态与 manifest/大小/摘要记录归档，再清理临时模型和 update 大文件副本。
- 证据归档失败保留对应沙箱供诊断；此例外不阻止现有 Daemon 按其契约恢复待命链路。
- 首版不交付大文件结果下载或历史归档浏览。具体容量、文件上传上限和模型删除规则由模型库票决定，验收覆盖由[定义 Stage 4 分层验收矩阵](09-stage4-acceptance-matrix.md)决定。

### 现有设计与实现的处理边界

- 本票取消首版插件需求，不为真实算法制定训练/聚合签名、错误码或跨轮状态契约，也不建立旧算法入口的兼容层。
- 后续实施应把文件闭环编排归于平台，移除首版运行路径对 `issue41_algorithm.train/aggregate` 及完整多轮算法 callable 的依赖；直接复用既有 Runtime 与 Transport，不增加第二套文件交换协议。
- 现有算法专题、ADR-0010 与 Stage 2 Coordinator 的所有权表述存在冲突。进入实现前，在规格及权威设计专题中明确文件仿真作业的适用边界，并按需记录替代决策；不得静默以源码行为覆盖设计规则。真实算法插件与旧算法入口的全面替代留到后续真实算法工作，不在本票推演实现。
- 本次只规划，不修改运行代码。正式结论由本票拥有，地图 Decisions-so-far 仅保留一行结论索引。

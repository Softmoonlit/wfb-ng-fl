# 定义内容寻址模型库契约

## Question

首版受控模型库应如何定义上传、SHA-256 内容寻址、同内容去重、元数据、容量与文件名限制、列表、选择、引用保护和删除语义，使浏览器无需提交 Server 任意路径，并使运行中作业稳定引用不可变模型制品？

## Answer

### 制品身份与元数据

- 模型库仅管理不透明普通文件，不解析模型内容、不限制扩展名。浏览器通过管理网上传，模型下发仍使用既有无线数据面。
- Server 计算完整 SHA-256；一个摘要对应一份不可变模型制品和一条列表记录。浏览器通过完整摘要选择和启动作业，不提交 Server 任意路径；由 Server 在受控模型库内解析制品。
- 保留首次上传文件名、实际字节大小、完整摘要和首次入库时间。文件名仅供展示，不作为存储路径或身份。
- 同内容重复上传返回已有制品，不新增别名，不修改首次名称或入库时间。同名不同内容分别保存，以大小和摘要区分。
- 文件名允许中文和空格，UTF-8 编码长度为 1～255 字节；拒绝 `/`、`\`、控制字符和单独的 `.`、`..`，不自动截断或改名。页面以纯文本显示名称。

### 上传、容量与失败

- 拒绝空文件，单文件上限为 1 GiB（1,073,741,824 字节），模型库容量上限为 10 GiB（10,737,418,240 字节）。40 MiB 仅是实体闭环验收输入。
- 总容量按去重后的制品内容计算，上传中的临时数据也计入预算。上传开始时按声明大小预留容量，声明大小须与实际接收大小一致；不得越过单文件或总容量限制。
- Server 同时只接收一个模型上传；额外上传请求立即返回忙碌，不在服务端排队。运行中作业允许上传，列表、状态与急停持续可用。
- 接收过程中计算 SHA-256；只有完整接收并完成持久化后，制品才可进入列表并被选择。未完成上传不可见、不可被作业引用。
- 首版不支持断点续传。断连、大小不符、超限或写入失败时，清理临时数据并释放预留容量；daemon 重启清理未完成上传。实际磁盘空间不足时失败并清理，不自动删除已有制品。
- 入库成功但响应丢失时，重新上传通过去重返回已有制品。去重成功后释放临时数据及容量预留。
- 接收完成前不能确认重复内容，因此库满时重复上传也可能因预留容量不足而被拒绝；操作者可以直接选择已有制品。

### 保留、引用与删除

- 成功入库的制品持续保留，直到操作者手动删除；不自动淘汰，也不随作业结束删除。
- 接受作业时，Server 原子检查制品存在并取得引用；该检查与删除互斥，避免先检查后删除的竞态。表单选中或浏览不形成引用。
- 从作业接受到终态资源清理完成期间，拒绝删除所引用制品。清理完成后释放引用，允许删除；完成、失败和急停均遵循同一边界。
- 作业记录保留当时使用的名称、大小与摘要，历史记录不要求永久保留文件本体。作业临时模型和 update 的清理边界沿用《定义文件仿真作业运行契约》。
- 页面删除前要求操作者确认，后端在删除时再次检查引用；若其他页面已删除该制品，刷新列表即可。

### 列表与操作范围

- 首版仅提供上传、列表、选择和删除，不提供重命名、下载、标签、备注或搜索。
- 列表按首次入库时间倒序，展示首次文件名、字节大小、入库时间、摘要和是否被作业引用；允许查看及复制完整摘要。
- 查看列表与作业状态不因上传或运行中作业而禁用。API 路由、请求响应 Schema、错误编码由《定义 Web 控制面的 HTTP 与 SSE 契约》承接；页面组织由《验证桌面 Web 操作台的信息架构与交互》承接。

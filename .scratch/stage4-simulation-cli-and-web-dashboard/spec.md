# Stage 4: 用户交互入口：CLI 命令行与 Web 可视化面板

## 阶段目标

在底层通信、协同守护引擎与纯无网物理闭环均验证无误、接口完全冻结后，在 Server 侧开发面向仿真实验操作者的用户交互控制层，通过连接 Stage 2 提供的 `wfb-fl-server-daemon` 本地 IPC 接口，提供轻量 CLI 命令行工具与零构建依赖的浏览器 Web 可视化面板。

## 消费 Stage 2 的核心契约与交互承接

1. **统一 Local IPC 接入**：
   CLI 工具（`wfb-fl-core`）与 Web 后端均作为轻量客户端连接 `/run/wfb-fl/server.sock` 或 `http://127.0.0.1:9090`，零网卡抢占，零业务端口冲突。

2. **全生命周期常态化在线拓扑与信号展示**：
   无论是否有任务运行，利用 Server 守护引擎持续收集的客户端 UDP 心跳，在 Web 界面和 CLI 上常态化展示 Client 1 与 Client 2 的在线绿灯、当前所在信道、最后心跳延迟及空口信噪比/丢包遥测。

3. **射频感知与参数预设交互 (承接 Stage 2 / ADR-0011)**：
   - 提供“扫频探路”一键触发按钮，以直观柱状图渲染合法 5 GHz 信道排行（永久屏蔽 Channel 161）；全信道拥堵时给出显著风险警告弹窗；
   - 提供网卡预设单选下拉框（`robust` / `standard` / `performance`）；
   - 下行 UFTP 速率滑块随预设自动带出推荐中值（如 `standard` 默认 15 Mbps），手动超出安全区间时弹出强风险确认警示。

4. **三种联邦学习协同范式交互选择**：
   - 界面提供通俗易懂的单选组件：`[ ⊙ 同步 (Sync) | ○ 半异步 (Semi-Async) | ○ 异步 (Async) ]`；
   - 选“同步”时：锁定全员收齐；
   - 选“半异步”时：动态展开“最小收齐节点数（`min_updates`）”输入框；
   - 选“异步”时：动态展开“最大版本滞后（`max_staleness`）”输入框。

5. **一键仿真控制与流式推流**：
   - 支持一键下发作业、暂停与全网急停（`JOB_ABORT`）；
   - 采用纯原生前端技术栈（HTML5 + CSS + 原生 JS），服务端通过 SSE（Server-Sent Events）向浏览器毫秒级推送轮次推进曲线、各节点状态机卡片与实时带内日志。

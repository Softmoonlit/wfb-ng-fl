# 01: 建立可审计的三机运行包络

**What to build:** 为 Issue #41 的每次三机执行建立独立、不可覆盖、fail-closed 的运行包络。每次运行从重新发现实际拓扑和生成唯一 run ID 开始，在启动数据面前完成 preflight；无论成功或失败，都能受控停止已启动资源，并生成绑定唯一代码、主机、配置和运行模式的基础归档及失败分类。

**Blocked by:** External prerequisite: 三台机器已上线，当前 server 能通过 SSH 控制 client1 和 client2

**Status:** ready-for-agent

- [ ] 每次运行重新发现并归档 server、client1 和 client2 的主机身份、管理地址、仓库位置和实际无线接口，不沿用旧拓扑事实。
- [ ] 每次运行生成唯一 run ID，并绑定 branch、commit、工作区状态、三机身份、解析后配置和运行模式。
- [ ] preflight 验证三机版本与工作区一致、SSH、sudo、运行依赖、无线 USB、monitor/UP、信道、端口、TUN、残留进程和受管目录边界。
- [ ] 管理网被明确限制为 SSH 编排和证据回收，不得作为模型或 update 的成功数据路径。
- [ ] 旧归档不可覆盖，不同 run ID 的文件不可拼接，新运行不能复用未清理的旧运行目录。
- [ ] 任一 preflight 失败都阻止后续数据面阶段启动，并生成包含最后成功层、第一失败层和环境、工具、实现或链路能力分类的 failed 结果。
- [ ] 中途失败时先受控停止本次运行已经启动的资源，再完成证据收集和结论生成；不能在同一 run ID 中修改配置后续跑。
- [ ] 运行包络提供供后续阶段追加独立证据分区的单一接口，而不预判 gate、Runtime 或 lifecycle 状态。
- [ ] 成功 preflight、各类 preflight 失败、旧状态污染、归档覆盖、混合 run 和停止失败的自动化测试通过。

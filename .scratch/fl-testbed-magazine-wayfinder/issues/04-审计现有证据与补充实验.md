# 审计现有证据与补充实验

Type: task
Status: resolved
Blocked by: 03

## Question

项目现有设计、自动回归和真实硬件证据能分别支撑中心主张的哪些部分？还缺哪些最小且必要的定量实验、基线、消融或可复现性材料，才能达到 Magazine 文章的论证强度？

## Answer

### 审计范围与方法

读取六篇设计专题、设计入口与 CONTEXT.md；全仓清点 Makefile 测试门禁、C++/Python 测试、tests/acceptance、tests/real_hardware、实验脚本、射频可编程面（src/、scripts/default）、提交历史与未合并分支。结论基于 HEAD = chore/local-issue-tracker（2026-08-09）。

### 一、现有证据能支撑主张的哪些部分

**主张 1：可编程真实广播空口（第一贡献/钩子）**

- 设计证据（强）：六篇专题冻结 monitor 接收、raw injection、广播承载、Radiotap/HT/VHT、射频观测（无线物理层设计）；GRANT/READY/Token Passing/队列反压/反馈窗口（链路层专题）。物理层明确不冻结具体硬件型号、信道组合、功率阈值、发射速率——可编程面实际边界由实现决定。
- 实现证据（强）：src/v6_uplink.cpp 暴露旋钮 `--link-id`（信道）、`--radio-bandwidth 20|40`、`--radio-mcs-index 0-31`、`--radio-short-gi`、`--fec-k/--fec-n`、队列水位、`--grant-duration-ms`/`--guard-interval-ms`/反馈窗口、方向流；经 scripts/default/fl-*.json 的 link_args 透传给 wfb_v6_uplink（wfb_ng/fl/service.py L160-176）。
- 回归证据（中）：control_envelope_test、v6_uplink_queue_test、v6_uplink_downlink_nonce_test、test_v6_startup 覆盖控制帧判定、水位反压、nonce 隔离、启动校验；但没有任何测试验证"射频参数确实生效"（注入 radiotap 头与实际发射帧一致、不同参数产生不同可观测链路行为）——该部分目前只有代码 review 支撑。
- 硬件证据（弱）：唯一现役入口 v6_manual_uplink_demo.sh + 演示手册记录了三机演示参数（ch157/HT40+/MCS1/短GI/FEC 8-12/grant 120ms），但手册面板数字是占位符，非实测记录；仓库无归档实测数据（tests/logs 被 .gitignore）；RX_ANT 日志（src/rx.cpp L647，freq/mcs/bw/rssi min-avg-max）是唯一空口观测面且为日志文本。

**主张 2：跨层 testbed 与验证方法（第二贡献）**

- 设计证据（强）：五层架构、下行完成屏障、上行收齐边界、Transport 契约（UFTP closed group、HTTP PUT、Content-Digest、100 Continue、201 Created）、Runtime 四接口与原子持久化全部冻结。
- 回归证据（强）：135 个 Python 用例覆盖 v8 契约层（file_contract、http_put_transport、uftp_operation、runtime_persistence、multi_client_sync、role_service_lifecycle、single_client_loop）+ 2 个 netns 全流程验收脚本（v6_uplink/downlink_namespace.sh，UDP 替代空口，产出 result.md/2A JSON）；v8 角色服务生命周期已集成进 master（feat/40）。
- 硬件证据（中）：v8 真实硬件 FL 闭环脚本（issue41_fl_runtime_loop.sh、issue41_build_summary.py 等）只在未合并分支 feat/41-real-hardware-fl-runtime-redo；master 无。其"两轮"指两轮 FL round，非统计重复。

**主张 3：真实硬件代表性实验洞察（第三贡献）**

- 无任何现有证据：全仓无 round latency、time-to-accuracy、丢包率/FEC 统计、重复实验或统计口径数据；2A 摘要全部是行为计数器（tun_read_pause_total、reassembly_overflow_evict、grant/ready 计数等），不含射频或性能指标；"真实硬件测试已通过"仅存于路线图文字声明（docs/后续版本路线图.md），无配套数据。

### 二、主张-实现不一致（必须裁决）

中心主张声称"在网卡、驱动和监管域允许范围内显式控制并记录……发射功率"，但全仓无任何 txpower/功率旋钮或记录（发射功率只能靠驱动/iw 默认）。两个修正选项：(a) 缩小主张，把发射功率从"显式控制并记录"清单移除或降级为"驱动默认功率 + RX RSSI 观测"；(b) 增加实现，为 wfb_v6_uplink 增加 txpower 配置与记录。建议在 05 能力矩阵讨论中裁决，默认倾向 (a)。

### 三、最小必要补充实验与可复现性材料（按工单 03 的证据策略）

1. **能力展示矩阵实验**（支撑主张 1）：真实硬件上对每个宣称旋钮做冒烟验证（参数被接受、系统可跑通），射频旋钮（MCS/带宽/短 GI）须有 RX 侧观测佐证"发射参数确实到达空口"。现成基础：v6_manual_uplink_demo.sh 已传参、RX_ANT 已记录；缺：结构化采集与归档。
2. **代表性实验一：MCS 生效与可重复**（候选参数已锁定 MCS）：约 3 个设置 × 5-10 次重复，每次记录（发射配置、RX 观测、端到端结果），以中位数/IQR（或箱线图/成功次数）汇总。缺：重复运行编排（脚本循环）、结果归档；RX_ANT 需解析为结构化数据或新增结构化输出。
3. **代表性实验二：端到端证据链**：从实验一选 2 个配置，运行完整 v8 FL 轮次（多客户端、多轮），展示"空口配置 → 链路行为 → 文件完整交付 → FL 轮次进度"，采集 round latency、wall-clock time-to-accuracy 等端到端指标。缺：master 上无真实硬件 FL 闭环脚本（可移植/重新验证 feat/41 分支资产）。
4. **可复现性材料**：(a) 实验产物归档约定——配置、日志、摘要打包为可引用产物（当前 tests/logs 被 gitignore、result.md/2A JSON 不落库）；(b) 统计汇总脚本（中位数/IQR/箱线图）；(c) 无 CI，回归只靠本地 make test——可选为"可复现 testbed"主张加 CI 跑 make test。
5. **基线/消融**：按工单 03 决策不新增普通 Wi-Fi 性能基线、不与其他平台比较；无需额外算法消融——"同一参数不同设置"本身构成消融，内含于实验一。

### 四、给后续工单的关键事实

- 能力面旋钮清单（见第一节）→ 05 能力矩阵/参数范围表、06 写法。
- RX_ANT 是唯一射频观测面（freq/mcs/bw/rssi min-avg-max，日志文本）→ 05 图表数据来源。
- 发射功率无旋钮无记录 → 主张修正裁决（并入 05）。
- 实验一/二现成基础：v6_manual_uplink_demo.sh（可改造为循环+归档）、netns 验收脚本、feat/41 分支硬件 FL 闭环资产。
- 2A 摘要为行为计数器、无性能指标 → 实验指标需新增采集；演示手册面板数字为占位符，不可引用为数据。

### 结论

设计（主张 1/2 的能力面与方法论）证据充分且已冻结；回归（主张 2）覆盖良好但无 CI 且不验证射频生效；硬件（主张 1/3）只有单次演示、无归档数据；主张 3 完全没有定量证据，需按实验 1-3 的最小实验集从零建立；发射功率主张必须先裁决才能定稿能力展示部分。

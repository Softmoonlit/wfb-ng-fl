# 确定文章主张与比较边界

Type: grilling
Status: resolved
Blocked by: 01, 02

## Question

基于体裁范本、技术对手和目标刊物要求，文章应如何把“可复现跨层 testbed”收敛成一个可辩护的中心主张？应与哪些平台比较、比较哪些维度，并明确排除哪些无法公平比较的范围？

## Answer

### 中心主张

本文围绕可编程真实广播空口展开：普通关联式 Wi-Fi 会隐藏或自动决定许多 PHY/MAC 行为，并通常让广播/组播沿默认基本速率路径发送；本 testbed 基于 802.11 monitor 接收与 raw frame injection，在网卡、驱动和监管域允许范围内显式控制并记录信道/中心频率、带宽、发射功率、受支持的 HT/VHT MCS 和发射元数据，再把真实空口观测连接到模型完整交付、update 收集、轮次完成和学习结果。其价值不是预设性能领先，而是把无线条件转化为端到端 FL 中可控制、可测量、可重复的实验变量。

全文采用以下贡献层级：

1. 可编程真实广播空口是第一贡献和文章钩子；
2. 跨层 testbed 与验证方法是第二贡献，负责连接空口配置、链路观测、文件交付与 FL 轮次结果；
3. 真实硬件上的代表性实验洞察是第三贡献，具体结论须以证据审计和补充实验为准。

Token Passing、反压、UFTP、HTTP 和文件持久化是让传输闭环成立的支撑机制，不分别包装成研究贡献，也不把反压或调度参数视为一般性的 FL 训练影响因素。

### 相关工作与比较边界

Flower、FedScale、FedComm 和真实 MQTT FL testbed 只用于定位问题：它们分别代表通用框架、规模化 benchmark、通信协议实验和真实端到端部署。本文不与它们比较算法数量、客户端规模、API 完整度、Runtime 性能或通用 benchmark 能力，也不声称本项目在这些维度优于它们。正文不设置独立 Related Work，相关定位压缩到引言约 120–180 词。

普通 Wi-Fi 只作为设计动机和能力边界的概念参照，不设为必要性能基线。本文不声称 raw-injection 广播比普通 Wi-Fi 更快、更准、更节能或更可扩展；只有未来决定提出这类相对性能结论时，才需要补充公平的普通 Wi-Fi 单播/组播实验。

### 证据策略

采用“能力展示 + 两个代表性实验故事”，不进行全面参数 benchmark：

- 能力展示说明可配置、可记录和可观测的空口参数范围，并明确真实硬件、驱动和监管约束；
- 代表性实验一选取一个最有说明力的空口参数，以约三个设置和每个设置 5–10 次重复验证参数确实生效、结果可重复且变化可解释；优先候选为 MCS，最终由证据审计决定；
- 代表性实验二从实验一选择两个代表配置，运行完整 FL 轮次，展示“空口配置 → 链路行为 → 文件完整交付 → FL 轮次进度”的端到端证据链；
- 其他信道、带宽、发射功率、MCS、客户端数量和模型大小只进入能力矩阵或未来研究范围，不做笛卡尔积扫描；
- 重复实验用中位数与四分位范围、置信区间、箱线图或成功次数压缩表达，不能用单次验收通过代替可重复性证据。

文章不预设无线配置会改变按轮次计的算法收敛规律；需要连接学习层时，优先报告 round latency、wall-clock time-to-accuracy 等端到端指标，而不是声称最终准确率提高。

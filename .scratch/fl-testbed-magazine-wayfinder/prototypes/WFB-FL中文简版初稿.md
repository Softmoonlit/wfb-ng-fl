## 一、 为什么需要新平台？无线 FL 需求与平台能力对比

### 1. 真实无线 FL 实验平台的四大核心需求

从“分布式协同计算”与“半双工时变信道”的内在物理矛盾出发，严谨的无线 FL 实验平台必须满足四项基本需求：

1. **真实物理空口参与（Real Air Interface）**：脱离纯软件仿真（NS-3/Mininet）与离线 trace 的理想化陷阱。真实的功放非线性失真、多径干涉与突发丢包（Bursty Loss）是引发 FL 轮次掉队（Straggler）的根源，配合主机总线与中断瓶颈，构成了算法落地的真实物理约束。
2. **关键 PHY/MAC 行为精细可编程（Fine-Grained PHY/MAC Programmability）**：满足控制变量法与因果归因的硬性要求。商用 Wi-Fi 固件全自动速率自适应（如 Minstrel）会导致实验者无法判定训练提速源自算法还是固件升档；平台必须支持逐包显式指定 MCS 0–31、带宽、Short GI 与 FEC。
3. **高吞吐下行物理广播支持（High-Throughput Downlink Broadcast）**：匹配 FL 下行“一对多大模型同步”特征。常规单播传输开销随客户端数呈 $O(K)$ 爆炸；而标准 802.11 协议将广播锁死在 1~6 Mbps 基本速率（广播 50 MB 模型需近 67 秒）。平台必须突破限制，支持高阶 MCS（数十至数百 Mbps）物理广播，将耗时压缩至秒级（$O(1)$ 开销）。
4. **帧级射频观测与消费级硬件低门槛（Deep RF Observability & Broad Reproducibility）**：应用层日志无法定位丢包机理，平台须通过 monitor 模式无损捕获 Radiotap 头部，实时提供帧级 RSSI/MCS 观测；同时必须基于现成消费级 802.11 网卡，避免昂贵 SDR（如 USRP）造成的“贵族孤岛”，确保学术界普遍可独立复现。

### 2. 现有无线平台局限性与 WFB-FL 对比

审视当前无线物理实验载体，现有平台在上述需求上均存在结构性短板：
- **常规 Wi-Fi 平台**：受制于固件闭源封装，PHY/MAC 参数不可控，广播被锁死在低速率且缺失帧级射频观测；
- **蓝牙/BLE 平台**：带宽狭窄（1–2 Mbps），报文载荷微小，无法承载大模型快速分发；
- **SDR / 蜂窝测试床**：虽具备物理层可编程性，但硬件高昂（单节点数万元）、协议栈脆弱且受频谱管制，难以规模化普及。

**WFB-FL** 利用消费级 Wi-Fi 网卡的 monitor 模式与原始帧注入机制，在**低成本通用硬件**上同时实现了**全栈物理参数可编程、突破协议限制的高阶 MCS 原生物理广播、帧级射频观测以及专为 FL 定制的跨层可靠性契约**。

## 二、 WFB-FL 平台架构与运作机制

### 1. 五层跨层体系架构

WFB-FL 采用清晰的五层单向依赖架构，控制流自顶向下下发，数据与完成状态自底向上回传：

```
+-------------------------------------------------------------------------+
| (1) FL 算法层 (Algorithm Layer)                                         |
|     - 本地模型训练、评估、聚合算法 (PyTorch/TF)                         |
+-------------------------------------------------------------------------+
                                    │ (标准 SDK API: publish, wait_for_model,
                                    ▼  submit_update, wait_for_updates)
+-------------------------------------------------------------------------+
| (2) FL 运行时 / SDK 层 (Runtime Layer)                                   |
|     - 轮次生命周期编排、本轮参与客户端集合冻结、轮次状态机             |
+-------------------------------------------------------------------------+
                                    │ (文件与 Manifest: SHA-256 结构校验)
                                    ▼
+-------------------------------------------------------------------------+
| (3) 传输适配后端 (Transport Backend Layer)                              |
|     - 下行：UFTP 闭合组物理广播模型分发                                 |
|     - 上行：基于 HTTP PUT (带 100 Continue / 201 Created) 的独立会话    |
+-------------------------------------------------------------------------+
                                    │ (TUN/IP 虚拟网卡边界)
                                    ▼
+-------------------------------------------------------------------------+
| (4) 集成式链路层底座 (Integrated Link-Layer: wfb_v6_uplink)             |
|     - 中心化 Token Passing 发送权调度、反向控制窗口、出站反压队列       |
+-------------------------------------------------------------------------+
                                    │ (Radiotap 控制头注入 & Monitor 抓包)
                                    ▼
+-------------------------------------------------------------------------+
| (5) 无线物理与射频观测层 (Radio PHY & Observability Layer)               |
|     - 消费级 802.11 网卡 Raw Frame Injection、物理广播、RX_ANT 观测    |
+-------------------------------------------------------------------------+
```

### 2. 可编程空口与射频观测机制

- **发送端（全栈参数控制）**：
  - **信道与频段**：显式配置 2.4/5 GHz 物理信道，实现多实验物理隔离；
  - **信道带宽**：支持 20 MHz 与 40 MHz 切换；
  - **调制编码方案（MCS）**：支持 HT/VHT MCS 0–31 逐包指定；
  - **保护间隔（Short GI）**：支持开启/关闭 400ns 短保护间隔；
  - **前向纠错冗余（FEC）**：支持在链路层配置 Reed-Solomon 纠错比率（如 $k/n = 8/12$）；
  - **出站反压队列**：显式设置链路层发送队列容量与水位，杜绝缓冲区溢出；
  - **Token 调度窗口**：精确设置令牌持续时间（如 120 ms）与保护时隙（如 10 ms）；
  - **发射功率**：通过底层接口受控调节发射功率。
- **接收端（非侵入式射频观测面 RX_ANT）**：
  - 接收侧网卡在 monitor 模式下无损截获每个 802.11 原始帧并解析 Radiotap 头部；
  - 实时输出结构化日志，包含时间戳、接收频率、实际生效 MCS、信道带宽与三维 RSSI（min/avg/max），提供第一手物理观测依据。

### 3. 端到端 FL 轮次全生命周期与运作流程

```
[Server Runtime]              [Server Link (wfb)]           [Client Link (wfb)]           [Client Runtime]
       │                              │                              │                            │
       ├─ (1) 冻结本轮 Client 集合 ───┼──────────────────────────────┼────────────────────────────┤
       ├─ (2) 触发 UFTP 模型广播 ────►│                              │                            │
       │   (分发模型文件与 Manifest)  ├── 802.11 高速广播 (MCS 0-31) ─►│                            │
       │                              │◄── UFTP 反向窗口状态回传 ────┤                            │
       ├─ (3) [下行完成屏障达成] ◄────┤                              │                            │
       │   (全员确认交付后越过屏障)   │                              ├─ (4) SHA-256 结构校验 ────►│
       │                              │                              │   (校验成功后启动本地训练) │
       │                              │                              │                            │
       │                              │◄── 发送 READY 声明 ──────────┤◄─ (5) 训练完成生成 Update ─┤
       │                              │                              │   (写出 update manifest)   │
       │                              ├── 发放上行 GRANT 令牌 ──────►│                            │
       │                              │                              ├─ (6) HTTP PUT 提交 ───────►│
       │                              │◄── HTTP 流式上传数据 ────────┤   (100-Continue 预留槽位)  │
       │                              │                              │   (201-Created 原子落位)   │
       │                              │                              │                            │
       ├─ (7) [全员收齐触发聚合] ─────┼──────────────────────────────┼────────────────────────────┤
       │   (全员 Update SHA-256 校验通过后触发模型聚合，写入成功终态) │                            │
```

一轮完整的 FL 训练包含以下核心阶段：
1. **下行阶段（高速物理广播）**：Server 调用 UFTP 以高阶 MCS（如 MCS 7）广播模型文件，周期性开辟反向控制窗口收集切片状态。全员接收后越过下行屏障，Client 校验 SHA-256 后开启本地训练；
2. **上行阶段（令牌防撞与原子上传）**：Client 训练完毕写出 update manifest 并发送 `READY` 声明；Server 集中发放独占 `GRANT` 令牌；Client 凭令牌通过 HTTP PUT 上传（`100 Continue` 预留槽位 $\to$ `201 Created` 原子提交），杜绝并发空口碰撞；
3. **收齐聚合**：Server 确认全员合法 Update 后触发聚合并步入下一轮，异常则确定性整轮重置。

## 四、 平台客观约束与开放研究方向

### 1. 平台当前客观约束
1. **硬件与节点规模**：当前基于中小规模边缘节点集群验证，超大规模节点的 Token 调度扩展性仍待评估；
2. **射频芯片与驱动异构性**：当前元数据依赖特定 802.11 芯片（如 Atheros/MediaTek）的开源驱动 Radiotap 格式；
3. **发射功率旋钮前置依赖**：`txpower` 显式接口的完整集成是后续定稿投稿的前置工程任务。

### 2. 开放研究方向
1. **跨设备与新频段泛化**：拓展至 Wi-Fi 6/6E/7（802.11ax/be）与 6 GHz 频段；
2. **算法驱动的自适应空口调度**：利用 RX_ANT 实时射频反馈，由 FL 算法层根据参数重要性动态调整 MCS 与 FEC 冗余；
3. **自动化云原生评测基准床**：构建支持远程提交作业的标准化物理无线 FL 评测平台。

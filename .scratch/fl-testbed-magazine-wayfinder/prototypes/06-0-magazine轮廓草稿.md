## 摘要（约 150 词，待英文定稿）

联邦学习（FL）正快速从数据中心延伸至真实无线边缘环境，但主流框架普遍将无线链路抽象为透明、可靠的黑盒管道，遮蔽了底层空口配置、信道时变与模型文件交付及训练收敛之间的深层因果关系。本文提出 **WFB-FL**——一种基于现成消费级 802.11 硬件的跨层无线联邦学习实验平台，**把真实无线链路从 FL 抽象层下面拿出来，做成可控制、可测量、低门槛的实验载体**。WFB-FL 基于 802.11 monitor 模式与原始帧注入，突破传统协议栈限制，直接实现高阶 MCS 广播分发、逐帧物理/MAC 参数精细控制、非侵入式射频观测以及严格的跨层传输契约保障。文章首先提出无线 FL 实验平台需求并对比现有无线平台能力；接着深入阐述 WFB-FL 的跨层架构、可编程空口与端到端运作机制；随后展示正式实验证据（能力资格确认、MCS 重复运行一致性实验与端到端 FL 传播实验）；最后讨论系统洞察、实验边界与开放研究方向。

## 第 1 节 Introduction（约 600 词）

联邦学习（Federated Learning, FL）使得大量分布式边缘客户端能够在不共享本地私有数据的前提下，协同训练全局机器学习模型。随着 FL 部署场景从高速有线数据中心延伸到移动设备、智能工厂和车载边缘网络，无线网络已成为模型下发与梯度上传的关键物理纽带。然而，当前主流 FL 实验范式存在一个显著的结构性断层：通用编排框架（如 Flower）与大规模评测基准（如 FedScale）通常将无线传输抽象为均质、透明且无差错的可靠管道。框架默认数据包能够即时且完好地送达，既不暴露底层无线信道与协议栈的动态配置，也不记录空口传输的真实物理行为，更无法让实验者显式调控无线环境以研究其对算法收敛的影响。

这种黑盒抽象在真实无线环境中带来了严重的实验不可解释性。在实际物理信道中，调制编码方案（MCS）、信道带宽、发射功率、保护间隔（GI）以及多径衰落等因素会导致物理层吞吐、误帧率与传输时延发生剧烈波动；这些底层物理层差异会经由链路队列积压、传输层分片重组与应用层文件交付，逐级放大并直接映射为客户端掉队（straggler）、轮次耗时拉长甚至训练发散。当无线链路被封装在黑盒之中时，研究者根本无法判定所观察到的 FL 性能波动究竟源自分布式算法设计的优劣，还是底层无线空口恶化诱发的系统副效应。

为打破这一黑盒困境，**本文把真实无线链路从 FL 抽象层下面拿出来，做成可控制、可测量、低门槛的实验载体**——可控制，指空口关键参数（MCS、带宽、保护间隔、FEC、发射功率等）作为自变量可被实验者显式设定；可测量，指帧级射频行为（实际生效 MCS、信号强度、频点、吞吐与丢包）作为因变量可被独立观测；低门槛，指实验所需全部硬件与软件均以消费级成本可得，无需昂贵专用射频设备。我们提出并实现了 **WFB-FL**（WifiBroadcast for Federated Learning）跨层实验平台。系统基于消费级 802.11 网卡的 monitor 接收模式与原始帧注入（raw frame injection）技术，直接在物理/MAC 层构造、发送与捕获无线空口帧——这里的“空口”指数据实际通过无线电电磁波收发的物理媒介环节，包含调制解调、载波监听、信道编码与介质访问控制等具体行为。在此基础上，WFB-FL 建立了从物理空口、链路层令牌调度、传输层文件分发到应用层 FL 运行时（Runtime）的完整跨层控制与观测体系，把无线空口从不可控的外部噪声转变为可显式设定自变量、可独立观测因变量、可低成本部署的受控实验对象。

本文的核心贡献总结如下：

1. **可编程真实广播无线空口与低门槛硬件实现**：基于现成消费级 802.11 硬件，突破商用固件封装，将 MCS、带宽、Short GI、FEC 及发送队列等关键 PHY/MAC 参数完全暴露为可编程控制点，并实现帧级非侵入式射频元数据观测；
2. **WFB-FL 跨层实验平台与端到端可靠性契约**：构建了向下贯通真实空口、向上适配 FL 业务语义的五层跨层架构，定义了包含下行广播屏障、上行原子槽位预留、SHA-256 完整性约束的分层验证契约，保障了无硬件 ACK 广播信道上的严谨实验闭环；
3. **真实硬件上的代表性实验洞察**：在真实测试床上完成了正式能力资格确认，通过多轮 MCS 重复运行一致性实验与端到端 FL 训练实验，定量揭示了物理层配置差异如何沿“空口行为 → 文件交付 → 轮次同步 → 学习收敛进度”链条逐层传播。

## 第 2 节 Testbed 需求与无线平台能力对比（约 800 词）

### 真实无线 FL 实验平台的四大核心需求

要将无线链路从不可见的黑盒管道转化为严谨的实验载体，测试床的设计绝不能仅凭工程直觉，而必须从**无线 FL 的业务流量特征、信道物理定律与实证科学方法**自顶向下推导。本文讨论范围限定在真实物理部署的无线平台：**真实物理链路是所有候选平台共享的前提，而非区分性需求**（纯仿真平台不在对比之列）。在此前提下，平台设计面临以下四项不可妥协的核心需求：

1. **关键 PHY/MAC 行为精细可编程（Fine-Grained PHY/MAC Programmability）**：商用 Wi-Fi 固件全自动速率自适应（如 Minstrel）会导致实验者无法判定训练提速源自算法还是固件升档；平台必须支持逐包显式指定 MCS 0–31、带宽、Short GI 与 FEC，满足控制变量法与因果归因的硬性要求。
2. **高吞吐下行物理广播支持（High-Throughput Downlink Broadcast）**：匹配 FL 下行“一对多大模型同步”流量特征。常规单播传输开销随客户端数呈 $O(K)$ 爆炸；而标准 802.11 协议将广播锁死在 1~6 Mbps 基本速率（广播 50 MB 模型需近 67 秒）。平台必须突破限制，支持高阶 MCS（数十至数百 Mbps）物理广播，将耗时压缩至秒级（$O(1)$ 开销）。
3. **帧级射频观测（Frame-Level RF Observability）**：应用层日志无法定位丢包机理，平台须通过 monitor 模式无损捕获 Radiotap 头部，实时提供帧级 RSSI/MCS 观测，为因果归因提供第一手物理证据。
4. **消费级硬件低门槛（Low-Cost Commodity Hardware）**：平台必须基于现成消费级 802.11 网卡，避免昂贵 SDR（如 USRP）造成的“贵族孤岛”，使多数实验室能够负担实验部署。

### 现有无线平台局限性与 WFB-FL 对比

审视当前无线物理实验载体，现有平台在上述需求上均存在结构性短板：
- **常规 Wi-Fi 平台**：受制于固件闭源封装，PHY/MAC 参数不可控，广播被锁死在低速率且缺失帧级射频观测；
- **蓝牙/BLE 平台**：带宽狭窄（1–2 Mbps），报文载荷微小，无法承载大模型快速分发；
- **SDR / 蜂窝测试床**：虽具备物理层可编程性，但硬件高昂（单节点数万元）、协议栈脆弱且受频谱管制，难以规模化普及。

**WFB-FL** 利用消费级 Wi-Fi 网卡的 monitor 模式与原始帧注入机制，在**低成本通用硬件**上同时实现了**全栈物理参数可编程、突破协议限制的高阶 MCS 原生物理广播、帧级射频观测以及专为 FL 定制的跨层可靠性契约**。

### 跨层定位与相关工作区分

在整个分布式与无线机器学习研究生态中：
- **通用 FL 编排系统**（如 Flower、FedScale）：侧重于算法调度、异构计算模拟与大规模基准测试，但将无线通信视为理想黑盒；
- **通信模拟与网络仿真**（如 FedComm）：主要在 NS-3 或 Mininet 中对通信协议进行数学仿真，不涉及真实硬件射频特性；
- **广域网部署测试床**（如基于 MQTT 的跨国广域网 FL 测试）：在真实 Internet 上开展端到端训练，但其底层无线接入依然是不可控的常规商用信道。

综合来看，现有平台均无法同时满足全部四项需求：常规 Wi-Fi 与 BLE 缺乏可编程性与帧级观测，SDR 虽具备可编程性与可测量性，但单节点数万元的硬件成本使绝大多数实验室难以负担。WFB-FL 的唯一学术定位，是**首个在消费级硬件上同时满足全部四项需求的真实 FL 实验平台**。

## 第 3 节 WFB-FL：跨层体系架构与端到端运作机制（约 1200 词）

作为本文的核心贡献，**WFB-FL** 突破了传统网络协议栈的黑盒封装，构建了自上而下的五层跨层体系架构。系统将底层可编程无线空口、链路层无冲突令牌调度、传输层高效模型广播与应用层 FL 业务逻辑深度缝合，使复杂的无线通信过程对上层算法完全透明，同时对底层物理环境完全可控可测。

### 1. 五层跨层体系架构

WFB-FL 采用清晰的五层单向依赖架构，控制流自顶向下下发，数据与完成状态自底向上回传（如图 F1 所示）：

```
+-------------------------------------------------------------------------+
| (1) FL 算法层 (Algorithm Layer)                                         |
|     - 本地模型训练、评估、聚合算法 (PyTorch/TF)                         |
+-------------------------------------------------------------------------+
                                    │ (标准 SDK API: publish, wait_for_model,
                                    ▼  submit_update, wait_for_updates)
+-------------------------------------------------------------------------+
| (2) FL 运行时 / SDK 层 (Runtime Layer)                                   |
|     - 轮次生命周期编排、本轮参与客户端集合冻结、轮次状态机             |
+-------------------------------------------------------------------------+
                                    │ (文件与 Manifest: SHA-256 结构校验)
                                    ▼
+-------------------------------------------------------------------------+
| (3) 传输适配后端 (Transport Backend Layer)                              |
|     - 下行：UFTP 闭合组物理广播模型分发                                 |
|     - 上行：基于 HTTP PUT (带 100 Continue / 201 Created) 的独立会话    |
+-------------------------------------------------------------------------+
                                    │ (TUN/IP 虚拟网卡边界)
                                    ▼
+-------------------------------------------------------------------------+
| (4) 集成式链路层底座 (Integrated Link-Layer: wfb_v6_uplink)             |
|     - 中心化 Token Passing 发送权调度、反向控制窗口、出站反压队列       |
+-------------------------------------------------------------------------+
                                    │ (Radiotap 控制头注入 & Monitor 抓包)
                                    ▼
+-------------------------------------------------------------------------+
| (5) 无线物理与射频观测层 (Radio PHY & Observability Layer)               |
|     - 消费级 802.11 网卡 Raw Frame Injection、物理广播、RX_ANT 观测    |
+-------------------------------------------------------------------------+
```

各层核心职责与接口关系如下：
1. **FL 算法层**：承载具体分布式训练任务（如 ResNet/Transformer 训练与 FedAvg 聚合）。算法层仅调用 FL Runtime 提供的四个极简本地接口（`publish_model`、`wait_for_model`、`submit_update`、`wait_for_updates`），完全不感知任何底层网络与硬件细节。
2. **FL Runtime / SDK 层**：管理同步 FL 轮次的生命周期。在每轮启动时，Runtime 冻结“本轮参与客户端集合”快照，该快照严格约束下行模型广播接收目标与服务端等待 update 的全员收齐集合。
3. **Transport Backend 层**：将 FL 文件交换映射到高效传输管道。下行阶段调用 UFTP（UDP-based Fast Transport Protocol）闭合组，直接通过底层广播通道向全量客户端并发分发模型文件；上行阶段为每个客户端建立独立的 HTTP PUT 会话，实现 update 文件的隔离上传。
4. **集成式链路层底座（`wfb_v6_uplink`）**：坐落在 TUN 虚拟网络边界之下，统一管理无线信道的发送权、流量分流与拥塞控制。针对无线半双工与广播碰撞难题，设计了 **Token Passing 调度机制**：服务端作为仲裁者，仅向已发送 `READY` 声明的活跃客户端轮流发放 `GRANT` 令牌；客户端严格在持有有效令牌期间向空口注入上行数据，彻底消除多客户端上行竞争碰撞。此外，链路层周期性开辟“反向控制窗口”，在下行广播期间短暂暂停模型注入，向客户端发放短 GRANT 以回传 UFTP 确认状态。
5. **无线物理与射频观测层**：直接驱动消费级 802.11 硬件。在发送侧通过 Radiotap Header 注入自定义 PHY 参数；在接收侧通过 monitor 模式无损截获空口原始帧，并解析提取硬件级射频元数据。

### 2. 可编程空口与非侵入式射频观测机制

WFB-FL 将无线信道的关键物理/MAC 行为完全抽象为用户态可调的配置旋钮，同时提供高精度的硬件级无损观测：

- **发送端：全栈可编程控制旋钮**
  - **信道与频段（Channel / Link ID）**：显式指定 2.4 GHz 或 5 GHz 频段上的具体物理信道，实现多实验间的物理频域隔离；
  - **信道带宽（Bandwidth）**：支持 20 MHz 与 40 MHz 频宽切换；
  - **调制编码方案（MCS Index）**：支持 HT/VHT MCS 0–31 逐包显式指定，直接决定物理层传输速率与抗噪容限；
  - **保护间隔（Short GI）**：支持开启/关闭 400ns 短保护间隔；
  - **前向纠错冗余（FEC Parameters）**：支持在链路层配置 Reed-Solomon 纠错编码比率（如 $k/n = 8/12$），提供物理层之上的数学冗余恢复能力；
  - **出站反压队列（Queue Watermarks）**：显式设置链路层发送队列容量与 pause/resume 触发水位，防止无硬件 ACK 环境下的缓冲区溢出；
  - **Token 调度窗口（Grant Duration & Guard Interval）**：精确调节令牌持有时长（如 120 ms）与保护时隙（如 10 ms），适配不同网络规模；
  - **发射功率（Transmit Power）**：通过底层接口与脚本受控调节网卡发射功率。

- **接收端：非侵入式射频观测面（RX_ANT Observability）**
  - 接收侧网卡在 monitor 模式下无损截获每个到达的 802.11 原始空口帧，并实时解析 Radiotap 头部，向系统输出结构化的 `RX_ANT` 射频日志。
  - 日志精确记录每帧到达的时间戳、接收频率、实际生效 MCS、信道带宽以及信号强度（min/avg/max RSSI）。这为研究者分析底层无线信道波动对上层 FL 训练的微观影响提供了最客观、直接的第一手物理证据。

### 3. 端到端 FL 轮次全生命周期与运作流程

在缺乏底层硬件 ACK 的半双工广播无线信道上，WFB-FL 通过严格的端到端时序协作，保障一轮 FL 训练的高效、可靠闭环（如图 F2 所示）：

```
[Server Runtime]              [Server Link (wfb)]           [Client Link (wfb)]           [Client Runtime]
       │                              │                              │                            │
       ├─ (1) 冻结本轮 Client 集合 ───┼──────────────────────────────┼────────────────────────────┤
       ├─ (2) 触发 UFTP 模型广播 ────►│                              │                            │
       │   (分发模型文件与 Manifest)  ├── 802.11 高速广播 (MCS 0-31) ─►│                            │
       │                              │◄── UFTP 反向窗口状态回传 ────┤                            │
       ├─ (3) [下行完成屏障达成] ◄────┤                              │                            │
       │   (全员确认交付后越过屏障)   │                              ├─ (4) SHA-256 结构校验 ────►│
       │                              │                              │   (校验成功后启动本地训练) │
       │                              │                              │                            │
       │                              │◄── 发送 READY 声明 ──────────┤◄─ (5) 训练完成生成 Update ─┤
       │                              │                              │   (写出 update manifest)   │
       │                              ├── 发放上行 GRANT 令牌 ──────►│                            │
       │                              │                              ├─ (6) HTTP PUT 提交 ───────►│
       │                              │◄── HTTP 流式上传数据 ────────┤   (100-Continue 预留槽位)  │
       │                              │                              │   (201-Created 原子落位)   │
       │                              │                              │                            │
       ├─ (7) [全员收齐触发聚合] ─────┼──────────────────────────────┼────────────────────────────┤
       │   (全员 Update SHA-256 校验通过后触发模型聚合，写入成功终态) │                            │
```

一轮完整的 FL 训练包含以下核心阶段：

1. **下行阶段：高速物理广播与完整性校验**
   - Server 启动新轮次并冻结参与客户端名单，调用 UFTP 启动模型广播。UFTP 数据包直接由底层以设定的高阶 MCS（如 MCS 7）在空口广播发送；
   - 链路层周期性开放反向控制窗口，Client 回传接收切片状态；
   - 只有当所有预期客户端均完整接收模型文件后，Server Runtime 才越过**下行完成屏障**；Client Runtime 对模型文件进行 SHA-256 摘要校验，验证无误后触发本地训练。

2. **上行阶段：令牌门控防撞与原子上传**
   - Client 完成本地训练并生成包含哈希摘要的 `update manifest`；
   - 客户端链路层向服务端发出 `READY` 就绪声明，加入调度活跃队列；
   - Server 令牌调度器按顺序向客户端发放独占的 `GRANT` 令牌；
   - Client 仅在持有有效令牌期间，通过 HTTP PUT 管道流式上传 update 数据（遵循 `100 Continue → 写入并校验 Hash → 201 Created` 原子落位流程），彻底杜绝多节点并发盲发引发的空口碰撞。

3. **全员收齐与模型聚合**
   - Server Runtime 持续跟踪本轮 update 到达情况。当且仅当全员合法 update 全部完成落盘且 SHA-256 校验一致时，触发模型聚合算法并持久化轮次成功终态，平滑步入下一轮训练；
   - 若发生超时或不可恢复的节点故障，系统触发确定性失败保护，避免残缺或损坏数据污染全局模型。

**[F2 占位：WFB-FL 端到端 FL 轮次全生命周期与时序运作图]**
> *图 F2 论证职责*：展示一次标准 FL 轮次的端到端完整时序流，涵盖下行高速广播、反向状态窗口、上行 Token 门控调度、HTTP PUT 原子上传以及全员收齐聚合的关键状态转移。

## 第 5 节 Discussion and Open Challenges（约 600 词）

### 实验洞察与核心结论回声

WFB-FL 平台的实验证据给无线联邦学习研究带来了关键启示：无线空口绝非不可见的静态管道，通过在消费级硬件上开放 monitor 模式与 raw frame injection，研究者能够以极低成本获得对底层物理空口的完全控制权与精确观测能力。通过跨层传输契约与令牌调度的联合设计，广播信道的高吞吐优势可以被安全、可靠地释放给 FL 模型分发，从而在真实物理世界中显著加速联邦学习的端到端收敛。

### 平台当前边界与客观约束

为保持严谨的科学态度，WFB-FL 的当前实验结论受以下系统边界约束：
1. **硬件与节点规模边界**：当前验证基于中小规模边缘集群（若干台搭载 802.11 网卡的节点），更超大规模节点的 Token 调度扩展性仍待进一步评估；
2. **射频芯片与驱动异构性**：当前观测数据依赖于特定 802.11 芯片（如 Atheros/MediaTek）的开源驱动 Radiotap 格式，不同芯片厂商的元数据完整度存在细微差异；
3. **发射功率旋钮前置约束**：`txpower` 显式编程接口的完整集成与自动化校准是后续定稿投稿的前置工程任务；
4. **统计外推边界**：实验展示的是特定物理配置下的稳定统计规律，不直接等同于任意复杂工业无线环境下的普遍性能表现。

### 开放研究挑战与演进方向

基于 WFB-FL 平台，未来无线 FL 研究可在以下开放方向展开探索：
1. **跨设备与新频段泛化（Hardware & Spectrum Generalization）**：将 WFB-FL 底座扩展至 Wi-Fi 6/6E/7（802.11ax/be）以及更多低成本嵌入式 SOC（如 ESP32、树莓派原生 Wi-Fi），探索 6 GHz 频段下的空口可编程特性；
2. **智能化自适应空口调度（Adaptive Cross-Layer Control）**：利用 RX_ANT 实时射频观测反馈，设计由算法层驱动的自适应空口参数自调节机制（根据模型层重要性动态调整 MCS 与 FEC 冗余）；
3. **自动化持续集成评测床（Automated CI/CD Benchmark Bed）**：将 WFB-FL 构建为标准化、支持远程提交作业的云原生无线 FL 物理测试基准平台。

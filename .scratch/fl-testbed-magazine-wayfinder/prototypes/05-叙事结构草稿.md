## 系统定位（替代"技术对手对比"框架）

本 testbed **不是**又一个 FL 框架，**不**与之比性能/泛化/benchmark 容量。本 testbed 在 FL 工具生态的位置：
- FedScale/Flower 提供"现实数据 + 规模 + 仿真 trace"，但它们的无线是 trace/仿真，不暴露真实空口；
- FedComm 是应用层协议 benchmark，网络条件作为受控 profile，不到空口物理层；
- 跨国 MQTT FL testbed 是真实端到端，但走 Internet + MQTT，不可控无线链路、不报物理层行为；
- 本 testbed 填的缺口：把真实广播无线空口变成可控制、可测量、可重复的实验载体。

四大工具仍按 map Notes 在第 2 节末"系统定位"段被引用，但**不画对比表、不做性能对照、不占图表名额**。

## 中心论点（候选，对齐系统定位）

> 真实无线空口在主流 FL 平台里被抽象成不可见、不可控的可靠管道；我们把它解放出来，做成可控制、可测量、可重复的实验载体——用一个可编程真实广播空口 testbed 与基于契约的验证方法实现，并以代表性实验刻画空口行为对 FL 轮次的影响。

记忆点候选：把无线空口从 FL 抽象层下面拿出来，做成可复现的研究载体。

## 逐节论什么

### 1. Introduction（~650 词）
- FL 在数据中心成熟，部署到真实无线空口时，链路层行为静默改变训练动态。
- 主流 FL 平台把空口当不可见、不可控的可靠管道（trace/仿真/Internet）。
- 但要系统研究"空口行为如何影响 FL"，研究者缺一个**可控制可测量可重复的真实空口实验载体**。
- 我们提出：可编程真实广播空口 testbed + 契约式验证方法，并以代表性实验刻画影响。
- 贡献声明（三项）：①可编程真实广播空口 ②跨层 testbed 与验证方法 ③代表性实验洞察。
- 不写"我快/我强"——只写"把不可见不可控的一层变成可见可控可复现的研究载体"。

### 2. 为什么需要一个可编程无线空口 testbed（~900 词）
**A. 缺口（窄、抽象，不列具体载体）**
- 真实无线空口行为（链路配置→FL 训练动态）是 FL-over-wireless 研究的关键变量，但当前研究载体要么把它吞掉（仿真/trace）、要么不可控（实测但参数静默）、要么获取成本太高，研究者缺一个能把真实空口拿出来做受控实验的载体。
- 一两句抽象论断即可——具体载体为什么不行/行留给 B，A 只起逻辑入口作用，不再枚举载体。

**B. 载体选择（实体论证，全节唯一一次展开）**
- 三个候选载体逐一考察（实体论证只此一处）：
  - 普通 Wi-Fi：广播/组播受限（无 ACK、低速率、可靠性差），FL 一对多场景实际退化为一对一，训练器拿不到可观测、可控制的广播行为——不能当可复现研究载体。
  - SDR 自建 5G 基站：能细控但成本/复杂度过高，普通研究组难以重复部署。
  - 可编程广播空口：现成网卡 + raw injection + monitor + 射频旋钮，把广播做成可观测、可复现、可控制的实验面——落到本 testbed。
- 本 testbed 不与普通 Wi-Fi 比"快"，不与 5G 比"强"——比的是研究载体的**可控性、可测量性、可重复性**。

**C. 系统定位（一段 ~120 词，替代对比表，与 B 不重复）**
- 落地本 testbed 在 FL 工具生态的位置：FedScale/Flower 提供现实数据与规模但无线是 trace/仿真；FedComm 是协议 benchmark 但不到空口物理层；跨国 MQTT testbed 真实但走 Internet、不可控无线链路；本 testbed 填真实广播空口做成可控可测可重复实验载体的缺口。
- 这是**定位**，不是性能对照；与 B 分工——B 讲物理载体选型（Wi-Fi/SDR/广播空口），C 讲软件生态位置（FL 框架/testbed 工具），两者对象不同不重复。

学术动机承载：本节同时承载 Notes 里"广播空口暴露的系统问题作为学术动机"——在 A 抽象缺口中点出"链路配置→FL 训练动态"这一静默影响作为动机要素，不是主轴实体论证。
避免：不与普通 Wi-Fi / 5G 比性能；不与 FedScale/Flower 比功能数量；不做性能对照暗示。

### 3. 跨层 testbed 架构与可编程空口（~1100 词）
- 渲染 testbed**本身**的架构与能力面——五层架构 + 下行完成屏障 + 上行收齐边界；各层在哪儿、可编程空口有哪些旋钮、RX 观测面在哪。是系统"有什么/能做什么"的设计层渲染，**不是贴代码实现**（不展开函数签名、不贴代码片段）。
- 可编程空口能力面（由 T1 承载）：`--link-id`(信道)/`--radio-bandwidth 20|40`/`--radio-mcs-index 0-31`/`--radio-short-gi`/`--fec-k/--fec-n`/队列水位/`--grant-duration-ms`/`--guard-interval-ms`/反馈窗口/方向流/**发射功率**（按裁决 b 保留该行，前提=系统侧补 `txpower` 旋钮实现，属本地图外部前置依赖）。
- 这些旋钮是第 2 节论证的"可控可测可重复"载体承诺的兑现。
- RX 侧观测面：RX_ANT（freq/mcs/bw/rssi min-avg-max）是唯一射频观测面，承载"可测量"承诺。
- **Transport 契约**在本节只作架构里的**一层命名一句带过**（架构中有一层负责 transport 交接），**不展开其契约定义**——契约内容留给第 4 节。
图表：F1 架构对比图（钩子）+ T1 能力矩阵表。

### 4. 基于契约的验证方法（~450 词，去数据化、瘦身）
- 第二贡献是**验证方法学**——回答"本 testbed 怎么保证可复现、可信任"，与第 3 节"系统长什么样"和第 5 节"在本载体上回答什么研究问题"三方分工。
- "基于契约的验证方法"具体指：本项目把跨层各层间的交互定义成明确的不变式接口，叫做**契约**；然后用分层验证拓扑逐层核查这些契约。
- 第 3 节只命名 Transport 契约这一层，**契约的定义与验证在这里展开**：
  - Transport 契约：UFTP closed group、HTTP PUT、Content-Digest、100 Continue、201 Created 是不变式。
  - 轮次语义契约：完成屏障、收齐边界是不变式。
- 分层验证拓扑：契约层单元核查 → 全流程 netns 验收（UDP 替代空口）→ 真实空口实验，三层对应不同验证目标与边界，明示每层**验证什么、不能证明什么**——契约层验语义不变式、netns 验端到端流程、真实空口验物理行为，三层互不替代。
- 契约是可复现性的载体——把"testbed 可复现"从一句声明做成可分层核查的方法学。
- **不引用**通过/失败/性能数据；可用一句就绪陈述说明本方法已在仓库以契约与脚本实现（按用户裁决②的保守版），不展开数字。
图表：F2 完整轮次时序图（含故障路径 + 分层验证标注）。

### 5. 代表性实验设计（~1150 词，去数据化、定位为设计）
- **诚实姿态**：实验在建，本节陈述已规划的最小实验集、研究问题、变量、指标与重复性口径，非现成性能数字；占位结论待正式实验跑出后回填。**不引用**任何现存开发测试脚本/log/ppt 面板数字作正文证据。
- 能力展示矩阵：每个旋钮冒烟验证（参数被接受 + 射频旋钮有 RX 佐证），结果折叠进 T1 表新增列（占位）。
- 实验一：MCS 生效与可重复。研究问题=空口旋钮是否真正到达链路并产生可观测差异；设计=3 设置 × 5-10 重复，记录发射配置 + RX 观测 + 端到端结果，以中位数/IQR 汇总。
- 实验二：端到端 FL 轮次。研究问题=空口配置是否沿"链路行为→文件完整交付→FL 轮次进度"传递；设计=从实验一选 2 配置、多客户端多轮，采集 round latency、wall-clock time-to-accuracy 等端到端指标。
- 单一贯穿场景 vs 多场景并列：本工单裁决——采用"两个代表性实验故事"并列展示（让 04 工单遗留的雾从 map Not yet specified 毕业）。
- **实验的角色不是"我比 X 性能好"**，而是"本载体让以下研究问题可以被回答"——对齐系统定位。
图表：F3 testbed 实物/拓扑图 + F4 链路结果（占位）+ F5 端到端轮次结果（占位）。

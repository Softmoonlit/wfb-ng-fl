## What to build

在第一版正式主线闭环之上，验证 `Client -> Server` 方向的 `TCP per-client 上行` 能够通过 Token Passing 门控稳定完成一个小文件传输，并保持端到端内容正确。

这个纵向切片的目标不是证明某个内部调度细节，而是从外部行为上证明：当客户端上行发送权受 Token Passing 控制时，标准 TCP 仍能通过 `TUN` 设备和链路层形成正确的可写信用 / 反压语义，不发生静默损坏。完成后，应能从客户端发起一次小文件上传到服务端，并验证接收结果与原文件一致。

## Acceptance criteria

- [x] 在第一版正式主线的单客户端不对称 Token 拓扑上，新增 `Client -> Server` 的 TCP 小文件传输验收步骤。
- [x] 传输使用标准 TCP 会话穿过 `TUN` 设备边界，而不是替换为其他业务协议或测试捷径。
- [x] 上行传输过程中，客户端发送路径仍保持 Token Passing 门控配置。
- [x] 服务端成功收到完整文件，且内容与客户端源文件完全一致。
- [x] 该验收步骤可以被自动执行，并纳入第一版独立验收脚本的成功判定。

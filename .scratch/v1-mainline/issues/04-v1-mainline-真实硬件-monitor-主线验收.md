## What to build

为 `v1-mainline` 新增一个独立的真实硬件 `monitor` 模式主线验收 issue，用于验证当前已经在 `wlan emulation` 下通过的单客户端不对称 Token 主线，在真实 `monitor/injection` Wi-Fi 网卡参与的无线链路上也能够成立。

该验收必须保持与当前 `tests/acceptance/v1_mainline.sh` 相同的主线语义：继续使用 `TUN/IP` 边界、split-process 形态（`wfb_tun`、`wfb_tx`、`wfb_rx`）以及“`Server -> Client` 常开、`Client -> Server` Token 门控”的不对称 Token 策略；唯一替换的是底层链路介质，从本机 `wlan emulation` 改为真实 `monitor` 模式无线网卡。

该 issue 聚焦单客户端拓扑下对 `issue01 + issue02 + issue03` 的真实硬件补充验收：双向 `ping`、上行 TCP 小文件传输、下行 TCP 小文件传输，并要求生成可审计留痕，明确证明数据路径确实经过真实 `monitor` 模式网卡，而不是回退到旧 `wfb_core` 路径或本机仿真链路。

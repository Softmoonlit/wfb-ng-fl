## What to build

在第一版正式主线闭环之上，补充验证 `Server -> Client` 常开方向的小文件 TCP 传输，确认不对称 Token 策略下的下行路径能够独立稳定工作，并且不会与上行门控配置产生错误耦合。

这个纵向切片聚焦下行阶段的端到端外部行为：服务端在不启用 Token 门控的前提下，通过标准 TCP 穿过 `TUN` 设备向客户端发送一个小文件，客户端能够完整接收且内容正确。它作为第一版的补充增强验收，用于证明常开下行路径与上行门控路径可以在同一主线边界内共存。

## Acceptance criteria

- [ ] 在第一版正式主线的单客户端不对称 Token 拓扑上，新增 `Server -> Client` 的 TCP 小文件传输验收步骤。
- [ ] 下行传输过程中，服务端发送路径保持常开配置，不启用 Token Passing 门控。
- [ ] 传输使用标准 TCP 会话穿过 `TUN` 设备边界完成。
- [ ] 客户端成功收到完整文件，且内容与服务端源文件完全一致。
- [ ] 该验收步骤可以被自动执行，并且不会破坏双向 `ping` 与上行 TCP 验收结果。

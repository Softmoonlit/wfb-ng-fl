# 定义 Web 在线节点展示与失联作业呈现

## Question

Web 怎样只展示和提供选择在线客户端，同时准确呈现当前作业参与节点失联以及重新上线的事实？

决定在线列表和目标选择控件的更新方式、节点重新上线后是否恢复选中、提交前状态变化的反馈，以及在线但尚不满足训练条件的展示。在线判定复用服务器权威心跳事实，训练所需数据与依赖就绪作为后续作业接入的独立检查，不让浏览器自造节点状态。

明确离线节点从在线列表移除后，其身份与失联原因在当前作业状态或事件中怎样保留。列表过滤不得改变已冻结参与集合、丢弃正在等待的 update，或把失败任务伪装成少节点成功。

若需要交互原型再使用 prototype 技能；本票先确定行为，不扩展成节点管理后台或历史归档浏览。

## Context

- [真实 FedAvg 训练规划](../map.md)规定在线列表移除离线节点，作业事实仍保留。
- 当前快照具有 online 与 readiness，页面渲染全部节点，目标输入仍是文本框。

## Answer

### 权威事实与领域区分

在线判定复用 Server Daemon 的有效心跳事实和控制台权威快照，浏览器不自造节点心跳门限，不以管理连接是否可达推断无线客户端是否在线。保留现有服务器在线判定，本票不调整心跳周期或离线超时。

区分三个集合：在线客户端是当前可观察的在线节点；选择草稿是操作者尚未提交的目标意图；作业受理后的固定参与集合是后端已接受的作业事实。三者不能相互覆盖。在线不等于基础就绪，基础就绪也不等于已经通过当前训练任务的数据、GPU 和依赖检查。

术语“在线客户端”和“作业候选客户端”由根目录 `CONTEXT.md` 拥有。本票决定展示与选择行为，具体训练准备检查及跨层承载由训练作业契约票接入。

### 在线列表与选择入口

节点列表及新作业目标入口只显示在线客户端，按节点编号排列；离线节点从这两处移除。Server 自身继续由服务端状态区呈现，不混入客户端选择。

在线但尚未待命、基础未就绪或存在阻塞错误的节点继续可见，显示服务端状态及已知原因，但禁止选择。在线且待命、基础就绪者可作为作业候选；没有训练检查事实时不能显示“训练就绪”。训练所需数据、GPU 和依赖检查继续在作业准备阶段完成，不为本票新增持续后台训练能力探测。

以勾选控件替代逗号分隔目标文本框，去掉手工输入任意节点编号和状态刷新时自动填入在线节点的旧路径。首次打开不选中任何节点，新节点上线不自动加入选择。用户显式勾选后才形成目标草稿，没有选中目标时不提交空集合。

### 选择草稿的更新与生命周期

收到服务端新快照时，保留仍有效的勾选。已选节点离线或变成基础不可选时，取消该节点勾选并提示原因，其他有效选择保留；节点恢复可选后仍处于未选状态，不自动选回。

上述变更只作用于尚未提交的草稿。请求已发出后，后端裁决的是该次提交的完整目标，页面刷新不能悄悄改写它；请求受理后只按服务器作业快照呈现实际参与集合。

草稿只保留在当前页面，不增加浏览器持久存储或服务器保存选择的功能。页面内状态刷新、同一服务实例的 SSE 重连保留有效勾选；整页重载、关闭重开或发现 Server 实例变化时清空选择。已有运行作业依服务器快照恢复，不依赖页面草稿，不重新提交启动请求。

### 提交竞态与错误反馈

浏览器候选过滤不能代替服务端的提交校验。操作者提交时若任一目标已离线或不可接受作业，后端整体拒绝，页面显示逐节点原因并刷新候选事实；不得自动剔除失效目标后启动较小集合，也不自动重试。

逐节点反馈复用已有 `preflight_target_nodes_not_ready` 和 `unready_nodes` 等结构化事实，不仅丢弃细节显示一条泛化错误。操作者依据新状态确认并再次提交。服务端正式受理后的失败或准备超时则属于已有作业的生命周期，不能伪装成从未受理的表单校验失败。

### 当前作业的失联与重新上线

离线过滤不改变当前作业已冻结的参与集合，不丢弃其期望 update，也不允许少节点成功。作业详情保留全部参与者身份，标明服务端已知的当前在线／失联状态及原因，并记录关键失联事件。心跳超时只证明未持续收到有效心跳；没有证据时不编造断电、网卡故障或具体物理原因。

参与者重新上线后更新其当前在线事实，但不擦除此前的失联事件或已经形成的作业失败。在线恢复不代表训练已恢复，更不能使已失败作业重新变为运行。作业终态后的已有最近作业视图继续保留相应终态和失联摘要，不扩展历史作业数据库或归档浏览。

作业参与者的状态必须可从服务端快照恢复，不能只靠浏览器临时列表或有限事件回放重建。关键事件沿用现有有限保留边界，不新增永久事件存储，也不让周期心跳刷屏。

当前实现中，心跳 registry 的 OFFLINE 变化尚未直接接入运行作业的失败处理；本票不把该缺口冒充已实现能力。严格同步失败与终态恢复由后续训练作业契约落实，浏览器只展示后端裁决，不自行将离线判断转换成作业成功或失败。

### 管理连接中断与恢复

管理连接中断和 HTTP 404 不同：404 表示服务器返回所请求资源不存在；网络断开、连接拒绝或超时可能没有 HTTP 响应。已加载页面不应在状态获取失败时把全部无线客户端标为离线，也不凭空切成 404 页面。

无法取得有效最新状态时，保留最后一份快照并明确提示“无法获取最新状态／状态可能已过时”，暂停启动新作业。提示管理状态不可用不代表后台训练已停止。取得有效新快照后重新按服务器门禁和有效选择决定能否启动。

保留现有 SSE 与 HTTP 状态轮询：SSE 单独中断但 HTTP 轮询仍成功时，使用轮询取得的有效状态并保持可操作性，不因单一路径失败而统一禁启。同一实例恢复连接后按新快照更新节点和作业，并依上述草稿规则处理选择；实例变化时清空草稿。

# 确定真实 FedAvg 参考任务与效果判据

## Question

第一版采用什么数据集、模型与训练环境，怎样证明现有 Stage 4 文件闭环已经扩展为真实、正确且能连续运行的同步 FedAvg？

需确定参考数据集及其来源、模型与训练框架、目标客户端运行条件、本地训练与服务端评估位置、样本加权口径、最小完整轮次及效果判据。训练函数和聚合函数是否已经存在且可在目标机器运行，由 agent 核对源码和依赖事实，不要求用户代查。

区分训练发生、聚合数值正确、下一轮使用聚合模型与模型效果四类证据；不预先承诺某个准确率或单次 loss 单调下降，不以文件复制、文件变化或通信成功代替训练证据。

只决定一个明确的参考任务和必要扩展入口，不设计任意算法插件平台。

## Answer

### 参考任务与角色规模

采用 MNIST 手写数字 0～9 分类作为首个真实 FedAvg 参考任务。目标为 Jetson Orin Nano 开发板，共 5～8 块，包含 1 个服务端与 4～7 个客户端。最终实机数量在运行前按可用硬件确定，记录实际节点清单；单次作业参与集合固定，不因失联自动缩减。不要求现在确定精确板数，也不将已有三端 VM 文件闭环当作本任务的完成证据。

### 数据来源与准备

使用 MNIST 官方训练／测试划分，分别为 60,000 张训练图片与 10,000 张测试图片，数据来源采用 MNIST 官方发布数据或可核对到相同原始内容的镜像。数据在部署准备阶段预置，运行时不依赖在线下载。具体本地数据接入与检查边界由[确定首版 MNIST 本地数据最小接入](02-client-dataset-library.md#answer)拥有。

每个客户端预置相同完整官方训练集，服务端预置官方测试集。客户端执行本地训练，服务端在训练开始前及每轮聚合后评估全局模型。测试集不参与训练、梯度更新或模型平均；已冻结的参考配置不使用本次验收测试曲线反复选择超参数后再作为独立效果证据。

本次不实现服务器指定数据划分、样本区间或索引下发。客户端之间的训练样本重叠是有意简化的参考条件；该任务验证真实训练与通信编排，不据此证明不同数据分布、数据多样性或增加独立样本带来的收益。

### 模型、训练框架与轮次配置

| 项目 | 决议 |
| --- | --- |
| 模型 | 两层卷积加分类层的小型网络，输出 10 类，不使用预训练权重；首版实现固定并记录唯一模型结构，不增加 Web 任意结构配置 |
| 计算框架 | PyTorch；Jetson 客户端在 GPU 上执行真实前向、反向和参数更新 |
| 全局轮次 | 5 个完整同步轮次，每轮等待固定参与集合的全部有效更新后聚合 |
| 本地训练 | 每轮从本轮全局模型开始，将本地完整训练集训练 1 遍，即 1 个 epoch |
| 批大小 | 64，保留末尾不足一个批次的样本 |
| 优化器 | SGD，学习率 0.01；参考起点不使用动量和权重衰减 |
| 评估 | 服务端记录初始模型与每轮聚合模型的官方测试集平均分类损失和准确率 |

卷积通道数、激活、图像归一化、损失函数和初始化等模型实现细节需在参考实现中固定并归档，不交给运行时隐式决定；采用普通分类损失并确保训练与评估预处理一致。记录初始化与数据加载随机种子、软件和设备版本，不能因种子相同就承诺跨设备 GPU 位级一致。

客户端 GPU 不可用或训练依赖不满足时应明确拒绝启动该 GPU 参考任务，不静默切换 CPU。服务端的参数平均只需要正确处理张量，不要求为少量聚合计算强制使用 GPU；服务端评估设备应在运行证据中记录。具体 JetPack、CUDA、Python、PyTorch 版本尚未取得实机证据；按[核实 Jetson GPU 训练环境与依赖约束](08-jetson-training-environment.md#answer)的后续用户裁决，以操作者确认的目标能力继续设计，将实际版本、GPU 可用性与训练验证移交部署阶段，不再作为训练接入设计前置。本决议不能代替环境就绪证明。

### FedAvg 与平台职责

保留本平台既有的文件交付和轮次能力。客户端通过现有模型等待接口获得模型文件，用 PyTorch 加载和训练，再通过现有更新提交接口交付训练后的模型参数。服务端收齐更新后执行样本数加权的 FedAvg，发布聚合模型供下一轮使用。PyTorch 不替代平台，也不会自动完成联邦学习编排；本次不引入第二套联邦学习运行框架。

聚合采用本轮本地训练后模型参数的样本数加权平均，权重为该客户端本轮实际使用的训练样本数除以本轮所有参与客户端样本数之和。样本数不乘全局轮数，也不按优化器步数计算。当前参考任务每端均为 60,000，因此等价于等权平均；仍保留真实样本数与权重记录，以便核验计算语义。

模型／更新文件格式、样本数传递位置、服务端聚合调用与多轮驱动的接入方式由[定义真实训练作业的算法接入与跨层契约](06-fedavg-job-contract.md)拥有。本票不裁决现行设计中服务端算法入口与 Coordinator 轮次所有权的冲突。

### 完成判据与证据边界

参考配置保持固定，至少完成一次包含实际全部参与客户端的 5 轮真实无线训练作业；不能将少节点试跑、仅通信成功或占位复制算作完整完成。稳定性重复次数、故障场景和最终归档组合由[冻结端到端验收边界与实施交接条件](07-acceptance-and-handoff.md)决定。

必须分别证明：

1. 客户端确实使用本轮模型与预置训练集在 GPU 上执行优化。记录节点、轮次、模型身份、训练样本数、优化器步数、训练损失与设备；只有文件变化不足以证明训练。
2. 每轮聚合使用了固定参与集合的全部有效模型及正确样本权重。对实际收到的参数作独立数值复核，浮点差异使用记录在验收口径中的合理容差；只记录聚合函数被调用不足以证明数值正确。
3. 后续轮次客户端加载的是上一轮实际聚合得到的模型，保留发布与接收模型的身份关联证据。
4. 在相同官方测试集和评估口径上，记录初始值与每轮结果。第五轮全局模型的测试准确率高于初始模型，测试平均损失低于初始模型；不预设固定高准确率，不要求每轮指标单调改善。指标非有限值或结果未改善时如实判失败并保留证据，不用重复挑选成功运行来替代判据。

以上是已确认的规划决策，尚无真实训练执行或硬件效果数据。后续若证据证明参考参数需要改变，显式修订并记录配置，再重新验证，不能事后改写当前运行的判定条件。

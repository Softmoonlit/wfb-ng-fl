# 定义算法可调用的无线配置接口与轮次间重配边界

## Question

服务端算法怎样在作业开始前或完整轮次之间请求改变无线配置，并获得准确的完成或失败结果，同时保持网卡和链路由守护进程统一管理？

决定支持字段、集群级与节点级作用范围、调用位置和返回语义，以及该接口怎样接入 Coordinator 的轮次边界。按用户最新裁决，信道由操作者在集群空闲时设置并保存，算法不能修改信道，作业启动与轮次推进不自动选信道；算法增加全网统一的 HT 20／40 MHz 带宽配置。请求带宽与已选信道不兼容时明确拒绝，不自动换信道或降低带宽。信道一致性和发射参数的作用范围分别处理，不把全部属性都定义成任意节点可独立修改。

核对现有重配的空闲门禁、双最终屏障、租约、客户端任务链路所有权、心跳寻频和速率约束。决定轮次间进入重配前需要确认什么、哪些运行资源需要暂停或重新配置，以及部分成功、失联和急停时如何结束作业与恢复资源。不得简单删除空闲检查或让算法直接调用 iw 来绕过所有权。

不包含传输过程中的切换、自主调参、自动选信道或未提出的 PHY 参数扩展。若现有契约之间出现冲突，明确记录并交由用户裁决，不能静默覆盖。

## Context

- [真实 FedAvg 训练规划](../map.md)已经采纳开始前与完整轮次之间调用的目标。
- 当前实现只允许空闲集群重配；服务端常驻链路与客户端任务链路生命周期不同。
- 读取无线物理层、跨层和链路专题，并核对当前 radio、control、daemon、Coordinator 调用路径。

## Answer

### 权限、参数与作用范围

算法可以在作业开始前和完整轮次之间请求配置，但不能直接操作网卡、调用 `iw`、启动链路进程或绕开守护进程所有权。信道由操作者根据现场测量，在集群空闲时设置并保存；算法接口不含信道字段，作业启动与轮次推进不自动选信道。客户端寻找服务端已设置信道、重新入网和配置对齐的能力保留。

首版开放以下逻辑字段，不增加节点级覆盖：

| 配置 | 取值或规则 | 作用范围 |
| --- | --- | --- |
| `radio_txpower_dbm` | 10～20 dBm | 服务端与全部客户端使用同一值 |
| `downlink_mcs` | 3、4、5、6 | 服务端下行发射 |
| `uplink_mcs` | 3、4、5、6 | 全部客户端使用同一值 |
| 带宽 | HT 20／40 MHz；具体序列化字段由训练作业契约票统一确定 | 全网统一，发射描述与网卡工作模式一致 |
| `uftp_rate_kbps` | 按带宽与下行 MCS 组合确定范围和默认值 | 服务端后续 UFTP 下行操作 |

FEC、GI 保持底座固定，不扩展 80 MHz、VHT、STBC 或其他尚未提出的 PHY 参数。请求带宽与操作者所选信道或硬件支持不兼容时，执行前拒绝，不自动换信道或降低带宽；当前信道黑名单和有效候选限制继续生效。

统一配置覆盖请求受理时全部在线客户端，包括作业参与者和待命节点。当前作业参与者必须全部包含，不能排除失联参与者以凑齐成功；尚未上线节点不阻塞该事务，随后按已生效配置重新入网和对齐。请求受理后目标确认集合固定。

### 算法调用和轮次边界

采用作业绑定的同步调用，概念形式为 `configure_radio(patch)`；算法只提交增量配置并等待结果。具体入口装配、字段传递和结果对象接入由[定义真实训练作业的算法接入与跨层契约](06-fedavg-job-contract.md)落实，不在本票另建插件系统或改变 Runtime 文件 manifest。

初始配置在客户端任务启动前执行，成功后才发布和启动任务。轮次间调用在本轮聚合、评估完成后及下一轮模型发布前执行；Coordinator 在请求进行期间禁止发布下一轮模型。配置与必要运行资源均确认就绪后才允许成功返回。

轮次间重配屏障必须确认：服务端没有未完成的模型发送或上传处理；全部作业客户端已收到本轮上传成功结果、结束本轮 `submit_update` 并进入下一轮等待，且明确确认可重配。服务端收齐 update 或完成聚合本身不能代替客户端确认。等待、确认和恢复均有期限，缺失确认不得解释为成功。

屏障内暂停新的任务数据交换，保留必要控制通信；算法进程、Runtime、TUN、任务接收器及客户端任务链路继续保留。守护进程仍拥有物理网卡，客户端任务链路与空闲链路不得并存拥有同名 TUN，不通过另启空闲链路绕过门禁。

### 本机在线应用与集群事务

复用 `wfb_tx_cmd` 背后的发射配置更新能力并接入 `wfb_v6_uplink`，不以调用现有 CLI 已经能够配置 v6 为前提。现有 CLI 的全量设置语义也不能直接充当算法的增量接口：守护进程先合并、校验完整目标配置，再交给受控底座应用。

MCS 更新不重启链路；带宽更新同时协调各端网卡工作带宽与帧发射描述。功率仍通过网卡配置接口应用；UFTP 速率用于后续下行操作，不在正在传输的操作中替换。v6 数据帧和调度控制帧的独立发射配置均须纳入一致更新，不能仅更新其中一条路径。

本机命令成功只证明本机配置更新步骤完成，不能代替远端生效、集群确认或资源就绪。保留已有 PREPARE、COMMIT、FINALIZED、CONFIRMED 事务和租约边界，显式扩展运行期应用能力及轮次间门禁，不仅删除“空闲集群”检查。

### 注入速率规则与标定前置

范围和推荐值按“带宽、下行 MCS”组合维护。改变带宽或下行 MCS，且请求省略 `uftp_rate_kbps` 时，采用新组合的推荐值；显式指定速率则按新组合校验，不合法直接拒绝。仅改变功率或上行 MCS 时保留下行速率。结果包含最终实际选择的速率。

现有仓库只有一套源自 40 MHz 配置背景的 MCS 速率表，不能当成已经支持两种带宽的证据。20 MHz 具体范围和推荐值由[标定 20 MHz 下行注入速率范围与推荐值](09-20mhz-uftp-rate-calibration.md)取得真实硬件依据后补齐，禁止将未经验证的按比例折算数字写成安全范围。标定任务阻塞训练作业契约与最终交接的冻结，不阻塞本票的权限、调用边界和失败规则结单。

### 完成、错误与停止作业

同步结果或结构化错误须能区分请求身份、请求及目标配置、事务状态、失败阶段、目标与未确认节点、已确认的生效配置，以及资源恢复事实。实际配置无法确认时明确表示未知，不能用缓存目标值证明全网已经生效；不可逆提交后可以记录本端保留的新配置，但仍须保留缺失的远端确认。字段名和对算法／Web 的承载由训练作业契约票落实。

执行前参数错误直接拒绝，不改变配置和资源；算法可以按错误处理请求。开始跨节点协调后失败则结束当前作业，不自动续训，初始配置失败则不启动训练。已完成轮次的结果保留，作业结果与资源恢复状态分别记录。

算法配置在不可逆提交前失败，恢复变更前完整配置，保持操作者所选信道；不沿用现有统一退回基准信道 157 的算法失败路径。回退本身无法确认也必须保留错误，不能报告已恢复。操作者空闲期切信道仍使用单独的切信道恢复机制。不可逆提交后确认不完整则保持已提交的新配置并进入 `RADIO_ERROR`，不擅自回退，不开始下一轮。

保留现有人工“停止作业”能力，不新增硬件紧急断电功能。停止请求唤醒正在等待的屏障并禁止下一轮：不可逆提交前停止推进并尝试恢复原配置，提交后保留新配置；随后按作业终态路径回收任务资源。缺失配置确认或资源恢复确认如实保留。页面和记录区分“请求已受理”与“资源恢复完成”，不承诺全部节点瞬间停止。

### 生效配置的保留

正常完成或普通训练失败后，保留最后一次成功生效的无线配置，后续作业沿用直到再次显式修改；不在每次作业结束后额外执行恢复初始配置的事务。重配本身失败仍按上述事务边界收尾。该规则适用于守护进程持续运行期间；服务重启以操作者保存的启动配置为依据，不把算法调整自动写成永久启动配置。

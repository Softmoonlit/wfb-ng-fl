全部验收与交接决策已通过本票三轮交流确认，地图内没有未解决的决策或无法表述的 fog。按用户最新要求，收尾仅交付决议和地图，不生成正式 `spec.md`、实施任务或占位文件；此前关于后续生成这些文件的计划由本次明确指示暂缓。路线已收敛与规格／实施交付完成是不同事实。

产品与跨层调用规则沿用[训练作业契约决议](06-fedavg-job-contract.md#answer)及其指向的六篇设计专题；本票拥有验收组合、数值标准、证据与实施顺序，不另立一套算法或传输接口。历史 Stage 4 规格不重开，也不被真实训练决策冒充为已实现。

### 真实硬件与成功运行组合

沿用[参考任务](01-fedavg-reference-task.md#answer)：1 个 Jetson Orin Nano 服务端与 4～7 个客户端，实际数量部署时确定并记录。同一验收组合固定参与集合、初始模型、数据及训练参数；客户端 GPU 训练，服务端记录实际评估设备。逐节点环境与依赖在部署阶段确认，不要求当前提供板子或编造版本、耗时。

连续完成三次各含五个完整同步轮次的真实无线作业：

| 作业 | 轮1 | 轮2～3 | 轮4～5 |
| --- | --- | --- | --- |
| 第一次 | 40 MHz | 40 MHz | 40 MHz |
| 第二次 | 20 MHz | 20 MHz | 20 MHz |
| 第三次 | 40 MHz | 20 MHz | 40 MHz |

第三次在第1轮和第3轮聚合、评估后，完成轮次间屏障再重配。按预先冻结的合法方案覆盖统一功率、上下行 MCS、注入速率修改、组合推荐值与显式值校验；不遍历全部参数组合。信道由操作者在空闲时选择并保存，须支持上述带宽；全程固定，不自动选信道或降带宽。

20 MHz 正常运行前先完成[速率标定交付](09-20mhz-uftp-rate-calibration.md#answer)；标定允许通过受控入口为测量设置 HT20，不把这一操作当成已取得正常运行的速率依据。当前不填写未经验证的速率表，现有 40 MHz 依据也须核对其适用条件。

每次作业均须分别证明真实 GPU 优化、全员有效 update 的样本加权聚合、后续轮次加载实际聚合模型、初始及每轮评估。末轮准确率高于初始、平均损失低于初始，非有限指标或未改善如实失败，不要求逐轮单调或固定高准确率。M0→M5 的模型关联与末轮提交确认沿用正式契约，M5 保存不再额外广播。

三次之间通过正常清理恢复待命，不人工重启 Daemon。所有尝试保留记录；非预期失败不能通过挑选三次成功隐藏，修复后重新验证连续组合。刻意故障另记，不计连续成功次数。三次无线条件不同，不据此归因单项参数或提出吞吐门槛；记录实际吞吐与耗时即可。

### 独立聚合数值标准

首版模型参数为 FP32。对三次作业的每一轮全部实际收到的 update，校验来源集合、关联与内容摘要后，在 CPU 上通过独立路径以 FP64 重算 `sample_count / sum(sample_count)` 加权平均，逐个参数、逐个元素比较实际聚合结果：

```text
abs(actual - reference) <= 1e-6 + 1e-5 * abs(reference)
```

复核不调用生产聚合函数，也不复用其加权求和逻辑；相同的文件读取／格式检查能力可以共用。键、形状、dtype、身份或有限性不符直接失败，不能通过容差放过结构错误。容差在验收前固定，失败后不能按观察结果放宽。结果保存实际输入和输出摘要、节点与样本数、权重、计算精度、最大误差、逐轮通过结论及复核工具版本。

参考任务各端实际样本数均为 60,000，真实作业中的加权与等权数值相同。因此另以可区分参数、1∶3 样本权重，对正式聚合函数执行一次受控计算核验，并与独立参考结果比较；它证明权重进入计算，不冒充真实训练，不加入数据划分、模拟训练或旧本机回归套件。

复核使用服务端实际保留的轮次 update 与聚合模型，在显式清理前完成，不依赖 Client 已删除的沙箱或 Runtime 重启后的结果重放。必要制品的持久备份见下文。

### 故障与 Web 最小边界

每个既定独立处理分支至少一次，不做全参数笛卡尔组合，不要求故障作业跑满五轮。故障预先指定并独立记录，尽量复用其状态完成 Web 检查，不重复完整训练。

| 范围 | 必须验证的分支与结果 |
| --- | --- |
| 准备 | 初始模型不合法、数据检查失败、GPU 不可用分别明确失败；GPU 不降级 CPU，首轮不发布 |
| update | 来源／轮序／基准模型关联错误、非法统计、非有限参数按契约拒绝，不跳过节点、不以旧数据聚合 |
| 运行故障 | 客户端训练异常、角色退出及参与者失联结束当前作业；固定集合不缩减，重新上线不恢复失败作业 |
| 期限 | 准备、完整轮次和传输 I/O 的期限各自能结束等待并清理；协作计算未退出不得报告恢复完成 |
| 停止作业 | 训练期间及无线不可逆提交前后分别处理；停止受理不等于全部节点已停止，后续轮次不发布 |
| 重配 | 提交前失败恢复变更前配置并保留信道；提交后确认不完整按协议保留新配置及 `RADIO_ERROR`，未知不能冒充成功 |
| Web | 在线过滤、基础未就绪禁选、初始空选、上线不自动加入、离线取消与恢复不重选、提交竞态整体拒绝、固定参与者失联、重载／服务实例变化、管理状态过时和 SSE／HTTP 单路可用按既定规则呈现 |

无线成功证据区分本机在线更新、受理时目标集合的全体确认和运行资源恢复；不能只采用 Daemon 缓存或 CLI 返回值。屏障须证明客户端已收到本轮上传成功响应、没有活动文件操作、下一轮尚未发布，期间保留任务资源；预期无线暂停由事务自身期限裁决。新节点与待命节点的对齐和目标集合规则沿用无线决议，不另改语义。

Web 初始与逐轮评估表、固定参与者准备／训练摘要及失败节点／阶段／原因须从权威快照恢复。执行、效果和恢复状态分别核对；管理连接中断不推断无线离线或训练停止，不增加曲线分析与多作业比较。

### 最终证据与保留

| 部分 | 内容与边界 |
| --- | --- |
| 总报告 | 真实节点清单、无线网卡／驱动、设备位置与环境、GPU／软件版本、代码版本、冻结配置／种子、所有尝试、逐轮模型关联与指标、数值复核、无线确认、故障与 Web 结果；关联原始证据位置和摘要 |
| 节点小型审计 | 沿用日志、配置、状态、结果摘要和 manifest，不把 Client 模型／update 本体加入白名单 |

材料备份到操作者指定的持久目录，不只引用 `/tmp` 等可能消失的工作路径；不要求通过带内控制面集中上传大文件或日志。完成复核、备份及摘要核对后，由操作者显式决定何时清理原文件，不增加自动过期或历史数据库。保留原始失败记录，不能只汇总通过结果。

环境、数据和依赖可在部署准备阶段处理；实际作业从受理到终态仍沿用无 SSH 依赖的带内控制与数据路径。旧文件闭环证据只按未改变的通信能力复用，不能代替真实 GPU 训练、实际聚合或本次双带宽重配证据。

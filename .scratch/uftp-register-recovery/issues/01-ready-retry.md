# UFTP 注册失败时的上行声明恢复

Status: ready-for-agent

## 问题与证据

2026-10-29 手动作业 `web-849186770bbc4c9daa1c32a6fb26a146` 前两轮完成，第三轮 UFTP 返回 7、`transport_failed`。fl02 已注册，fl01 接收器持续发送 REGISTER，但 Server 未在注册预算内收到。

Server native 在 GRANT seq=17490 后以两次静默窗口移除 node1；客户端有效授权停止，REGISTER 积压。重新声明依赖固定 4 秒重试，丢失一次声明可能形成约 8 秒的等待，超过本次约 7.2 秒 UFTP 注册期。后续诊断在 seq=22291 后复现相同移除，直到 READY 重入、seq=22335 后七份注册包集中到达。

## 修正范围

- 在现有 `pending && !authorized` 接缝，将 READY 未确认重试节奏改为每秒一次。它是控制包重试节流，不是调度周期估计或授权期限。
- 无积压或授权有效时不增发 READY；重声明复用现有幂等入队，不改变队列顺序。
- 不更改 UFTP 注册预算、单轮预算、静默移除策略、心跳参数、无线配置和目标 `[1,2]`。
- 使用已有真实 run_client / loopback UDP / socketpair TUN 接缝做 RED/GREEN；确认首个 READY 丢失后重试并获 GRANT 发数据。
- 不通过 TASK_ANNOUNCE 添加调度配置字段：重复 READY 已有幂等语义，重试节流不依赖参与容量。

#### 4. 自然并发与重叠区间观测

- **时序证据**：
  - Client2 于 `79516.560s` 发起 PUT，Client1 于 `79516.655s` 发起 PUT（相差仅 95ms）。
  - 自然重叠区间：`79516.655s` 至 `79561.156s`，并发重叠时长达 **44.50 秒**（占上行总时长的 81.9%）。
  - 服务端活动上传集合状态转移序列为：`[2]` -> `[1, 2]` -> `[2]` -> `[]`，严格收敛且无任何竞态冲突。

#### 5. 单次 I/O 进展与停滞超时审计

- 单次 I/O 停滞超时阈值严格锁定为 **120 秒**。
- 实测中 TCP 连接、HTTP 头部握手、数据块流式传输全程均在无停滞状态下推进，无任何单次 I/O 超时或空口挂死现象。
- 周期总耗时 85.73 秒，裕量超过 150 秒。

#### 6. 丢包、FEC 纠错与分源归因痛点验证

- **遥测全局计数**：
  - 服务端接收原始包数：38,517 包
  - 服务端接收原始字节数：121,995,455 字节 (~116.3 MiB)
  - FEC 成功恢复包数：4,517 包
  - 残余丢包数：1,022 包
  - 残余丢包率：约 **2.58%**（相比历史无新拓扑时的 15%~25% 发生显著改善）
  - 队列暂停与恢复：TUN 暂停 33,844 次，恢复 33,844 次，最终状态完全恢复（`pause_recovered: true`）。
- **痛点与后续支撑**：
  - 当前由于 `src/rx.cpp` 仅输出单一聚合的 `\tPKT\t` 统计行，无法识别这 1,022 个丢包中 Client1 与 Client2 各自贡献了多少包，也无法判断 USB 3.0 网卡在抗丢包能力上是否显著优于 USB 2.0。
  - 本基准测试成功建立了 40 MiB 单周期物理链路承载的基线数据，直接支撑 Ticket 02 交付 C++ 底座分源遥测，以便按源节点进行精准归因与后续射频调优。

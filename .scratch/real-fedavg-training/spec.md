# 真实 FedAvg 训练、受控无线配置与在线客户端控制台

## Problem Statement

现有平台已经具备常驻服务、无线带内控制、模型库、同步文件交付和 Web 作业入口，但正式作业仍以文件复制代替客户端训练与服务端聚合。操作者即使完成多轮文件交换，也无法证明客户端读取了真实数据、执行了 GPU 优化、服务器正确计算了 FedAvg，或下一轮使用了聚合后的模型。

研究者需要在已有通信底座上运行一个明确、可复核的真实训练任务，同时能够替换自己的训练与聚合代码。现有算法入口和 Coordinator 存在重复的服务端循环路径；基础资源 ready 也不能证明当前任务的数据、GPU 与依赖已经就绪。若只在文件闭环外加训练函数，仍会留下准备检查、失联、期限、停止和末轮资源回收的完成边界缺口。

算法还需要在规定边界调整无线条件。现有集群重配主要面向空闲状态，现有本机发射命令不能直接作为 v6 集群重配接口。没有轮次间暂停确认、双带宽组合速率校验与分阶段失败处理，就无法安全地将配置策略接入训练循环。

当前页面展示全部登记节点，目标选择可能被状态刷新自动填充，也缺少训练评估与固定参与者失联的完整呈现。操作者需要明确选择可用节点，并能区分在线、基础就绪、训练准备、作业结果与资源恢复；管理连接中断不能被误报为无线节点全部离线。

## Solution

在既有五层通信结构和常驻服务内接入首个真实 FedAvg 参考任务：Jetson Orin Nano 客户端使用 PyTorch GPU 训练小型 MNIST 卷积模型，服务器按实际样本数聚合，在初始和每轮聚合后评估，连续推进五轮。初始模型沿用模型库上传与摘要选择；各端直接读取预置的本地官方数据，不建设通用数据集库或服务器分区能力。

服务器通过显式配置选择客户端入口、聚合、评估及可选无线策略，作业受理时冻结配置。Coordinator 唯一拥有服务端发布、收齐和多轮推进，客户端入口拥有本地多轮循环。算法通过显式作业上下文报告准备与提交完成、检查停止及表达受控无线配置意图，Runtime 四个文件接口继续只承担文件交换语义。

信道由操作者在空闲时确定并保存。算法可在客户端启动前或完整轮次之间，同步调整统一功率、上下行 MCS、20／40 MHz 带宽与 UFTP 注入速率；守护进程负责参数合并、校验、暂停屏障、各端在线应用和最终确认。作业结果、效果结果与资源恢复分别记录。

Web 保留初始模型、目标客户端、轮数三个启动输入，目标改为明确勾选的在线候选。页面提供最小评估结果表、参与者准备与训练摘要、失败及恢复信息，并以服务器权威快照恢复视图。交付通过三次真实硬件五轮作业、独立数值复核及有界故障检查证明，不以文件复制、缓存配置或仅有命令返回替代完成证据。

## Implementation Decisions

### 既有基础与职责划分

- 本特性在现有常驻服务、模型库、Web、Coordinator、Runtime、Transport 和 v6 链路上演进。真实训练、评估、训练准备报告、双带宽在线重配及新结果展示属于待实现目标，不能因设计文档已描述就宣称产品已具备。
- Server Daemon 与 Client Daemon 保持物理网卡、链路和作业生命周期所有权。Coordinator 在服务端唯一拥有模型发布、全员收齐和多轮推进；客户端算法入口拥有本地训练循环。服务端算法函数只承担计算、评估与配置选择。
- 服务端算法在既有 Daemon 作业上下文中执行，客户端算法在 Client RoleService 进程内执行。不增加第二套联邦学习框架、独立算法进程、Runner、Runtime RPC 或插件注册平台。
- 正式训练路径直接清理文件复制、模板 update、固定大小假设、重复 server 循环和旧二参数客户端入口，不增加兼容分支。未完成接入时明确拒绝训练启动，不能回退为文件仿真成功。
- 继承既有 UFTP 下行、HTTP PUT／TCP 上行、严格同步、文件身份与提交完成契约。上层作业失败不能追溯改写已成立的 Transport 文件成功。

### 显式配置与算法调用

- 服务器显式指定一份算法 JSON 配置。必需字段为 `client_entry`、`aggregate_entry`、`evaluate_entry`、`algorithm_config`，可选字段为 `radio_policy_entry`。入口使用 `package.module:callable` 定位，参数为 JSON object。
- 各端预部署匹配代码及依赖。服务器须能导入服务端函数，客户端须能导入客户端入口；不下发 Python 代码、不动态安装、不依赖导入副作用启动任务。
- 操作者在集群空闲时切换配置。Server Daemon 受理时验证并冻结入口、参数、摘要、模型制品、参与者、轮数和期限；运行中修改配置文件不改变活动作业。
- Web 启动作业仍只提交 `model_sha256`、`target_nodes`、`rounds`，轮数默认 5，允许少轮试跑。算法配置位置由部署显式指定，不增加算法菜单、任意 Python 输入框或通用配置编辑器。
- Client Daemon 从冻结内容生成客户端算法配置，通过既有显式启动参数交给 RoleService；算法配置与基础设施配置分离。不把服务器本地目录当成客户端目录下发，也不通过命令行传模型、update 或 Runtime 结果。
- 客户端入口接收 Runtime、算法配置和作业上下文，正常返回仅表示本地作业循环结束。提前返回、完成轮数不足、异常退出均报告失败事实，不能据此宣告全局成功。
- 聚合函数接收当前模型、按节点索引的全部 update、宿主指定输出位置、算法配置和上下文；校验后原子生成新模型，正常返回空结果，不原地覆盖当前模型或托管 update。
- 评估函数接收模型、配置与上下文，返回 `metrics`、初始阶段的 `preparation`、末轮判定 `verdict` 及 `reason`。参考指标为有限 `loss` 和 0～1 的 `accuracy`；初始和中间轮判定未定，末轮为布尔值。Coordinator 执行算法返回的效果结论，不把参考任务阈值固化为所有算法的基础设施规则。
- 可选无线策略接收配置及上下文，可以不调整或完成一次同步配置调用。未配置策略时沿用当前无线配置；策略异常使作业失败。

### 作业上下文与原有文件接口

- 上下文显式绑定作业身份，提供只读节点身份、总轮数、本地轮序／阶段、必要本地配置、产物位置及已取得的评估／训练摘要。不得以隐藏全局变量或固定隐藏位置取得配置，也不暴露任意底层对象。
- 客户端检查后通过 `report_prepared` 报告准备结果；每次 update 提交成功返回后，通过 `report_round_complete` 报告从 1 开始的本地轮序，再等待下一轮。宿主负责绑定身份和可靠交付。
- 所有计算函数通过 `check_stop` 在准备、批次训练、评估、聚合等合理边界检查停止与期限，不吞掉停止信号继续推进。
- 只有服务端无线策略上下文暴露同步 `configure_radio`。算法不能调用网卡、链路进程、Transport、READY 或 GRANT 接口，不生成或操纵 Runtime 的 `round_id`。
- Runtime 保持 `publish_model`、`wait_for_model`、`submit_update`、`wait_for_updates` 四个本机文件接口，不新增业务参数。manifest 保持原有身份、完整性及轮次职责，不加入数据集、样本数、训练指标、无线配置或页面字段。

### 参考模型、训练与数据

| 项目 | 固定要求 |
| --- | --- |
| 目标硬件 | Jetson Orin Nano，共 5～8 块，含 1 个服务端与 4～7 个客户端；实际清单在部署时确定 |
| 模型 | 未预训练的两层卷积加分类层小型网络，输出 10 类，模型参数 FP32 |
| 全局轮次 | 默认及完整参考任务为 5 个严格同步轮次 |
| 客户端计算 | PyTorch GPU，每轮从本轮全局模型开始，完整训练集训练 1 个 epoch |
| 批大小 | 64，保留不足一个批次的尾部样本 |
| 优化器 | SGD，学习率 0.01，无动量和权重衰减 |
| 训练数据 | 每个客户端使用内容相同的 60,000 个 MNIST 官方训练样本 |
| 评估数据 | 服务端使用 10,000 个官方测试样本，测试集不参与训练、梯度更新或参数平均 |
| 评估位置 | 初始模型及每轮聚合模型在服务端评估，记录实际设备，不强制服务端聚合使用 GPU |

- 参考实现唯一固定并归档卷积通道、激活、图像归一化、分类损失、初始化及数据加载种子等实现细节。它们不成为运行时任意模型结构配置；训练与评估使用相同预处理。不承诺 GPU 跨设备位级一致。
- 提供初始化工具，按固定结构和记录的种子生成未训练模型。通过已有模型库上传并按完整 SHA-256 选择，同一制品可用于多次作业。模型库继续管理不透明文件，格式与模型内容由算法校验。
- 各端配置本地 `mnist_data_dir`，直接读取原目录预先解压的官方 IDX 文件。客户端固定读取 `train-images-idx3-ubyte`、`train-labels-idx1-ubyte`，服务端固定读取 `t10k-images-idx3-ubyte`、`t10k-labels-idx1-ubyte`；不引入通用数据集管理或格式适配，不自动解压、下载、注册或复制入库。
- 检查 IDX 类型、维度、文件长度、图片／标签对应计数、28×28 灰度图及 0～9 标签，核对完整样本总数和每份文件 SHA-256。各客户端对应摘要必须一致；相同样本数不等于内容相同，各端摘要一致也不能单独证明官方来源，部署证据须保留数据来源。
- 数据是操作者维护的持久资产，运行时不得修改或删除。准备检查失败拒绝开始；训练中读取失败结束作业，不换数据、跳过节点或降级文件复制。
- 本轮权重使用实际完成训练的样本数，不以期望值、目录配置、优化器步数或全局轮数代替统计。样本重叠是参考任务的有意简化，不论证数据多样性或不同分布收益。
- 客户端 GPU 不可用、依赖不匹配或必要 GPU 操作失败明确报错，不静默转 CPU。JetPack、CUDA、Python、PyTorch 的实际组合及设备能力在部署阶段记录和检查，不填写当前未取得的版本或性能数字。

### 模型与 update 文件

- 模型和 update 各为一个 PyTorch 文件，保存 CPU 参数张量与必要的基本类型元数据，不保存可执行模型对象或恢复任意类。模型至少表达 `model_format`、`state_dict` 和初始化来源／种子；聚合产物保持相同可加载结构并保留模型来源关联。
- 加载严格核对格式、键、形状、dtype 及有限数值。客户端将模型放到 GPU 训练，交付前将参数保存为 CPU 张量；文件大小来自实际序列化结果，同时保留各端共享的显式上行大小上限。
- update 内容固定包含以下算法事实，随同一个文件接受原有完整性校验，不建立另一个提交协议。

| 内容 | 要求 |
| --- | --- |
| `model_format`、`state_dict` | 本地完整训练后参数，结构与固定模型匹配 |
| `base_model_sha256` | 本轮实际读取的全局模型摘要 |
| `node_id`、`round_index` | 内部节点身份和从 1 开始的算法本地轮序，不代替 Runtime 轮次身份 |
| `sample_count` | 本轮实际训练样本数，正整数，参考任务完整训练一次为 60,000 |
| `optimizer_steps` | 实际优化器更新次数，正整数，不能用作样本权重 |
| `train_loss` | 按实际样本统计的有限平均训练损失 |
| `device` | 实际计算设备的有限描述，参考客户端必须为 GPU |

- 服务端逐一检查节点集合、内部身份、轮序、基准模型摘要、参数结构、数值与样本统计。任一不符即失败，不忽略异常节点、不使用旧 update，也不返回部分成功。
- FedAvg 对全部有效客户端模型按 `sample_count` 除以本轮总样本数加权，不乘全局轮数、不按优化器步数计权。聚合写入宿主指定的新文件，半成品和异常结果不得发布。

### 准备屏障与有限控制结果

- Server Daemon 整体校验候选和初始制品引用后受理。Coordinator 准备阶段校验模型及测试数据、完成初始评估；如有无线策略，在初始评估后、启动客户端任务前调用，成功后才继续。
- Client Daemon 先停止空闲链路并确认 TUN 释放，再启动独立进程组中的 RoleService。RoleService 初始化任务链路、Runtime、Transport 和接收器，再进入客户端算法检查。基础 ready、进程已创建或 TUN 出现均不表示训练准备通过。
- 客户端通过显式上下文报告数据、GPU、依赖和有限设备信息；RoleService 沿私有通知／状态通路交给 Daemon，不把原始 stdout 当协议。服务端收齐并验证全部固定参与者报告，加上服务器本地检查，才首次发布模型。
- 沿用既有带内 JSON UDP 控制，不新建控制链路或消息平台。每条 UTF-8 消息不得超过既有 4096 字节边界，检查序列化大小并限制摘要与错误文本；超限明确失败，不静默截掉身份等关键字段，不承载大清单或日志。
- `TASK_READY` 至少携带作业身份、节点身份、稳定逻辑报告身份和准备结果；参考报告包含模型格式、样本数、固定 IDX 文件摘要、GPU／依赖检查与有限设备信息。
- `TASK_ERROR` 至少携带同样的作业／节点／报告关联，以及阶段、可取得的本地轮序、稳定错误码和短原因。导入／配置错误、检查失败、业务异常和提前退出都须显式反馈，不能只等待心跳超时或写本地日志。
- `ROUND_READY` 表达本轮 `submit_update` 已成功返回并暂停任务数据发送、可以等待下一轮；它不代替 Runtime 收齐或链路层 READY，末轮同样用于安全收尾。
- 报告在预算内以同一身份重试，确认匹配作业、节点和报告身份，并明确接受或拒绝。服务端先验证、记账再确认；相同事实幂等确认，冲突内容、过期作业、非参与者或不适用阶段不能成功接受。不得用无身份 heartbeat ACK 代替。
- 任务发布、停止／完成及恢复沿用作业绑定、幂等和有界确认原则。重试不能重新启动算法或重复训练，也不能无限刷新预算。启动等待不得占满唯一控制接收线程，使停止请求无法处理。

### 轮次序列与资源所有权

- 初始模型记为 M0，在准备阶段评估。第 k 轮发布 M(k−1)，等待全部固定参与者有效更新，聚合得到 Mk，再评估 Mk；客户端每次提交返回后报告本轮完成。
- 相邻轮次如有无线策略，在本轮聚合、评估之后且下一轮发布之前调用。无策略或策略不调整则直接沿用当前配置，不隐式扫描或调参。
- 五轮保存 M5 作为最终产物，不再为 M5 额外广播或调用末轮后的无线策略。终态回收前须取得各客户端末轮提交返回／完成报告，避免服务器收齐后过早关闭仍等待上传响应的客户端。
- 同一任务 Runtime、Transport、接收器和链路跨轮复用。每轮只结束该次文件操作，轮次间合法重配不销毁算法进程、TUN 或接收器。
- Client 空闲链路与任务链路分时拥有同名 TUN，不并存。Server 持久链路跨作业保留；完整作业结束后关闭任务角色并按已确认配置恢复待命，新作业创建新的执行上下文。
- 客户端自然返回仅证明本地职责结束；全局执行、效果与恢复由服务器基于各层事实分别记录。资源回收和审计失败不追溯改写已成立的文件交付事实。

### 受控无线配置

| 算法字段 | 取值／规则 | 作用范围 |
| --- | --- | --- |
| `radio_txpower_dbm` | 10～20 dBm | 服务端与全部客户端统一值 |
| `downlink_mcs` | 3、4、5、6 | 服务端下行发射 |
| `uplink_mcs` | 3、4、5、6 | 全部客户端上行统一值 |
| `bandwidth_mhz` | 整数 20 或 40 | 全网 HT 带宽一致 |
| `uftp_rate_kbps` | 按带宽与下行 MCS 组合校验范围及推荐值 | 服务端后续 UFTP 下行操作 |

- 操作者在集群空闲时按现场测量确定并保存信道，算法 patch 不接受 `channel`。作业启动和轮次推进不自动选信道；客户端寻频入网、重连与配置对齐保留。现有有效候选和黑名单限制继续生效。
- `channel_width` 仅由 Daemon 根据固定信道、逻辑带宽和硬件支持合法派生为 HT20 或有方向的 HT40，不作为第二套独立真值。不兼容时执行前拒绝，不改信道、不降带宽；FEC 和 GI 保持底座固定，不扩展 VHT／80 MHz 或额外 PHY 参数。
- Daemon 先合并完整目标配置，再校验带宽与下行 MCS 组合。改变任一维度且省略速率，使用新组合推荐值；显式速率按新组合范围校验；只改功率或上行 MCS 保留当前下行速率。请求拒绝不改变资源，策略可处理参数错误；进入跨节点协调后的失败必须结束作业。
- 请求受理时冻结服务器及全部在线客户端的确认集合，含在线待命节点和全部作业参与者。不能剔除失联参与者；尚未上线节点不阻塞该事务，上线后按已生效配置对齐。
- 轮次间重配先确认服务端文件操作结束、全部作业客户端已收到上传成功结果并进入等待／暂停。聚合完成不替代客户端确认。暂停新任务数据交换、保留必要控制通信，禁止下一轮模型发布。
- 复用 `wfb_tx_cmd` 背后的本机在线更新能力接入 v6，不以现有 CLI 已可配置 v6 为前提。MCS 更新不重启链路，带宽同时更新网卡工作模式及发射描述，功率由受控网卡接口设置。数据帧和调度控制帧配置须一致更新；UFTP 速率在下一次操作启动时固定，不修改活动操作。
- 本机完成、集群事务完成和资源就绪分别确认。沿用 PREPARE、COMMIT、FINALIZED、CONFIRMED 和租约边界，不能仅删除空闲门禁，也不能另启空闲链路绕过任务链路所有权。
- 同步结果或结构化异常至少包含 `request_id`、`job_id`、`phase`、`transaction_state`、`before_config`、`requested_patch`、`target_config`、`target_nodes`、`confirmed_nodes`、`unconfirmed_nodes`、`effective_config`、`recovery_state` 和必要的 `error_code`／`reason`。只有有确认依据时才能填写全网生效配置，无法确认时明确未知，不以缓存目标值冒充成功。
- 不可逆提交前失败，尝试恢复变更前完整配置并保持操作者信道，回退未确认则记录未恢复；算法失败不统一退回基准信道 157。不可逆提交后保留已提交新配置，缺失确认进入 `RADIO_ERROR`，不强行回退或自动续训。空闲期操作者切信道保留自身的恢复机制。
- 普通完成或训练失败后，保留最后一次成功生效配置，不额外恢复作业初始值。服务重启采用操作者保存的启动配置，算法调整不自动写成永久启动配置。

### 期限、失联和停止

- 服务器控制配置显式提供正的 `preparation_timeout_seconds`、`round_timeout_seconds`、`io_timeout_seconds`，受理时冻结并传递给需要的客户端上下文。准备预算覆盖初始评估、角色启动和检查确认；完整轮次从发布起覆盖训练、上传、聚合、评估及末轮必要提交确认；I/O 预算覆盖下层传输等待，轮次间无线事务另有既定期限。
- 宿主分别监管预算，期限到达唤醒等待并显式请求下层已有取消能力，不新增 Runtime 四接口参数，不由作业超时追溯撤销已成立的文件成功。重试和阶段变化不得无限续期。实际数值部署时按测量确定，不把旧短启动超时当作 GPU 训练预算。
- 固定参与者业务报错、角色异常退出或达到现有服务器心跳失联条件，活动作业失败，不缩减集合、不补轮、不续训；重新上线只更新当前活性。受控重配暂停由事务确认与租约裁决，不并发套用普通失联处理打断预期暂停。
- 操作者停止作业后唤醒屏障、禁止下一轮；无线不可逆提交前停止推进并尝试恢复旧配置，提交后保留新配置，随后回收任务。缺失确认与恢复事实独立保留，不承诺全网瞬间停止或硬件断电。
- 客户端回收 RoleService 整个进程组；服务端算法须协作退出。计算尚未退出、传输未取消回收或待命资源未恢复时，不能报告恢复完成，也不能以固定等待时间代替退出证明；存在冲突资源时拒绝新作业。
- 以 `execution_result`、`effect_result`、`recovery_state` 分别表达执行、算法效果和资源恢复。效果未判定不得填成功或伪造零指标。首次终态不被后到消息改写，后续错误保留诊断与恢复进展。

### 在线候选与结果快照

- 在线与基础就绪复用服务端权威事实，不改变既有心跳阈值。客户端列表及新作业候选仅含在线客户端，按节点编号排列；Server 在自身状态区展示。在线但未就绪者显示状态与已知原因、禁止勾选，不能提前显示训练就绪。
- 用勾选替代目标文本框；首次为空，新上线不自动加入，不接受任意手工编号。新快照保留仍有效草稿，节点离线或不可选则取消并提示，恢复后不自动选回，没有目标不提交空集合。
- 草稿只存在当前页面。页面内刷新和同一服务实例重连保留有效选择；整页重载、重开或服务实例变化清空。已受理作业从服务器快照恢复，与草稿分离，不重发启动。
- 提交时后端整体校验完整目标，任一不可用则整体拒绝，返回逐节点原因并刷新候选，由操作者确认后重提。不自动剔除、缩减或重试，已受理后的准备失败不得伪装成未受理表单错误。
- 当前／最近作业详情保留固定参与者、当前活性与失联事件，离线过滤不删除作业成员；重新上线不擦除失联或恢复失败作业。仅心跳超时不能推断断电或具体物理故障。
- 权威快照包含服务实例及版本、候选事实、冻结配置摘要、制品及参与集合、阶段／轮数、逐参与者准备与训练摘要、初始与每轮评估、模型身份、无线事务结果、失败详情和独立结果／恢复事实。原始服务器文件位置不构成 Web 文件访问授权。
- 页面先提供一张最小评估表和必要参与者摘要，不建设曲线、多作业比较或历史数据库。关键事件辅助说明，不承担状态重建，不用心跳刷屏；大日志保留本地，不经带内控制集中上传。
- 无法取得最新状态时保留最后快照并提示过时，暂停新启动，不把所有无线节点改成离线或统一显示 404。有效新快照恢复后按门禁操作；只有 SSE 断开而 HTTP 轮询仍有效时，继续使用轮询最新状态。

### 既定实施顺序

- 先完成参考算法、模型初始化、数据检查和作业上下文／准备／停止，再接入 Coordinator 的聚合、评估与多轮流程，用 40 MHz 少轮真实训练检查主链。少轮不计完整验收。
- 随后整合作业绑定的 v6 在线更新、双带宽无线事务和组合速率表。环境准备与底座更新可提前，Web 可在后端状态确定后与无线工作并行。
- 所有能力及部署前提就绪后，才开展下述三次正式运行、故障检查和最终证据交付。本规格不附实施任务文件，也不把中间试跑当成最终完成。

## Testing Decisions

### 验证边界与已有基础

- 主要接缝是现有 Web／Server Daemon 作业入口贯通的真实硬件端到端行为：受理、准备、无线文件交换、GPU 训练、聚合评估、重配、终态与待命恢复。检查可观察结果、实际文件与节点事实，不断言私有函数调用顺序来代替业务结果。
- 沿用当前常驻服务、角色进程组、Runtime／Transport 完成事实、控制台快照及节点小型审计作为观测点。只有外部结果无法证明加权数值时，补充对正式聚合函数的受控不等权核验和独立制品复算，不建立新的通用测试框架。
- 既有文件闭环、模型摘要、作业身份与硬件验收经验可在其行为未改变时复用；旧 VM／三节点文件作业、字节平均样例和命令返回不能证明本次真实训练、数值聚合或新增双带宽能力。
- Web 使用真实页面与权威状态入口检查候选、提交和恢复；尽量复用已有故障场景。验证只针对当前受影响入口，不恢复已停止维护的本机自动回归、namespace 隔离验收或旧测试目标。
- 当前没有板端训练与完整 20 MHz 速率证据。代码、规格、受控算术检查或少轮试跑通过，都不能填写最终实机验收通过；环境及标定在有硬件的部署阶段执行。

### 三次完整成功运行

- 使用同一初始模型、数据、训练参数和固定参与集合，连续完成三次各五轮真实无线作业。三次之间正常回收并恢复待命，不人工重启 Daemon。实际节点数仍须满足 1 个服务端与 4～7 个客户端。

| 作业 | 第1轮 | 第2～3轮 | 第4～5轮 |
| --- | --- | --- | --- |
| 第一次 | 40 MHz | 40 MHz | 40 MHz |
| 第二次 | 20 MHz | 20 MHz | 20 MHz |
| 第三次 | 40 MHz | 20 MHz | 40 MHz |

- 第三次在第1、3轮聚合评估后完成屏障再切换；预先冻结合法的功率、上下行 MCS 与速率修改方案，覆盖推荐值及显式值规则。保持支持两带宽的操作者信道，不遍历参数笛卡尔组合，不设置吞吐达标线。
- 每次、每轮分别证明实际模型加载、GPU 前向／反向／参数更新、实际样本与步数、全员有效聚合及下一轮模型关联。记录 M0 初始评估和 M1～M5 评估；每次末轮准确率高于初始、损失低于初始，非有限或未改善如实失败，不要求逐轮单调或固定高准确率。
- 无线取证分别证明本机更新、完整目标集合确认和资源就绪；重配发生在上传成功已返回、活动文件操作已结束、下一轮未发布的边界。不能仅使用守护缓存或 CLI 返回。
- 保存全部尝试，非预期失败保留原因，修复后重新验证连续组合，不挑选三次成功隐藏失败。刻意故障另记，不计成功次数；不同无线条件的三次结果不用于单参数性能归因。

### 独立数值复核

- 对三次作业共十五轮的每轮全部实际 update，在服务端制品显式清理前校验身份和摘要，通过独立 CPU 路径以 FP64 重算样本加权平均，再逐张量、逐元素与实际 FP32 聚合结果比较。
- 通过条件固定为绝对差不超过 `1e-6` 加上参考值绝对值的 `1e-5` 倍。不得调用生产聚合函数或复用其求和逻辑；允许共用文件读取与格式检查。键、形状、dtype、身份与有限性错误直接失败，不能被数值容差掩盖。
- 保存输入／输出摘要、样本数及权重、精度、最大误差、逐轮结论和复核工具版本。阈值在验收前冻结，不能看结果再放宽；不依赖客户端已清理沙箱或 Runtime 重启重放。
- 参考训练各端样本数相同，还须以可区分参数与 1∶3 样本权重对正式聚合函数做一次受控计算，并用独立结果核对。它只证明权重进入算术，不代替真实数据和 GPU 训练，也不引入数据分区或旧回归套件。

### 故障与页面检查

每个既定独立处理分支至少验证一次，可用短作业，不要求五轮，不扩展为全部参数组合；故障预先安排、单独归档，并尽量复用到页面检查。

| 范围 | 必须观察到的结果 |
| --- | --- |
| 准备失败 | 模型不合法、数据缺失／损坏／不一致和 GPU 不可用明确失败；不发布首轮、不降级 CPU |
| update 拒绝 | 错误节点／轮序／基准关联、非法样本统计或非有限参数不能进入聚合，不跳过节点或复用旧数据 |
| 运行失败 | 训练异常、角色退出、参与者失联结束作业，参与集合不缩减，重新上线不续训 |
| 等待期限 | 准备、完整轮次与 I/O 的期限分别能结束等待并清理，未退出计算或缺失确认不显示恢复完成 |
| 停止作业 | 训练中及无线不可逆提交前后按相应配置／清理规则收尾，请求受理不冒充全部完成 |
| 重配失败 | 提交前恢复旧配置并保留信道，提交后确认不全保留新配置与错误；回退失败、未确认和未知配置均如实显示 |
| 控制事实 | 旧作业、非参与者、不适用阶段、重复和冲突报告按身份与阶段处理；重复确认不重做训练或改写终态 |
| 页面选择 | 在线过滤、未就绪禁选、初始空选、上线不自动加入、失效取消和恢复不重选、提交竞态整体拒绝 |
| 页面恢复 | 固定参与者失联及恢复、整页重载和服务实例变化、管理状态过时、SSE／HTTP 单路可用、评估与独立恢复结果均来自快照 |

### 部署标定与最终证据

- 先核实逐端 Jetson、无线网卡／驱动、代码和软件环境，确认兼容依赖、GPU 操作与固定数据来源。没有数据时保持未验证，不以规划票结单代替部署检查。
- 具备受控固定 HT20 的入口后，在操作者固定信道、功率、GI、FEC、拓扑与现场条件下，对下行 MCS 3／4／5／6 分别标定候选注入速率。可以使用受控文件分发入口，不要求先完成真实训练。
- 每个候选记录目标集合、文件大小、内容一致性、完成／失败、耗时、有效吞吐与可得重试信息；重复观察并说明已测范围、推荐依据和限制，单次成功不能证明安全上限。核对旧 40 MHz 表的适用范围，冲突如实记录。
- 交付按带宽与下行 MCS 索引的实际速率表、测量条件、原始证据和接入结果后，才能正常启用 20 MHz 并验收。测量本身允许设置 HT20，不能用 40 MHz 表、理论 PHY 或比例折算冒充实测；结束后恢复并核对操作者配置及待命状态。

| 证据部分 | 最小内容 |
| --- | --- |
| 总报告 | 实际节点与环境、无线网卡／驱动及位置条件、软件／设备版本、冻结配置与种子、所有尝试、逐轮模型链和指标、数值复核、无线确认、故障与 Web 结果，关联证据位置及摘要 |
| 节点小型审计 | 现有白名单日志、配置、状态、结果与 manifest；不加入客户端模型／update 本体 |
| 服务端计算制品 | 三次作业的初始模型、全部实际 update 和每轮聚合模型，独立保存路径与摘要，支持事后重新计算 |

- 证据备份到操作者指定持久目录，不能只引用临时工作位置；不要求经带内控制面集中传大文件或日志。完成复核、备份和摘要确认后，由操作者显式决定原文件清理，不增加自动过期机制或历史数据库。
- 运行阶段从作业受理到终态的唤醒、推进与复位不以 SSH 为前提；环境准备、部署和事后取证与此边界区分。资源恢复、效果和证据完整性均单独验收。

## Out of Scope

- 服务器指定数据划分、样本区间或索引下发、IID／非 IID 实验设计，以及以重叠训练集论证数据多样性收益。
- 通用数据集库、多数据集注册、版本管理、目录摘要体系、浏览／删除接口、Web 数据上传、服务器分发样本、运行时下载或通用格式适配。
- 客户端之间的直接或经服务端中转通信。
- 通用算法插件市场、动态代码／依赖分发安装、代码热切换、任意框架自动适配或第二套联邦学习运行平台。
- 半异步、异步、部分节点成功、运行中缩减参与集合、失败自动补轮、断点续训与故障后自动恢复训练。
- 活动文件传输中的无线切换、自动选信道、节点级差异化功率／MCS、无策略调用的自主调参、额外 PHY 参数或 80 MHz／VHT。
- 硬件急停断电、全网瞬时停止承诺、延期的通用服务终止框架、Runtime 新公开控制接口或通用消息平台。
- 曲线分析、多作业比较、历史数据库、持久选择草稿、集中大日志与节点管理后台扩建。
- 固定高准确率、逐轮单调损失、吞吐性能门槛、单项无线参数因果结论、跨 GPU 位级复现承诺。
- 不恢复旧本机自动回归、namespace 隔离验收，也不使用旧 VM 或模板文件作为最终真实训练证据。

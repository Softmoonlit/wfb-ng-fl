# 03: 实现空闲集群无线在线配置

**What to build:** 操作者在集群空闲时经现有受控入口提交无线配置，由守护进程合并、校验并协调各节点的网卡与 v6 发射器在线应用；同时具备按明确步骤设置 HT20 进行受控标定的能力。

**Blocked by:** 无（可立即开始）。

**Status:** ready-for-agent

**规格依据：** [受控无线配置及部署标定要求](../spec.md#implementation-decisions)，用户故事 28～31、43。

**交付边界：** 本票交付软件和可操作的受控入口，不等待实机速率数字。正常启用 20 MHz 的门禁与为取得数字而进行的受控测量要明确区分，不增加普通作业的强制旁路。实际网卡应用、本机与远端确认、数据交换分别交给[20 MHz 速率标定与组合表交付](09-20mhz-rate-calibration.md)和[关键故障与控制台实机检查](12-fault-and-console-hardware-acceptance.md)。

- [ ] 操作者仍只在空闲时设置并保存信道，保留有效候选、黑名单、寻频入网及配置对齐；作业不自动选信道。
- [ ] 统一支持规格规定的功率、上下行 MCS、20／40 MHz 逻辑带宽和 UFTP 速率；GI、FEC 保持固定，不扩展节点级差异化配置或额外 PHY 参数。
- [ ] 先合并完整目标配置，再派生唯一合法网卡工作带宽和 HT40 方向；固定信道与带宽不兼容时拒绝，不换信道或降带宽。
- [ ] 速率表按带宽与下行 MCS 索引；改变任一组合维度且省略速率取推荐值，显式值按组合校验，仅改功率或上行 MCS 保留原速率。
- [ ] 缺少实测 20 MHz 表时，正常配置明确拒绝，不复制 40 MHz 表或折算填值；提供受控标定步骤，测量不依赖真实训练完成。
- [ ] 复用已有发射参数更新能力接入 v6，MCS 更新不重启链路，带宽同时调整网卡工作模式及发射描述，功率经守护进程控制；不假定旧命令已经可操作 v6。
- [ ] 数据帧与调度控制帧发射配置一致更新，完整参数应用不因命令默认值意外改变固定 GI、FEC 或其他字段。
- [ ] 空闲配置协调沿用受理时冻结的全部在线目标集合、既有确认与租约；本机命令接受、实际应用、集群事务和资源就绪有不同完成含义。
- [ ] UFTP 使用合并校验后的速率启动后续操作，不修改活动文件操作；Transport 不取得网卡配置或组合门禁所有权。
- [ ] 正常结束保留最后成功配置；服务重启使用操作者保存的启动配置，不将算法运行期调整隐式持久化。
- [ ] 构建正式底座产物，检查无需设备即可检查的合并、派生、校验、消息和结果结构，记录需设备验证的项；不以编译或缓存值证明射频生效，也不恢复旧回归体系。
- [ ] 将受控标定入口、组合表接入方式及本机／远端确认的实测义务交给相关实机工单。

# 04: 接入 40 MHz 真实单轮训练流程

**What to build:** 操作者选择初始模型、目标和轮数后，既有作业入口可进入真实训练流程：服务器装配算法并初始评估，全体客户端通过数据和 GPU 准备，执行本地优化、提交完整参数，服务器收齐后真实聚合、评估并安全收尾。本票先建立无无线策略的单轮路径，不设置临时的仅单轮产品限制。

**Blocked by:** 01（[生成并入库参考初始模型](01-reference-model-artifact.md)）。

**Status:** resolved

**测试底座：** [fl00 + fl01、fl02、fl04 四板与已有通信基线](../spec.md#当前四板测试底座与实施进度)。01、02 已完成，本票复用现有模型读取、在线候选与准备期限／取消机制。

**规格依据：** [显式配置、参考计算、文件及准备契约](../spec.md#implementation-decisions)，用户故事 3～12、18～22、25。

**交付边界：** 本票交付真实算法与作业主链实现、适用检查和审阅，在当前四板执行可用的针对性检查；不再以无板作为当前阻塞，不引入 CPU 训练降级或文件仿真替身。板端完整验证交给[Jetson 部署检查与 40 MHz 少轮试跑](08-jetson-environment-and-40mhz-trial.md)。多轮补全、完整期限／失联／停止及无线策略由对应后续工单负责，已有文件传输成功不代表本票训练已通过。

以下勾选表示实现与适用检查完成，不代表官方数据或四板真实训练验收已通过。

- [x] 通过服务器显式算法配置装配客户端、聚合和评估 callable，检查入口及配置资格；作业受理冻结配置、摘要、制品、目标、轮数和期限，各端代码预部署，不动态分发安装。
- [x] Web 保留模型摘要、目标与轮数三个输入，默认五轮并允许少轮试跑；复用已完成票 02 的在线候选、整体校验与准备期限，不再实现第二套选择或准备流程，不新增任意代码输入或算法菜单。
- [x] Coordinator 唯一拥有服务端发布、收齐和推进，客户端入口接收 Runtime、配置及作业上下文并拥有本地循环；移除正式路径的复制训练、模板 update、复制聚合与重复服务端循环，不保留旧入口兼容分支。
- [x] 服务器准备阶段校验初始模型与官方测试 IDX，计算初始平均损失和准确率；模型库仍不解释算法内容。
- [x] 各端使用本地数据目录，直接检查固定官方 IDX 的结构、长度、图像／标签、计数和摘要；客户端为完整 60,000 样本、服务器为 10,000 测试样本，各客户端内容一致，不复制入库或运行时下载。
- [x] 客户端准备阶段检查依赖、GPU 及有限设备信息，准备失败明确报告，不降级 CPU；基础角色 ready 不能替代训练准备。
- [x] 显式上下文及宿主沿既有私有／带内控制通路传递准备和业务结果，绑定作业、节点与稳定报告身份；先验证记账再确认，支持幂等、有界重试与拒绝，不用无身份心跳 ACK 代替。
- [x] 控制消息不超过既有 4096 字节，超限明确错误，不静默截掉身份，不通过控制通路传大清单或日志；入口导入、检查和提前退出错误不只留在本地日志。
- [x] 全部固定参与者和服务器准备通过后才首次发布；客户端使用规格固定模型、统一预处理、SGD 参数及批大小，按实际样本统计执行每轮完整一遍训练并保留尾批次。
- [x] 单个 update 包含 CPU 完整参数、模型格式、实际基准摘要、节点与本地轮序、样本数、优化器步数、训练损失和实际设备；Runtime manifest 不承载业务字段。
- [x] 聚合校验完整固定集合及全部内容关联、结构、数值和统计，按实际样本数加权，原子生成新模型；异常不跳过节点、不用旧数据或半成品继续。
- [x] 单轮形成 M0 初始评估、M1 聚合评估及产物身份，效果判据属于参考算法，执行、效果与恢复分别记录；少轮不计正式五轮验收。
- [x] 复用原有四个 Runtime 文件接口与传输完成语义，不暴露底层对象或 Runtime 轮次身份，不由作业失败追溯撤销文件成功。
- [x] 建立客户端提交成功返回后的明确完成报告和末轮收尾基础；构建、导入、文件格式、纯计算及可验证的控制行为按实际环境检查，记录实际执行范围和仍交由票 08 验证的 GPU、无线及全员恢复事项。

## Answer

已交付 `algorithm.py` 的只读作业上下文、显式函数加载与公共结果校验，`mnist_data.py` 的本机固定 IDX 严格读取，以及 `mnist.py` 的真实 GPU SGD、CPU 完整参数 update、样本加权 FedAvg 和服务器评估。参考模型格式复用票 01，正式 Runtime 返回的只读 update 映射可直接聚合。

服务器从部署配置选择三个入口和算法参数，先将 M0 归档到作业目录，在既有可取消准备预算内评估，再等待全部有限准备报告。客户端沿私有 UNIX 通知和带内控制报告绑定身份，准备／业务错误、提交返回和末轮完成均有明确确认与重试。裸 ready、通用心跳 ACK 和本地进程创建都不能替代训练准备。清理后丢失的末轮 ACK 可由同身份报告重试确认。

Coordinator 唯一推进发布、收齐、聚合和评估，算法参数与上下文均只读。末轮效果失败保留已完成轮次、模型和指标，执行、效果和恢复事实分别记录。停止共享协作事件，等待计算退出再回收角色资源。完整期限／失联机制仍由票 06 补全。

已删除正式包中的 `issue41_algorithm.py`、其专属文件仿真测试和 Runtime 仿真匹配分支，不保留旧入口或 CPU 训练降级。未恢复已停止维护的旧本机／namespace 验收。

实际 fl00 Orin 已用受控 IDX 完成 60,000 样本、938 步的单轮及两轮 GPU 计算，最终 GPU／IDX／模型检查 82 项通过；客户端、报告和无线应用检查 105 项通过。还保留并迁移了票 02 的准入竞态、准备取消、锁释放和 HTTP 幂等检查。最终合并结果、类型检查与双轴审查结论见[持久证据](../evidence/04-real-single-round/README.md)。

本票未部署或重启四板常驻服务，未配置官方 MNIST，没有将本机受控计算或既有文件闭环当作四板真实训练通过。票 08 在 05、06 完成后负责逐端官方数据、GPU 环境、40 MHz 少轮无线训练及恢复；票 12、13 继续负责完整故障矩阵和最终三次五轮验收。配置方式见[部署说明](../../../docs/deployment/MNIST真实训练与本机数据配置.md)。

# 13: 完成连续三次五轮训练与最终交付

**What to build:** 在完成前置联调的真实集群上连续执行规定的三次五轮任务，对全部十五轮独立复核，确认训练效果、无线边界、待命恢复和持久证据完整，交付可审查的最终验收结果。

**Blocked by:** 11（[提供独立聚合复核与持久取证流程](11-independent-audit-and-evidence.md)）、12（[完成关键故障与控制台实机检查](12-fault-and-console-hardware-acceptance.md)）。

**Status:** ready-for-human

**规格依据：** [三次成功运行、数值复核与最终证据](../spec.md#testing-decisions)，用户故事 20～25、27～33、37、43～50。

**执行条件：** 实际集群、GPU／数据环境、组合速率表、故障检查、全部相关软件与审阅已完成。没有板子或前置实测结论时保持未执行，不以规划、代码审阅、受控算术或少轮记录提前结单。

- [ ] 固定实际 1 个服务端与 4～7 个客户端的参与集合、同一初始制品、数据、训练参数与种子记录；冻结各次合法无线方案及部署期限，保存环境、代码与网卡／驱动身份。
- [ ] 第一次五轮全程 40 MHz，第二次五轮全程 20 MHz，第三次轮1为40、轮2～3为20、轮4～5为40；第三次在轮1、3聚合评估后经完整屏障切换。
- [ ] 操作者信道全程固定且支持两种带宽，使用实测组合速率；预定方案覆盖功率、上下行 MCS、速率修改、推荐值和显式值，不遍历全部组合，不设吞吐门槛。
- [ ] 每次各客户端真实读取本轮模型、执行 GPU 前向／反向／优化并提交有效完整参数，记录实际样本数、步数、损失、设备和模型摘要，按实际样本数全员聚合。
- [ ] 每次核对 M0 初始及 M1～M5 的评估与身份、后一轮实际使用前轮聚合模型；末轮取得客户端提交完成确认，M5 保存不额外广播或运行策略。
- [ ] 每次第五轮准确率高于初始且平均损失低于初始，非有限或未改善如实失败，不要求逐轮单调或固定高准确率；执行、效果、资源恢复分别记录。
- [ ] 实测证明20和40均完成模型下发与更新上传，轮次间无活动文件交换、任务资源保留，下一轮不越过事务；本机、全体目标及恢复证据分开，不以缓存或本机 ACK 代替。
- [ ] 三次之间正常回收并恢复待命，不人工重启 Daemon；保持最后一次成功无线配置，下一作业仅通过规定初始策略显式修改。
- [ ] 对实际十五轮全部 update 和聚合产物逐轮独立 FP64 复算并按固定容差逐元素比较，保存权重、精度、最大误差、摘要及结论；受控1∶3核验记录仅证明算术，不代替这些实际输入。
- [ ] 保存所有成功、失败及此前刻意故障尝试，故障单独归档不计成功次数；非预期失败修复后重新验证连续组合，不挑三次成功或事后放宽判据。
- [ ] 按总报告、节点小型审计、服务端计算制品三部分交付：保留实际初始模型、全部 update 与聚合模型及摘要，备份到操作者指定持久位置，足以事后重新计算。
- [ ] 在独立复核、持久备份和摘要确认前不清理实际制品，之后由操作者显式决定原文件清理；客户端小型审计不扩装大文件，不新增历史数据库或自动过期。
- [ ] 报告如实记录耗时、吞吐、失败与限制，不将不同配置作业用于单项参数因果归因；作业受理至终态的唤醒、推进及复位无 SSH 依赖。
- [ ] 最终检查参考效果、执行、资源恢复与证据完整性分别有依据，按既有审阅流程流转；任何必要项缺失均不能填写最终验收通过。

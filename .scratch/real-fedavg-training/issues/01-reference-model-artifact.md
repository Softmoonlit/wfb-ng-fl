# 01: 生成并入库参考初始模型

**What to build:** 操作者可以用明确的初始化工具生成固定 MNIST 参考模型，记录初始化来源与种子，经现有模型库上传并选择同一初始制品，为后续真实训练提供严格可加载的输入。

**Blocked by:** 无（可立即开始）。

**Status:** ready-for-agent

**规格依据：** [参考模型与算法文件约定](../spec.md#implementation-decisions)，用户故事 1、2。

**交付边界：** 本票是软件实现票。完成条件是工具和模型库流程实现、适用的软件检查及代码审阅，不要求现在取得 Jetson。板端模型加载、评估和训练由[Jetson 部署检查与 40 MHz 少轮试跑](08-jetson-environment-and-40mhz-trial.md)实测；初始化与模型格式检查可在具备 PyTorch 的开发机进行，不代表客户端训练允许降级 CPU。

- [ ] 固定并记录两层卷积加分类层的唯一结构、10 类输出、FP32 参数、初始化方式与种子；不增加运行时任意模型结构配置。
- [ ] 初始化工具生成未经训练的模型，保存 CPU 参数张量、明确格式标识和必要基本类型元数据，不序列化可执行模型对象。
- [ ] 提供供真实算法复用的严格读取与校验能力，检查格式、键、形状、dtype 和有限数值；不为旧不透明文件建立兼容加载或回退路径。
- [ ] 生成物能通过既有上传入口入库并取得完整 SHA-256 身份，操作者可以选择或重复使用该制品；模型库继续管理不透明文件，不承担算法语义。
- [ ] 模型读取及后续使用不原地修改模型库制品；格式错误、结构不匹配或非有限参数产生明确错误。
- [ ] 核对现有依赖能力和类型后实现必要功能，记录开发环境、结构、种子及工具使用方法，不填写未取得的 Jetson 依赖版本。
- [ ] 完成初始化、合法文件读取、非法文件拒绝和既有模型库入口的适用检查，并记录检查范围；不恢复旧本机回归、namespace 验收或测试目标。
- [ ] 明确交接板端尚未验证事项及其所属实机工单，不将开发机生成或加载成功写成 GPU 训练通过。

# 02: 勾选在线候选并整体校验目标

**What to build:** 操作者从服务器判定的在线客户端中明确勾选目标，知道哪些节点暂不可用，并在提交竞态中获得完整拒绝原因；页面刷新状态不会擅自扩大选择或缩减已提交集合。

**Blocked by:** 无（可立即开始）。

**Status:** resolved

**测试底座：** [当前四板清单、已验通信事实与未验边界](../spec.md#当前四板测试底座与实施进度)。本票保持已完成，不因环境更新重新打开。

**规格依据：** [在线候选与结果快照](../spec.md#implementation-decisions)，用户故事 12～17、39～41。

**交付边界：** 本票是软件实现票，基于现有状态与作业入口完成候选、页面和整体校验的完整流程。可以检查受控快照与拒绝行为；真实节点上下线、提交竞态及管理连接变化由[关键故障与控制台实机检查](12-fault-and-console-hardware-acceptance.md)验证，不因四板文件传输通过而提前记为这些分支实测通过。

- [x] 客户端列表只展示在线客户端并按编号排列，Server 仍在自身状态区域展示；在线判定复用服务端心跳事实，不更改阈值或由浏览器另设计时器。
- [x] 在线但基础未就绪节点可见不可选，显示状态与已知阻塞原因；候选不显示成已通过本次数据或 GPU 检查的训练节点。
- [x] 目标使用勾选控件，初始为空；新上线不自动加入，不保留任意手工编号输入，没有目标时不提交空集合。
- [x] 状态刷新保留仍有效的选择；已选节点离线或不可选时取消并提示，恢复不自动选回。
- [x] 选择仅保留在当前页面及同一服务实例中；整页重载、重新打开或实例变化清空，不新增持久草稿。
- [x] 后端在受理前整体检查完整目标集合；任一不可用即整体拒绝，返回逐节点结构化原因，不自动剔除、缩减或重试。
- [x] 页面区分未受理表单错误和已受理作业的准备失败；作业参与集合受理后固定，后续状态刷新不能改写。
- [x] 管理状态不可获取时保留最后画面、提示过时并暂停启动，不把无线节点全部改成离线；有效快照恢复后按门禁操作。
- [x] SSE 中断但 HTTP 轮询仍有效时继续使用最新状态；运行作业的恢复不依赖重发启动。
- [x] 完成候选呈现、草稿变化、整体校验和连接状态的适用软件检查，记录真实无线联动仍待实机；不增加通用选择框架或恢复旧回归体系。

## Answer

已完成在线目标选择与整体校验流程：控制台按服务端心跳事实列出可选候选，目标初始为空并通过勾选明确选择；刷新只保留仍有效的草稿，失联或不可选节点自动取消并提示。服务端与控制台共用目标资格判定，提交竞态整体拒绝并返回逐节点阻塞原因，受理后的准备失败保留固定参与者及失败快照。

准备阶段的模型读取、哈希、Runtime/Role 启动和 TASK_READY 等待共享配置化期限；停止或超时会请求取消、关闭资源并等待退出，HTTP 状态快照与 SSE 任一路有效即可继续操作。受控页面、HTTP/Chromium、Python/Node 受影响测试和 Standards/Spec 双轴 `review` 均通过。真实节点上下线、无线提交竞态和管理链路故障仍由票 12 做硬件验收。

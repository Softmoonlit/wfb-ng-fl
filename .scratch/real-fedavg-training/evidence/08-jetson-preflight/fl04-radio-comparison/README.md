# fl04 信道、功率与上行 MCS 对照

2026-10-28 用户授权尝试 149、18 档功率和提高 MCS。采用逐项改变的三组单 fl04 4 MiB 双向传输。每组前核对四端冻结提交 701963a 的 Python 安装文件、加载路径和运行 native 摘要，备份并停止四端常驻服务，仅启动 fl00/fl04 standalone，结束后恢复原服务。

## 解释与限制

本次 149 / 14 / MCS4 可作为继续验证的候选：已有完整文件闭环；提高功率没有观察到收益，提高上行 MCS 后本次失败。每组仅一次，未交错随机化、未验证长期稳定，不能据此把故障唯一归因于信道或得出功率、MCS 的普遍因果结论。前次157测试上行失败是历史对照，并非本轮同步重复对照。

## 恢复后的实际状态

三组结束时 runner 均曾观察到全员 READY；两组传输通过，第三组传输失败但恢复观察通过。最终逐端 `iw` 再次确认均已回到原配置 157 / HT40+ / `-14.00 dBm`，四端服务 active，未保存实验配置。

但是追加观察发现：fl04 在恢复原配置后再次 OFFLINE，连续四次追加采样均 OFFLINE，最后心跳年龄从38.65增长至53.66秒；客户端再次报告“连续2次未收到ACK，退回寻频自愈”。不能把 runner 的短时 READY 当作长期恢复。Server IDLE，fl01/fl02 READY。证据见 `final-radio-services.json`、`final-status.json`、`final-followup-status.json`、`final-fl04-journal.txt`。

# 常驻心跳容错修正

## 规格与实现

用户明确授权按2秒发送/10秒持续无确认的机制修正常驻监督。背景及取舍见 `docs/adr/0018-区分心跳探测失败与链路持续失活.md`。

- IDLE默认心跳间隔从5秒改为2秒，单次请求等待仍为230ms。
- 以有效ACK对应请求的本机单调发送时间为活性锚，不按接收时刻延长预算。
- 连续miss只计账；每次探测结束时，IDLE若持续至少10秒没有有效确认且不处于射频事务，才进入HUNTING。删除“两次miss”触发常量。
- 成功寻频和后续有效ACK推进锚；首次无ACK入IDLE只获得一次有限观察起点，状态切换不能凭空续期。
- 回执仍严格匹配当前请求时间戳、当前信道及服务端来源，不引入历史ACK缓存或新线程。活动作业liveness、Server超过10秒静默投影OFFLINE、native授权/FEC及MCS0控制帧不变。
- 补足事务保护边界：原判断只覆盖COMMIT后的旧配置快照，现也使用已有 `radio_switch_pending` 覆盖PREPARE阶段；事务暂停寻频，但不刷新活性时间。

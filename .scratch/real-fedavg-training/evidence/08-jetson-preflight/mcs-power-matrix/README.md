结论：在本轮固定信道实验中，降低 fl02 上行 MCS 4→3→2 没有让 4 MiB 上行完成；提高实际发射功率 -14→-10 dBm 也没有让其完成。因此当前证据不支持“仅降低 MCS 或提高功率即可修复 fl02”；-18 dBm 值得作为候选工作点继续做重复验证，但仍不能视为稳定修复。这也不能证明路径损耗、遮挡没有影响，只能说明问题还包含更底层的控制帧、网卡/驱动、天线或 USB 环境因素。

在恢复到 `-14 dBm` 前，对 fl02 的 `-18 dBm / MCS 4` 组合进行了三次 4 MiB 重复。三次均保持四端同一构建、157/HT40+、FEC 8/14 和 Server MCS 3；每次结束后都恢复四端 daemon，并读回 157、`-14 dBm`。

- 第 1 次：fl01 下行接收大小/SHA 校验失败，未进入回传。
- 第 2 次：fl01、fl04 回传成功，fl02 单次 HTTP 回传超过 120 秒；两台完成节点文件摘要正确。

这三次重复不支持将 `-18 dBm` 认定为稳定修复。它同时证明 fl01、fl04 也存在间歇性失败，fl02 只是失败最严重的节点。完整 run 事实保存在 `runs/20261028T032707Z-power18-repeat1`、`runs/20261028T032816Z-power18-repeat2` 和 `runs/20261028T032937Z-power18-repeat3`。

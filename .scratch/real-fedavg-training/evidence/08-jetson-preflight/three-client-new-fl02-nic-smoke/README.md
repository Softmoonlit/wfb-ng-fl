# 三客户端新 fl02 网卡 smoke test

本次用于验证仅替换 fl02 网卡后，三客户端能否进入正式训练前的通信基线，不是 FedAvg 验收。

## 前置身份

- 四板 Python/native：提交 `701963a`，native SHA-256 `f7c73f41b730ddb3547e1730b5a5b7b40a55dd7a8e3e5f265dcc6563c6c432b1`。
- fl02 实际新网卡：`fc:22:1c:50:0a:88`。
- fl04 实际仍为原 fl02 网卡：`fc:22:1c:30:0c:bb`。
- 射频：157 / HT40+ / 实际 `-14 dBm`，Server MCS 3，客户端 MCS 4，FEC 8/14。
- 负载：三客户端各 4 MiB。

## 结果

- 三客户端下行均成功，三个文件 SHA-256 与源文件一致。
- fl02 新网卡上行 HTTP 201，4 MiB 完整，SHA-256 一致，耗时 19.032 秒，约 1.76 Mbps。
- fl04 上行超过 120 秒超时；Server native 持续出现 node 4 上行包丢失。
- fl01 下行成功，但因 fl04 失败，runner 未将整组标记为通过；本轮不能作为三客户端稳定基线。
- 失败前后标准恢复完成；随后连续 6 个 API 采样确认 Server `IDLE`、fl01/fl02/fl04 `READY`。

## 判断

仅替换 fl02 网卡已经改善 fl02：它从此前单节点上行超时变为本轮三客户端中成功完成 4 MiB 上行。当前三客户端失败点转移到 fl04，而 fl04 的实际 MAC 仍是原 fl02 网卡 `fc:22:1c:30:0c:bb`。需要先核对 fl04 的实际换卡动作并安装可靠网卡，再进行三客户端 smoke test；不应继续调节 fl02 的 MCS 或功率。

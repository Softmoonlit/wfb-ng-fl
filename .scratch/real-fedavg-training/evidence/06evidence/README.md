# 06 有界等待、失联失败与停止的软件证据

本票基线为 `d9386f9`。本目录记录软件公开接缝的检查，四板少轮训练、正常停止及真实恢复由票 08 执行，完整故障矩阵由票 12 执行；这里不把受控测试当成实机验收。

## 已实现的机制

- 服务器部署配置冻结准备、完整轮次和 I/O 三项有限正数预算。完整轮次使用一个绝对 monotonic deadline，覆盖发布、收齐更新、计算、评估及提交返回报告；阶段切换和重试不续期。
- 作业绑定的监督器主动观察期限和角色故障；控制面按既有心跳阈值主动观察冻结参与者。失联、错误或停止复用既有取消路径，Runtime 四接口不变，不缩减集合或自动续训。
- 到期和停止锁定首因。取消先调度宿主终态投递，再请求可能阻塞的 Runtime 取消；计算或传输未实际退出不报告恢复完成。
- 上传连接、请求头、body、最终响应共用绝对预算。Transport 使用数值 IPv4，避免 DNS 阻塞脱离预算；关闭主动 shutdown socket 并等待请求线程退出。manifest 已提交的文件成功不会被后续响应失败追溯改写。
- 客户端终态处理交给单一异步回收者，不阻塞唯一控制接收线程；进程组、任务 TUN、待命链路任一未确认均保留 blocked。恢复报告获服务器 ACK 前保留作业绑定和恢复门禁。
- `JOB_RECOVERY` 使用专用 ACK、稳定 report_id 和递增 recovery_epoch。相同事实幂等，blocked 后的新清理事实可推进 ready；旧事实与新事实不互相覆盖。服务器只在本地资源退出且全员恢复确认后允许新作业。
- 终态投递按冻结恢复预算重试。首次发送异常或部分节点 blocked 不阻止其他节点收到停止。执行、效果及资源恢复分别保留，后到错误或恢复进展不改写首次执行结论。

## 测试端点隔离与实机影响

09 的并行测量暴露出旧测试会向生产控制 UDP 端口发送心跳，且真实全网广播可能影响射频。此问题已作为受影响测试夹具修正：真实 UDP 明确使用回环地址和动态端口，socket 边界拒绝物理目标、全网广播及生产端口；多客户端广播仍通过内核的回环广播验证，不以私有方法模拟代替。生产默认端口不变。

09 已保留污染与失败记录，并经正常服务重启、真实心跳和 `iw` 读回恢复四板到 40 MHz、Server IDLE、三个客户端 READY。后续正式测量等待 08 的一致版本部署完成。

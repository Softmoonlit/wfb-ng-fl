# 05: 实现 SSE 事件、急停与资源恢复

**What to build:** 让操作者可以在运行监控页面接收权威状态和关键事件、发起急停，并区分急停请求受理、作业执行结果和资源恢复完成。浏览器刷新、SSE 断线、慢客户端和 Server 重启都不能伪造旧作业结果。

**Blocked by:** 04（通过 Web 启动同步文件仿真作业）

**Status:** ready-for-agent

- [ ] SSE 建立连接后先发送完整控制台快照，再发送完整状态变化快照和去重后的操作者关键事件；每帧具有单调事件标识。
- [ ] `Last-Event-ID` 只能用于发现中间事件可能丢失；慢客户端使用有限队列，溢出后关闭连接，重新连接可获得完整快照。
- [ ] Server 在当前实例内保留最近 100 条关键事件；周期心跳使用 SSE 注释，不进入操作者事件；同一领域事实不会从 Daemon 和 Coordinator 重复产生两条事件。
- [ ] Web 急停请求在活动作业时返回已受理状态，并经无线控制面传播到目标 Client；传输取消、RoleService 停止、临时制品清理和待命链路恢复均以实际结果写入状态。
- [ ] 执行结果与资源恢复状态独立表达；恢复未完成或受阻时禁止创建下一作业，并显示阻塞原因。
- [ ] 浏览器刷新、SSE 断线重连和 Server 重启后通过快照恢复或显示新的实例身份及前次作业不可用，不把旧作业伪造为成功或可续跑。
- [ ] 集成和浏览器测试覆盖首帧、事件去重、队列溢出、急停、恢复门禁、断线和服务重启。

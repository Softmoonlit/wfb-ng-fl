# 05: 实现 SSE 事件、急停与资源恢复

**What to build:** 让操作者可以在运行监控页面接收权威状态和关键事件、发起急停，并区分急停请求受理、作业执行结果和资源恢复完成。浏览器刷新、SSE 断线、慢客户端和 Server 重启都不能伪造旧作业结果。

**Blocked by:** 04（通过 Web 启动同步文件仿真作业）

**Status:** resolved

- [x] SSE 建立连接后先发送完整控制台快照，再发送完整状态变化快照和去重后的操作者关键事件；每帧具有单调事件标识。
- [x] `Last-Event-ID` 只能用于发现中间事件可能丢失；慢客户端使用有限队列，溢出后关闭连接，重新连接可获得完整快照。
- [x] Server 在当前实例内保留最近 100 条关键事件；周期心跳使用 SSE 注释，不进入操作者事件；同一领域事实不会从 Daemon 和 Coordinator 重复产生两条事件。
- [x] Web 急停请求在活动作业时返回已受理状态，并经无线控制面传播到目标 Client；传输取消、RoleService 停止、临时制品清理和待命链路恢复均以实际结果写入状态。
- [x] 执行结果与资源恢复状态独立表达；恢复未完成或受阻时禁止创建下一作业，并显示阻塞原因。
- [x] 浏览器刷新、SSE 断线重连和 Server 重启后通过快照恢复或显示新的实例身份及前次作业不可用，不把旧作业伪造为成功或可续跑。
- [x] 集成和浏览器测试覆盖首帧、事件去重、队列溢出、急停、恢复门禁、断线和服务重启。

## Answer

已实现管理 Web 的权威 SSE 控制台流和急停闭环。`GET /api/v1/events` 首帧发送完整快照，后续发送带单调 `id` 的完整状态快照与去重操作者事件；连接使用 100 项有界队列，慢客户端溢出后关闭，重连通过快照恢复。`Last-Event-ID` 只用于标记可能需要重新同步，不作为旧事件重放游标；心跳使用 SSE 注释，节点心跳不进入操作者事件历史。

新增 `POST /api/v1/jobs/{job_id}/abort`。活动作业返回 `202 accepted`，实际急停通过既有控制面终态广播、Coordinator/RoleService 停止、链路恢复和资源收口流程执行，控制台分别展示执行结果与资源恢复状态。Server 实例身份沿用进程级 UUID，浏览器通过实例变化提示前次作业不可续跑；页面接入 `EventSource`、断线提示和急停按钮。

## Answer

交付独立原生 `/radio` 页面及同源射频读取、校验、应用 API。页面读取 Server 提供的 MCS 安全范围与推荐速率，校验后展示规范配置，操作者再次点击才会应用；越界速率必须明确勾选风险确认，应用 API 同样校验风险确认，不能通过普通提交绕过。输入变化、断线、状态版本或实例变化、确认过期会清除确认；页面保留未提交草稿，并显示资源阻塞、事务结果与 `RADIO_ERROR`。

确认上下文保存在 application service 内存中，绑定 Server 实例、状态版本、实际差量配置和目标集合，60 秒过期、单次消费，新校验替换旧确认。应用只接受令牌与布尔风险确认，不能替换配置或目标。确认检查与 daemon 射频资源预留共享准入锁，协议等待期间释放锁。集群必须空闲、资源恢复完成、已注册节点全部待命且心跳新鲜；尚未上线的预置槽位不算已注册节点。

复用既有双最终屏障与 15 秒租约，并修复此前只有内存配置变化、进程参数未生效的缺口：Server 下行 MCS 与 Client 上行 MCS／频宽在可回退阶段同步重建常驻链路，失败时恢复旧参数，恢复失败进入既有 fail-closed 语义。Client 与控制面共用状态锁，避免回调重建链路和作业交接产生反向锁序。后续 Client 任务使用已生效的功率与 MCS，Server UFTP 发送器使用已确认速率。

领域和 HTTP 测试覆盖非法参数、强告警、令牌失效、作业与资源冲突、并发查询、差量协议、回退和不可逆失败；进程边界测试验证实际 MCS／频宽命令、启动失败与恢复失败，以及后续作业的 `uftp -R` 参数。页面测试沿用 Node VM／DOM／fetch 接缝；未宣称完成真实浏览器或 1280x720 布局验收。页面顶部急停入口预留既定作业急停 API，其受理由工单 05 完成。本票修改了射频运行时参数生效路径，工单 08 的三机实体验收需要重新覆盖相关射频／链路恢复行为，不能仅复用旧硬件归档。

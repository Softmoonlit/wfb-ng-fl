# 02: 通过 Web 管理内容寻址模型库

**What to build:** 让操作者可以从浏览器上传普通文件、查看 SHA-256 内容寻址的模型清单、重复上传时得到去重结果，并删除未被作业引用的模型制品。上传和模型库失败都必须留下可见且可恢复的领域结果。

**Blocked by:** 01（建立 Web 管理入口与可恢复状态快照）

**Status:** resolved

## Answer

新增 `wfb_ng/fl/model_library.py`，由既有 console application service 接入同源模型列表、上传与删除接口。制品以完整小写 SHA-256 为身份，首次展示名与入库时间保持不变；列表按入库时间倒序、摘要升序返回。单文件上限 1 GiB，库内容与在途预留合计上限 10 GiB；库满时仅接收并计算摘要，相同内容仍返回去重成功，新内容返回容量错误。只允许一个正在接收的上传，其余上传立即返回忙碌。

上传流式计算摘要，以独立临时目录写入内容和元数据，复用已有制品工具同步文件与目录后原子发布；默认持久目录为 `/var/lib/wfb-ng-fl/models`，可通过 `model_library_dir` 指定数据盘位置，与临时作业目录分开。daemon 重启后首次访问清理未完成上传及删除残留，并重新校验制品大小与完整摘要。模型盘不可用不阻止核心 daemon 构造和启动；首次完整性扫描不持有 daemon 状态锁。

中断、格式错误及写入失败清理临时内容并释放预留；若文件系统连清理也拒绝，保留预留并阻断后续写入，重试时先恢复清理。删除提交后若物理清理失败，稳定返回 `MODEL_DELETE_CLEANUP_FAILED` 并明确“模型已删除、磁盘清理尚未完成”；同实例与重启后的重试都保留该结果。磁盘恢复后可幂等完成清理。

引用状态由 application service 根据当前作业及资源尚未恢复的最近作业统一判断；检查引用与删除共用 daemon 锁，被引用制品返回 `409 MODEL_REFERENCED`。未引入第二套引用计数或作业生命周期。上传成功返回 201，去重返回 200；详细 API 字段、排序和部署约定见 `docs/deployment/部署与运行基准.md`。

原生 `/models` 页面支持上传、刷新、完整摘要与引用状态、删除确认和可恢复错误。异步清单响应使用版本判断，避免旧响应覆盖后续上传或删除结果。页面行为测试采用现有 Node VM 与 DOM/fetch 接缝；另用 Node 原生 FormData 经真实 HTTP 验证中文文件名及制品身份。未宣称完成真实浏览器或 1280x720 布局验收，后者由工单 06/07 覆盖；本票不涉及三机实体作业验收。

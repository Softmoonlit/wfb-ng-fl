# per-node 静默观测与粗粒度移除自愈闭环

## What to build

在重复声明刷新语义已经成立的前提下，交付第二版的粗粒度移除与自愈重入切片。服务端接收侧补 `per-node` 统计/标记，按 `NODE_ID` 维护 **静默时间** 与 **连续静默 grant 次数**；只有两者同时满足阈值时，服务端才将该节点从 **活跃队列** 中移除。客户端若长时间无 Token，则重发 **上行就绪声明**；若节点已不在队列中，服务端应将其按新入队处理并排到队尾，之后它仍能再次获得 Token。该切片完成后，第二版主线应具备“粗粒度误删后客户端自愈重入”的完整恢复路径。

## Agent brief

这是 `v2-mainline` 的误删恢复切片，目标是形成“粗粒度移除 -> 客户端重声明 -> 重新入队 -> 再次获 Token”的闭环。

实现时保持这些边界：
- 只补接收侧 `per-node` 统计，不引入发送侧反馈闭环
- 移除条件必须是“静默时间 + 连续静默 grant 次数”同时满足
- 观察到来自该 `NODE_ID` 的任意链路层数据包即可清零其连续静默 grant 次数
- 若节点已不在队列中，重声明按新入队处理并排到队尾

完成后优先验证：服务端能保守地做粗粒度移除，且被移除客户端可通过重声明恢复到后续轮换中。

## Acceptance criteria

- [x] 服务端接收侧具备按 `NODE_ID` 维护静默时间与连续静默 grant 次数的能力，并在观察到来自该 `NODE_ID` 的任意链路层数据包时清零其连续静默 grant 次数。
- [x] 服务端只有在静默时间与连续静默 grant 次数同时满足阈值时，才将该节点从 **活跃队列** 中粗粒度移除。
- [x] 被移除客户端在长时间无 Token 后重发 **上行就绪声明** 时，会被服务端按新入队处理并排到队尾，之后仍能再次获得 Token。

## Out of scope

- 动态 `duration_ms` / `guard_interval_ms`
- 显式完成/失败控制消息
- 上层轮次结束信号

## Implementation notes

- 服务端调度器已补 `per-node` 活性状态，按 `NODE_ID` 维护最近活性时间与连续静默 grant 次数，并在接收到 ready 声明或观察到该节点链路层上行数据包时刷新活性、清零连续静默 grant 次数。
- 粗粒度移除语义已落到调度循环：只有当静默时间与连续静默 grant 次数同时达到阈值时，节点才会从活跃队列中移除；当前阈值按本切片最小实现固定在调度器内部，未做动态配置。
- 若节点已被移出活跃队列，后续重发 ready 声明会按新入队处理并追加到队尾；它不会因重声明抢占更靠前的调度机会，而是在后续公平轮换中再次获得 Token。
- 已补单元测试与集成测试，覆盖双阈值移除、链路层观测清零静默计数、以及“粗粒度移除 -> 重声明 -> 队尾重入 -> 再次获 Token”的恢复闭环。

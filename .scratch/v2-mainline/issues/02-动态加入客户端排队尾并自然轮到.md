# 动态加入客户端排队尾并自然轮到

## What to build

在第二版正式主线的双客户端轮换闭环已经存在的前提下，交付“运行中动态加入”的完整切片：当客户端 A 已处于较长上行过程中时，客户端 B 中途发送 **上行就绪声明**，服务端应将其排到 **活跃队列** 队尾，不抢占当前轮换，不改变调度游标；随后客户端 B 仅在游标自然轮到时获得 Token 并完成上行。该切片完成后，第二版主线应能证明自己支持真正的运行中加入，而不是只支持静态同时起跑。

## Agent brief

这是 `v2-mainline` 的动态加入切片，目标是证明第二版主线支持运行中加入，而不是只有静态起跑。

实现时保持这些边界：
- 新客户端中途声明时只能排到队尾
- 不允许抢占当前 grant
- 不允许改变调度游标
- 仍保持固定 `duration_ms` / `guard_interval_ms`

完成后优先验证：客户端 A 长传输进行中，客户端 B 中途声明加入后不会插队，而是只在游标自然轮到时获得 Token 并完成上行。

## Acceptance criteria

- [x] 客户端 A 已在进行较长上行传输时，客户端 B 中途发送 **上行就绪声明** 能被服务端接受并排到队尾。
- [x] 服务端在客户端 B 动态加入时不改变当前调度游标，客户端 B 不会抢占当前 grant 或提前插队。
- [x] 当游标自然轮到客户端 B 时，客户端 B 能获得 Token 并完成小文件 `TCP` 上行。

## Implementation summary

- 在 `src/token_scheduler_test.cpp` 增加 `TokenScheduler 运行中动态加入的节点排到队尾并自然轮到`，通过公共接口验证运行中声明的新节点只会尾插进入 **活跃队列**，不会抢占当前轮换。
- 在 `src/tx_authorization_integration_test.cpp` 增加 `运行中动态加入的客户端排到队尾并在自然轮到时获得授权`，通过真实 `ready socket` 与 per-node `grant socket` 验证 `1 -> 1 -> 2` 的授权顺序，证明动态加入客户端不会提前插队。

# 第二版分层验收脚本与关键日志留痕

## What to build

把第二版正式主线的多客户端行为整合成一个分层验收入口。该验收应把“三个核心场景”做成硬验收：双客户端顺序入队轮换上行、长传输中动态加入、粗粒度移除后自愈重入；同时输出足够的辅助观测日志，用于解释服务端权威队列、调度游标、公平性与客户端状态转换。该切片完成后，第二版主线应有一个清晰、可重复、可回归的 acceptance 入口，而不是零散的手工验证。

## Agent brief

这是 `v2-mainline` 的验收收口切片，目标是把前面各行为切片汇总成一个分层 acceptance 入口。

实现时保持这些边界：
- 首批只做分层验收，不把所有时序日志都升级成强断言
- 三个核心场景必须是硬验收
- 服务端与客户端关键日志都要保留，但先以辅助观测为主

完成后优先验证：一条统一入口能够稳定跑通三类硬验收场景，并输出足够解释过程的关键日志。

## Acceptance criteria

- [x] 验收入口覆盖三类硬验收场景：双客户端顺序入队轮换上行成功、长传输中动态加入成功、粗粒度移除后自愈重入成功。
- [x] 服务端日志至少输出 `join/rejoin`、`refresh`、`grant`、`evict` 四类关键事件，并在关键事件后附带 **活跃队列** 快照与调度游标位置。
- [x] 客户端日志至少输出 `first_declare`、`redeclare`、`token_received` 三类行为事件，以及客户端最小状态机转换，用于辅助解释验收过程。

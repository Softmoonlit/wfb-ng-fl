# 固定时隙下的声明驱动双客户端轮换闭环

## What to build

交付第二版正式主线的最小端到端切片：在固定 `duration_ms` 与固定 `guard_interval_ms` 前提下，让两个客户端都能发送 **上行就绪声明**，由服务端维护单层 **活跃队列**，并以固定队列加调度游标的盲 round-robin 方式轮换发 Token。该切片完成后，两个客户端都应能够按声明顺序被纳入轮换，并分别完成小文件 `TCP` 上行，从而证明第二版主线已经从第一版的单客户端固定授权推进到多客户端声明驱动轮换。

## Agent brief

这是 `v2-mainline` 的第一条主线切片，用于把第一版的单客户端固定授权推进到双客户端声明驱动轮换。

实现时保持这些边界：
- grant 继续沿用现有定义，`duration_ms` 与 `guard_interval_ms` 保持固定配置
- 不引入动态 grant 时长策略
- 不引入发送侧反馈闭环
- 不引入显式完成/失败控制消息

完成后优先验证：两个客户端都能发送第一次 **上行就绪声明**，服务端按声明顺序纳入 **活跃队列**，并且两个客户端都能轮到并完成小文件 `TCP` 上行。

## Acceptance criteria

- [x] 两个客户端在本地具备待上传数据时都能发送第一次 **上行就绪声明**，未声明客户端不会被纳入 Token 轮换。
- [x] 服务端维护单层 **活跃队列**，并以固定队列加调度游标的方式按声明顺序轮换发 Token；grant 时长保持固定配置，不做动态伸缩。
- [x] 两个客户端都能在各自被轮到时完成小文件 `TCP` 上行，形成可验证的双客户端主线闭环。

## Out of scope

- 动态加入客户端的运行中排队语义
- 重复声明刷新活性语义
- `per-node` 静默观测与粗粒度移除
- 分层 acceptance 编排与完整日志留痕

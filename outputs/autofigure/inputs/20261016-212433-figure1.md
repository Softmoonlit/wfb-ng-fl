# Figure 1：WFB-FL 五层架构与端到端交互

请根据以下已经确认的规格，生成一张供 IEEE Communications Magazine 中文初稿使用的科研架构图。输出为 PNG。以准确表达系统为首要目标，中文文字必须清楚、正确、易读。

## 画面与风格

- 横向跨双栏画幅，目标宽高比约 2:1，尽量采用高分辨率，保持清晰文字。
- 白底、扁平矢量式期刊框图、规整对齐、充分留白。以蓝色和青色为主色，少量橙色强调上行或轮次推进。可以采用少量简单的服务器、边缘设备、文件和模型图标；不要照片、立体效果、渐变、阴影或复杂装饰。
- 所有说明使用中文，保留 WFB-FL、UFTP、HTTP PUT、TCP、TUN、monitor、802.11 等技术名称。不要在图内加入长图注或论文 Figure 编号。
- 用户确认的布局为 A 方案：左上角放紧凑的五层架构概览，其余区域展开服务端与多个客户端的交互。流程箭头直接嵌入节点交互，不另设底部独立流程条。架构概览与主交互图是同一画面的两个互补区域。

## 左上角：五层架构概览

概览约占总画面宽度的四分之一至三分之一，不要喧宾夺主。以五个上下排列、同宽的模块，自顶向下准确呈现：

1. 联邦学习算法层：训练评估与聚合
2. 联邦学习运行层：轮次编排
3. 传输适配层：下行 UFTP；上行 HTTP PUT / TCP
4. 链路控制层：发送许可、队列与重组
5. 无线收发层：原始帧注入 / monitor 接收

- 在第 3 层与第 4 层之间用清晰的细虚线标注“TUN 边界”，说明普通数据经 TUN 进入链路控制层。
- 五层用相近而可区分的低饱和颜色；主交互图中对应职责尽量复用这些颜色。
- 可用细小的向下实线箭头表示调用、向上细箭头表示完成返回，但不必为箭头堆积说明。
- 如果绘制调度控制旁路，仅用细虚线表达链路控制层直达无线收发层，标注“调度控制”，不能经过 TUN。优先保持清晰，概览内无需展开这条旁路。

## 主区域：服务端与多个客户端的端到端交互

仅有“服务端”和“客户端”两类正式角色。不要画路由器、接入点、云端、专用监听节点或第三类观测设备。

- 服务端位于主区域偏左或中左，客户端位于主区域右侧，以至少三个独立设备框表示“客户端 1”“客户端 2”“客户端 N”，中间配省略号，明确节点规模可扩展。
- 服务端框内包含短标签“全局模型”“模型发布”“更新收齐”“聚合”。用紧凑分区或少量模块表达算法、运行和传输职责即可，不要在每个节点重复整套五层长文字。
- 每个客户端内部至少表达“模型接收与校验”“本地训练”“更新提交”，可绘制小模型图标和训练循环箭头。多个客户端都要呈现训练功能，不能只有一个客户端训练。
- 在服务端与客户端之间，以简洁无线波纹或短标签标明“可配置 802.11 无线链路”。下行与上行共用该链路，不暗示是两套独立物理网络。

将以下四步直接融入对应节点与通信箭头，编号 ①②③④ 只是辅助识别，不要另画流程条：

① 模型下行：由服务端“全局模型 / 模型发布”发出一条蓝色实线主干，再清楚分支到所有客户端，体现同一份模型的一对多广播。主干标注“模型下行 · UFTP”。不要画成服务端逐个单播文件，不要画成客户端相互传递。

② 本地训练：在各客户端内部，从“模型接收与校验”连向“本地训练”，再连向本地更新。标注“本地校验通过后训练”。每个客户端可独立开始，不画等待所有客户端接收完毕后统一训练的全局屏障。

③ 更新上行：从多个客户端的“更新提交”分别画橙色回传箭头，汇向服务端“更新收齐”。在公共可读区域标注“更新上行 · HTTP PUT / TCP”，并用一个短标签说明“按许可轮流发送”。不同客户端的更新文件彼此独立；避免箭头相互交叉，避免暗示所有客户端同时发射。无需展开窗口时序。

④ 聚合：服务端内部从“更新收齐”连至“聚合”，再回到“全局模型”，构成下一轮的闭环。聚合前用简短条件标注“下行完成且本轮预期更新收齐”。不能把收到无线帧或某一个客户端上传完成画成整轮完成。

下行箭头与上行箭头应有不同路径和清楚箭头端点，模型必须从服务端到客户端，更新必须从客户端到服务端。以布局和连接呈现流程，不依靠大段文字。

## 图的语义依据

初稿 Figure 1 图注：展示服务端与多个客户端的五层职责划分、TUN 边界，以及模型下行、本地训练、更新上行与聚合的简化流程，并标明传输适配层在下行采用一对多文件分发协议 UFTP、在上行采用 HTTP PUT 与 TCP。

系统调用自顶向下发起、完成结果逐层向上返回。客户端本地收到完整模型并校验通过即可训练；服务端只有在下行完成且本轮预期有效更新完整收齐后才执行聚合。服务端管理发送许可，多个客户端按许可轮流上行。

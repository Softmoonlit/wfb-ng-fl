# Figure 1 v4：五层架构与四动作训练流程

## 已确认规格与第一次生成后的约束修正

为中文论文绘制清楚、充实、少字的系统插画。输出 PNG，横向约 2:1。白底、扁平计算设备插画、蓝青主色和橙色回传。主图以一台服务端、多个客户端及四个动作形成阅读循环，左上角放辅助架构卡片。

关键视觉要求：Cute characters means ONLY cute inanimate computers and file icons. NO humans, NO people, NO mascots, NO humanoid figures. 只用设备、数据、文件、神经网络图标表达活动，不画操作员或卡通角色。绝不画任何人脸。

## 左上角卡片

占画面宽度约24%，五条色带，只写以下五行：
联邦学习算法层
联邦学习运行层
传输适配层
链路控制层
无线收发层

第3行与第4行之间画细虚线，标“TUN 边界”。每层只有层名，不加短职责、协议、内部箭头或其他说明。

## 主区域

服务端放在中左，图标是一台工作站，短标签“服务端”。多个客户端放在右侧，以三个小型边缘设备和省略号组成一组，短标签“多个客户端”。不要将客户端画成操作员。各设备屏幕只显示简单神经网络图标。

从上到下、顺时针阅读四个动作：

1. 上方，从服务端的模型文件图标向客户端组画一条蓝色右向箭头，标签仅“模型广播 · UFTP”。不要给每个客户端拉线。

2. 右侧代表客户端旁展开一个小训练示意：本地数据图片堆叠图标 → 神经网络 → 更新文件图标。只画两条短连接。整个示意只标“本地训练”。其他客户端只保留设备，不重复训练示意。本地数据不上传。

3. 下方，从客户端更新文件向服务端画一条橙色左向箭头，标签仅“更新回传 · HTTP PUT / TCP”。箭头旁配两三个有细微颜色差别的更新文件图标。文件上不要任何文字、对勾或叉号。

4. 服务端左下方，在卡片下的空白处，用三个小更新文件图标汇聚成一个新模型图标，只标“聚合”。一条短局部回路将新模型接回服务端，用以进入下一轮广播，不绕整张图。汇聚线简短，不穿过文字。

## 文字白名单

整张图仅允许以下文字：五个层名、“TUN 边界”、“服务端”、“多个客户端”、“模型广播 · UFTP”、“本地训练”、“更新回传 · HTTP PUT / TCP”、“聚合”。

不要图内标题、图注、Figure编号、步骤编号、英文文件名、Global Model、Update file、Model等额外文字。文件和模型用小图形表示，不加文字。不要文件状态对勾或叉号，所有更新都是正常训练更新。

## 准确性与信息量

模型向客户端广播，更新向服务端回传，训练在客户端，聚合在服务端。本图只有服务端和客户端两类角色，没有云端、接入点或监听设备。架构与设备之间不拉线。不展开校验、就绪声明、发送许可、窗口、队列或实验参数。

图中必须有训练和聚合的小型图形展开，不能只有两个设备加两条通信箭头。箭头保持主次，两条跨设备箭头最醒目，局部连接短而轻。留白充足，文本清楚。

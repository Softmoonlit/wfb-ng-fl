# Figure 1 v4：五层架构与四动作训练流程

## 已确认的生成规格

为中文 IEEE Communications Magazine 稿件绘制 Figure 1。输出 PNG，横向约 2:1，白底、扁平设备插画、柔和蓝青主色，少量橙色区分回传。设备、文件、模型和数据图标承担主要表达，文字简短，具有清楚的阅读路径。不要人物装饰、卡通人物、大标题、图注或步骤编号。

用户已经确认：保留左上角五层架构卡片；主流程只表达模型广播、本地训练、更新回传、聚合四个动作。架构卡片不加短职责，所需信息放到流程图。不要就绪声明、许可调度、完成条件、校验、接收状态、队列或重传的流程细节。

## 左上角辅助卡片

紧凑卡片约占全图宽度 24%、高度 44%，恰好五条色带，上下排列，每条只写层名，禁止再加第二行职责、协议或操作文字：

联邦学习算法层
联邦学习运行层
传输适配层
链路控制层
无线收发层

第三层与第四层之间一条细水平虚线，标注“TUN 边界”。架构内部不画箭头，卡片不向设备拉线。卡片与主流程的对应区域可复用配色，但不增加图例。

## 主区域：设备插画与四个动作

主区域占据画面中部与右侧。一台简洁工作站/小型服务器放在中左，标“服务端”；右侧放三个小型边缘计算设备，组合标题“多个客户端”，设备之间配省略号。只有一台代表客户端展开训练小示意，其他两个设备只展示同类模型图标，不重复展开。整体留白，插画友好但设备不拟人。

四个动作形成一个能顺着阅读的循环。只用两条醒目的跨设备通信箭头和必要的短局部连接，不让连接交叉，不为每台客户端拉独立通信线。

### 模型广播

服务端屏幕附近画一个全局模型文件小图标，从这里引出一条蓝色实线箭头，向右指向客户端设备组。箭头短标签“模型广播 · UFTP”。一条箭头代表一对多广播，不逐客户端分支。

### 本地训练

在右侧代表客户端旁画小型本地训练示意：一个本地数据集图标（几张叠放的小图片）、一个神经网络模型图标、一个输出更新文件图标。用两条很短的内部连接表示数据和模型进入训练、产生更新。小示意只标“本地训练”，不为每个图标再写文字，不画独立长流程框。不把本地数据集连向服务端。

### 更新回传

从客户端组的更新文件附近引出一条橙色实线箭头，向左返回服务端。箭头短标签“更新回传 · HTTP PUT / TCP”。在箭头起点附近放两三个不同颜色/小标记的更新文件小图标，表示各客户端产生不同更新。更新文件都回到服务端，不画客户端之间的传递。上行箭头与下行箭头平行、分隔，不能交叉，不重复协议名称。

### 聚合

在服务端旁边、架构卡片下方的可用空间，画一个小型聚合示意：多个更新文件通过两三条短汇聚线合成一个新模型图标，标“聚合”。再用一条短回环，将新模型连接回服务端的广播模型位置，表达下一轮。回环只在服务端局部，不绕整张图，不穿过架构卡片或通信箭头。不要写更新收齐、聚合屏障、下一轮等额外说明。

## 信息与视觉边界

- 主流程只有四个动作，但每个动作都有实际图形内容：模型文件广播、本地数据训练、不同更新回传、多个更新合成新模型。不能退化为只有设备加两条箭头的拓扑示意，也不能扩成完整操作步骤图。
- 图内文字只允许五层名称、“TUN 边界”、“服务端”、“多个客户端”和四个动作标签（两个通信动作附协议名）。无需给无线符号加说明文字。
- 保留设备形象和小图标，不堆积文本模块。不加重复层、不加步骤序号、不加完成条件、不加参数表或实验数字。
- 下行方向必须从服务端到客户端组；上行方向必须从客户端组到服务端；聚合发生在服务端；本地训练发生在客户端；本地原始数据留在客户端。
- 场景只包含服务端和客户端，不要接入点、云、独立监听设备或其他角色。
- 不展开 Figure 2 的发送权时序，也不展开 Figure 3 的队列反压。

# Figure 3：出站队列水位与 TUN 反压机制

请生成适用于 IEEE Communications Magazine 中文论文的科研机制示意图。下列规格已经用户确认。图用于解释机制，不展示测量结果；不要虚构实验数据。

## 内容与因果关系

本图只解释固定容量的用户态出站发送队列的字节积压，以及高低双阈值控制 TUN 读入的反压关系。普通数据路径为“TUN → 出站发送队列 → 无线发送”。队列积压量只表示已从 TUN 读入但尚未发出的数据字节。

1. 起始处于“允许读入”状态，输入快于发送时，队列积压上升。
2. 积压达到预设高水位 H，触发“暂停 TUN 读入”。暂停的是从 TUN 向出站队列读入新数据，不是关闭 TUN、不代表清空队列，也不代表停止无线发送。
3. 暂停读入后，已有队列数据仍可随发送机会发出，积压下降。
4. 积压从高水位下降、进入 H 与 L 之间时，仍保持暂停读入；不会一跌破 H 就恢复。
5. 积压降至预设低水位 L，才触发“恢复 TUN 读入”。L 必须小于 H。
6. 两个阈值之间保持此前的读入状态，形成滞回区间，避免在一个临界点附近频繁启停。
7. H 与 L 都是水平、固定的预设阈值。变化的是队列积压量，阈值不随时间自动调整。

不要引入控制优先通道、接收重组、数据包数量上限、UFTP 补发、FEC 或发送权调度的细节。不要承诺杜绝所有网络丢包，不画额外的服务端或客户端节点。该图同时适用于客户端上行和服务端下行的出站队列。

上方约占 1/3：数据路径，左为 TUN 虚拟接口简洁图符，中为具有缓冲分组格子的出站发送队列，右为简洁无线发送图符。用蓝色箭头连接。TUN 与队列之间标示读入门控，并用短反馈箭头关联“高水位：暂停读入”“低水位：恢复读入”。门控只影响进入队列的箭头，出队到无线发送仍可继续。

下方约占 2/3：以时间为横轴、队列积压字节为纵轴的定性示意曲线。横轴写“时间”，纵轴写“队列积压（字节）”；不写任何数值刻度或实测单位数值。两条清晰水平虚线分别标“高水位 H”和“低水位 L”，H 在 L 上方。主曲线从低于 L 的位置上升，穿过 L，达到 H 的触发点 A 后转为下降，穿回 H 与 L 之间，直到 L 的触发点 B，再恢复上升。曲线平滑、变化合理，A 和 B 精确落在对应阈值线；A 与 B 的时间位置与读入状态条对齐。
